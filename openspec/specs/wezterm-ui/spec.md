# wezterm-ui Specification

## Purpose
Внешний вид WezTerm и то, что он показывает помимо вывода программ: шелл по умолчанию, цветовая схема, шрифт и межстрочный интервал, рамка и заголовок окна, поля, звонок, курсор, панель вкладок, притушение неактивных панелей и правая часть панели вкладок — бейдж активного режима и имя воркспейса. Не покрывает: размер окна и размер шрифта (wezterm-window-state, WT-STATE), полосу прокрутки и историю (wezterm-scrollback, WT-SCROLL-3), содержание режимов WINDOWS, RESIZE, copy mode и search mode (wezterm-windows-mode, WT-WIN; WT-SCROLL), вкладки, панели и воркспейсы как объекты и работу мышью с панелью вкладок (wezterm-panes-tabs, WT-PANE), загрузку конфига (wezterm-config-loading, WT-LOAD), кодирование клавиш (wezterm-keyboard-protocol, WT-KBD).

## Requirements

### Requirement: WT-UI-1 Шелл по умолчанию на Windows
На Windows терминал SHALL запускать в каждой новой вкладке, панели и окне `pwsh.exe -NoLogo`, если в одном из каталогов PATH процесса WezTerm лежит файл `pwsh.exe`, который открывается на чтение, иначе — `powershell.exe -NoLogo` (Windows PowerShell 5.1); `cmd.exe` по умолчанию MUST NOT запускаться.
Платформы: windows
История: FIXLOG 2026-05-31 «WezTerm: шелл/диск, дополнение путей, шрифт, Ctrl+C/V» (проблема 1), §18

PowerShell 7 из Microsoft Store попадает в PATH пользователя только псевдонимом `%LOCALAPPDATA%\Microsoft\WindowsApps\pwsh.exe`. Как файл такой псевдоним не открывается, поэтому не засчитывается, и запускается `powershell.exe`. Так на машине владельца: PowerShell 7.6 установлен из Store, а все панели запущенного WezTerm работают в `powershell.exe` (проверено 2026-09-27 по списку процессов WezTerm и пробным открытием псевдонима из конфига WezTerm). `pwsh.exe` выбирается, когда в PATH есть каталог с настоящим файлом, например после установки MSI или winget в `C:\Program Files\PowerShell\7\`. PATH берётся из окружения, с которым запущен процесс WezTerm; перечитывание конфига его не обновляет. `-NoLogo` убирает баннер PowerShell при старте. Шелл по умолчанию не действует там, где программа задана явно: `wezterm start -- <программа>`, выгрузка истории в nvim (WT-SCROLL-13).

#### Scenario: PowerShell 7 установлен файлом
- **GIVEN** `pwsh.exe` лежит в каталоге из PATH, например `C:\Program Files\PowerShell\7\`
- **WHEN** пользователь открывает новую вкладку (Ctrl+Shift+T)
- **THEN** в ней запущен PowerShell 7 без баннера

#### Scenario: PowerShell 7 из Microsoft Store
- **GIVEN** PowerShell 7 установлен из Microsoft Store, в PATH есть только его псевдоним в `%LOCALAPPDATA%\Microsoft\WindowsApps`
- **WHEN** пользователь запускает WezTerm ярлыком и открывает вкладку
- **THEN** в ней запущен Windows PowerShell (`powershell.exe`) без баннера, хотя `pwsh` в этой системе запускается по имени

#### Scenario: PowerShell 7 нет
- **GIVEN** `pwsh.exe` нет ни в одном каталоге PATH
- **WHEN** пользователь запускает WezTerm
- **THEN** запущен Windows PowerShell (`powershell.exe`) без баннера
- **AND** терминал стартует, а не падает на отсутствующем pwsh

#### Scenario: Смена диска командой cd
- **GIVEN** в панели шелл по умолчанию, текущий каталог на диске C:
- **WHEN** пользователь вводит `cd D:\`
- **THEN** текущим становится диск D: (в `cmd.exe` без `/d` этого бы не произошло)

#### Scenario: pwsh установлен при работающем WezTerm
- **GIVEN** WezTerm запущен, когда `pwsh.exe` в PATH не было, потом PowerShell 7 установлен через MSI или winget
- **WHEN** пользователь открывает новую вкладку или перечитывает конфиг (Ctrl+Shift+R)
- **THEN** по-прежнему запускается `powershell.exe`
- **AND** `pwsh.exe` начинает запускаться после перезапуска WezTerm с обновлённым PATH

### Requirement: WT-UI-2 Шелл по умолчанию на macOS и Linux
Вне Windows конфиг шелл не задаёт, и терминал SHALL запускать в каждой новой вкладке, панели и окне шелл пользователя как login-шелл: из переменной SHELL, если она указывает на исполняемый файл, иначе из учётной записи пользователя, иначе `/bin/sh`.
Платформы: macos

Linux получает ту же ветку конфига, что macOS. Как и на Windows, шелл по умолчанию не действует, где программа задана явно (WT-SCROLL-13, `wezterm start -- <программа>`).

#### Scenario: Шелл пользователя
- **GIVEN** шелл пользователя — zsh, SHELL указывает на него
- **WHEN** пользователь открывает новую вкладку
- **THEN** в ней запущен zsh как login-шелл (он читает `~/.zprofile`)

#### Scenario: SHELL указывает на несуществующий файл
- **GIVEN** SHELL указывает на файл, которого нет или который не исполняемый
- **WHEN** пользователь открывает новую вкладку
- **THEN** запускается шелл из учётной записи пользователя, а если и он не исполняемый — `/bin/sh`

### Requirement: WT-UI-3 Цветовая схема Catppuccin Mocha
Терминал SHALL раскрашивать текст, фон, выделение, курсор, панель вкладок и линии между панелями встроенной в WezTerm схемой «Catppuccin Mocha» независимо от светлой или тёмной темы ОС.
Платформы: все

Основные цвета схемы: фон #1e1e2e, текст #cdd6f4, выделение #585b70, курсор #f5e0dc, фон панели вкладок #11111b, активная вкладка #cba6f7 с тёмным текстом #11111b, неактивная #181825, кнопка «+» #313244, линия между панелями #6c7086, ползунок полосы прокрутки #585b70. Из той же схемы берутся 16 ANSI-цветов для вывода программ. Программа с собственной темой (nvim) рисует своими цветами.

#### Scenario: Тёмная схема в шелле
- **GIVEN** WezTerm запущен, в панели шелл
- **WHEN** пользователь смотрит на окно
- **THEN** фон #1e1e2e, обычный текст #cdd6f4

#### Scenario: Светлая тема ОС
- **GIVEN** ОС переключена на светлую тему
- **WHEN** пользователь открывает WezTerm
- **THEN** схема та же, тёмная Catppuccin Mocha

#### Scenario: Смена темы ОС при работающем WezTerm
- **GIVEN** WezTerm запущен, в окне включён режим WINDOWS
- **WHEN** ОС переключается между светлой и тёмной темой
- **THEN** цвета не меняются
- **AND** WezTerm перечитывает конфиг, поэтому режим WINDOWS выключается (WT-STATE-5)

#### Scenario: ANSI-цвет программы
- **GIVEN** в панели шелл
- **WHEN** программа выводит текст с кодом красного цвета (`ESC[31m`)
- **THEN** текст рисуется красным схемы, #f38ba8

### Requirement: WT-UI-4 Шрифт и запасные шрифты
Терминал SHALL рисовать текст шрифтом CaskaydiaCove Nerd Font, а символы, которых в нём нет, MUST брать по очереди из Inconsolata Nerd Font Mono, Cascadia Mono, Consolas, встроенных в WezTerm JetBrains Mono, Noto Color Emoji и Symbols Nerd Font Mono, затем из любого установленного в ОС шрифта, где символ есть, не показывая предупреждений о символах, которых нет ни в одном шрифте.
Платформы: все
История: FIXLOG 2026-05-31 «WezTerm: шелл/диск, дополнение путей, шрифт, Ctrl+C/V» (проблема 3)

Основной шрифт указан двумя именами, «CaskaydiaCove NF» и «CaskaydiaCove Nerd Font»; установленный Nerd Fonts 3.x находится по обоим, это один и тот же файл. Сам шрифт ставится отдельно: на Windows вручную (`winget install --id DEVCOM.CascadiaCodeNerdFont`), на macOS — установщиком (MAC-INST-6). Каждый шрифт из списка, кроме трёх встроенных, которого нет в системе, даёт ошибку конфигурации WezTerm: открывается отдельное окно «wezterm Configuration Error» с текстом «Unable to load a font specified by your font=wezterm.font('<имя>', …) configuration. Fallback(s) are being used instead…», по сообщению на каждый такой шрифт; позже, при первом жирном или курсивном тексте, туда же могут добавиться сообщения о вариантах этих шрифтов. Текст при этом рисуется первым найденным шрифтом списка, иконки Nerd Font остаются за счёт встроенного Symbols Nerd Font Mono. На Windows владельца установлены все пять шрифтов (Cascadia Mono — из Windows Terminal), сообщений нет. В macOS Inconsolata Nerd Font Mono, Cascadia Mono и Consolas не входят, а установщик ставит только CaskaydiaCove; вывод о сообщениях на Mac сделан по исходнику 20240203 и на месте не проверялся. `wezterm ls-fonts` этих сообщений не печатает. Если символа нет ни в одном шрифте, рисуется заглушка без уведомления. Размер шрифта — WT-STATE.

#### Scenario: Шрифт установлен
- **GIVEN** CaskaydiaCove Nerd Font установлен
- **WHEN** шелл или nvim выводит текст и иконки Nerd Font
- **THEN** текст рисуется CaskaydiaCove, иконки видны

#### Scenario: Символа нет в основном шрифте
- **GIVEN** CaskaydiaCove Nerd Font установлен
- **WHEN** вывод содержит эмодзи или иероглиф, которого в нём нет
- **THEN** символ берётся из запасного шрифта
- **AND** уведомления о недостающих глифах нет

#### Scenario: Символа нет ни в одном шрифте
- **GIVEN** вывод содержит символ, которого нет ни в одном шрифте
- **WHEN** WezTerm его рисует
- **THEN** на месте символа заглушка
- **AND** уведомления нет

#### Scenario: Основной шрифт не установлен
- **GIVEN** на машине нет CaskaydiaCove Nerd Font
- **WHEN** пользователь запускает WezTerm
- **THEN** открывается окно «wezterm Configuration Error» с сообщением «Unable to load a font specified by your font=wezterm.font('CaskaydiaCove NF', …) configuration…» и таким же для «CaskaydiaCove Nerd Font»
- **AND** текст рисуется следующим установленным шрифтом из списка, иконки Nerd Font видны

#### Scenario: Нет запасного шрифта из списка
- **GIVEN** CaskaydiaCove Nerd Font установлен, а Consolas в системе нет (например, на macOS)
- **WHEN** пользователь запускает WezTerm
- **THEN** открывается окно «wezterm Configuration Error» с сообщением «Unable to load a font specified by your font=wezterm.font('Consolas', …) configuration…» (выведено по исходнику 20240203)
- **AND** текст рисуется CaskaydiaCove, как обычно

### Requirement: WT-UI-5 Межстрочный интервал
Терминал SHALL делать высоту строки в 1,05 раза больше стандартной для шрифта.
Платформы: все

Интервал действует и в панели вкладок, и во всех панелях; при смене размера шрифта (WT-STATE-6) соотношение сохраняется.

#### Scenario: Высота строки
- **GIVEN** в панели шелл, шрифт любого размера
- **WHEN** пользователь выводит несколько строк текста
- **THEN** шаг между строками на 5 % больше стандартного для этого шрифта и размера

### Requirement: WT-UI-6 Рамка и заголовок окна
Окно SHALL иметь системный заголовок, за который его можно перетаскивать и в котором есть системные кнопки управления окном, и рамку, за которую меняется размер (`window_decorations = "TITLE | RESIZE"`).
Платформы: все
История: FIXLOG 2026-05-31 «WezTerm: окно не перетаскивается»

Кнопки — системные: на Windows «свернуть», «развернуть» и «закрыть» справа, на macOS три кнопки слева. Текст заголовка — стандартный для WezTerm, конфиг его не меняет.

#### Scenario: Перетаскивание окна
- **GIVEN** открыто окно WezTerm
- **WHEN** пользователь тянет его мышью за заголовок
- **THEN** окно перемещается

#### Scenario: Размер мышью
- **GIVEN** открыто окно WezTerm
- **WHEN** пользователь тянет за край окна
- **THEN** размер окна меняется, программы в панелях получают новое число строк и столбцов

#### Scenario: Кнопка «развернуть» на Windows
- **GIVEN** открыто окно WezTerm на Windows
- **WHEN** пользователь нажимает кнопку «развернуть» в заголовке
- **THEN** окно разворачивается на весь рабочий стол

### Requirement: WT-UI-7 Поля окна
Терминал SHALL оставлять между текстом панелей и краем окна поля: слева 6, справа 14, сверху 4 и снизу 4 пикселя; правое поле MUST занимать полоса прокрутки (WT-SCROLL-3), и текст под неё не заходит.
Платформы: все
История: FIXLOG §16

Пиксели физические: на экране с масштабом 200 % поля выглядят вдвое уже, чем на экране 100 %. Нижнее поле отделяет текст от панели вкладок.

#### Scenario: Последний столбец виден
- **GIVEN** в панели у правого края окна строка текста во всю ширину
- **WHEN** пользователь смотрит на правый край
- **THEN** последний символ строки виден полностью, полоса прокрутки его не закрывает

#### Scenario: Экран с масштабом 200 %
- **GIVEN** окно WezTerm на экране с масштабом 200 %
- **WHEN** пользователь смотрит на поля
- **THEN** правое поле и полоса прокрутки шириной 14 физических пикселей, то есть 7 логических

### Requirement: WT-UI-8 Звонок без звука
На символ звонка (BEL) терминал SHALL не издавать звука и MUST NOT мигать экраном.
Платформы: все

#### Scenario: Программа подаёт звонок
- **GIVEN** в панели шелл
- **WHEN** программа выводит символ BEL (например, `printf '\a'`)
- **THEN** звука нет
- **AND** экран не мигает

### Requirement: WT-UI-9 Курсор
Когда программа не задала форму курсора сама (например, шелл), терминал SHALL показывать в активной панели окна, которое в фокусе, мигающий блочный курсор, который 500 мс виден и 500 мс скрыт и переключается резко, без плавного затухания.
Платформы: все

После любого движения курсора (набор, вывод) курсор сразу виден, и отсчёт начинается заново: при наборе он не пропадает. В неактивных панелях и в окне без фокуса курсор не мигает и рисуется контуром блока — любой формы, в том числе заданной программой. Программа может задать свою форму и мигание (nvim через guicursor), тогда в активной панели действуют они. Частота кадров анимаций WezTerm ограничена (`animation_fps = 1`), поэтому мигающий текст (SGR 5) тоже переключается без плавного перехода.

#### Scenario: Мигание в шелле
- **GIVEN** окно в фокусе, в активной панели шелл, пользователь ничего не набирает
- **WHEN** проходит несколько секунд
- **THEN** блочный курсор 0,5 с виден и 0,5 с скрыт, без затухания

#### Scenario: Набор текста
- **GIVEN** в активной панели шелл
- **WHEN** пользователь печатает
- **THEN** курсор всё время виден и начинает мигать только после паузы

#### Scenario: Форма от программы
- **GIVEN** в панели nvim, который задаёт свою форму курсора
- **WHEN** nvim переходит в режим вставки
- **THEN** курсор принимает форму, заданную nvim

#### Scenario: Окно без фокуса или неактивная панель
- **GIVEN** окно WezTerm не в фокусе или панель неактивна, в ней nvim в режиме вставки (курсор-черта)
- **WHEN** пользователь смотрит на курсор в ней
- **THEN** курсор не мигает и нарисован контуром блока, а не чертой

### Requirement: WT-UI-10 Панель вкладок
Терминал SHALL всегда показывать панель вкладок внизу окна, даже при одной вкладке, в простом однострочном стиле (не «fancy»), с шириной вкладки не больше 24 знакомест.
Платформы: все
История: FIXLOG 2026-08-01 «WezTerm: leader → липкий модальный режим WINDOWS»

Слева направо: вкладки в виде « N: <название> », где N считается с 1, а название — имя вкладки (WT-PANE-11) или заголовок её активной панели; затем кнопка «+»; справа — бейдж режима и имя воркспейса (WT-UI-12, WT-UI-13); левая часть статуса пуста. Длинное название вкладки обрезается по ширине. Если вкладки все вместе не помещаются в ширину окна, они сужаются поровну; место под правую часть при этом не резервируется (WT-UI-15). Работа мышью с панелью вкладок — WT-PANE-13. Панель видна и в полноэкранном режиме. Цвета — из схемы (WT-UI-3). Панель внизу с именем воркспейса справа — видимый признак того, что загружен этот конфиг (WT-LOAD-15).

#### Scenario: Одна вкладка
- **GIVEN** в окне одна вкладка
- **WHEN** пользователь смотрит на окно
- **THEN** панель вкладок видна внизу окна: « 1: <заголовок панели> », кнопка «+», справа имя воркспейса

#### Scenario: Длинное название вкладки
- **GIVEN** у вкладки название длиннее 24 знакомест
- **WHEN** оно показывается в панели вкладок
- **THEN** вкладка занимает не больше 24 знакомест, название обрезано

#### Scenario: Полноэкранный режим
- **GIVEN** окно переведено в полноэкранный режим
- **WHEN** пользователь смотрит на низ экрана
- **THEN** панель вкладок с бейджем и именем воркспейса по-прежнему видна

### Requirement: WT-UI-11 Неактивные панели притушены
Когда во вкладке несколько панелей, терминал SHALL рисовать неактивные панели с насыщенностью 85 % и яркостью 75 % от обычной, а активную — без изменений.
Платформы: все

Текст в неактивных панелях остаётся читаемым. Во вкладке с одной панелью ничего не притушено. Потеря фокуса окном активную панель не притушивает.

#### Scenario: Две панели
- **GIVEN** вкладка разделена на две панели, активна левая
- **WHEN** пользователь смотрит на окно
- **THEN** правая панель заметно темнее и бледнее левой, но текст в ней читается

#### Scenario: Переход в другую панель
- **GIVEN** вкладка с двумя панелями, активна левая
- **WHEN** пользователь переходит в правую панель
- **THEN** притушенной становится левая, правая рисуется обычными цветами

### Requirement: WT-UI-12 Бейдж активного режима
Пока в окне активен один из четырёх режимов — WINDOWS, RESIZE, copy mode или search mode, — терминал SHALL показывать справа в панели вкладок, перед именем воркспейса, бейдж `▶ <РЕЖИМ>  ·  Esc выход` жирным тёмным (#1e1e2e) текстом на цвете режима; когда ни один из них не активен, бейджа MUST NOT быть.
Платформы: все
История: FIXLOG 2026-08-01 «WezTerm: leader → липкий модальный режим WINDOWS»

| Режим | Надпись | Цвет |
|---|---|---|
| WINDOWS (WT-WIN-1) | WINDOWS | жёлтый #f9e2af |
| RESIZE (WT-WIN-11) | RESIZE | оранжевый #fab387 |
| copy mode (WT-SCROLL-5) | COPY | синий #89b4fa |
| search mode (WT-SCROLL-9) | SEARCH | зелёный #a6e3a1 |

WINDOWS и RESIZE принадлежат окну: их бейдж виден, какая бы вкладка или панель ни была активна. COPY и SEARCH принадлежат панели: бейдж виден, пока активна панель, в которой открыт copy mode или search mode. Если одновременно активны WINDOWS/RESIZE и copy mode/search mode активной панели, бейдж показывает COPY/SEARCH. Бейдж меняется не позже чем через ~0,1 с после входа в режим или выхода из него, в том числе по таймауту (WT-UI-14). WINDOWS и RESIZE, а с ними и бейдж, гаснут и при перечитывании конфига и смене шрифта в окне (WT-STATE-5, WT-STATE-6). Других индикаторов нет: оверлеи, которые тоже перехватывают ввод, — QuickSelect, лаунчер, палитра команд, выбор символа, запросы имени вкладки и воркспейса, подтверждение закрытия панели, debug overlay — своего бейджа не дают. В каждом окне бейдж свой. При нехватке места бейдж обрезается (WT-UI-15).

#### Scenario: Вход в режим WINDOWS и выход
- **GIVEN** ни один режим не активен, бейджа нет
- **WHEN** пользователь нажимает Ctrl+Shift+Space, а потом Esc
- **THEN** после входа справа появляется жёлтый бейдж «▶ WINDOWS  ·  Esc выход»
- **AND** после Esc бейдж гаснет

#### Scenario: Выход по таймауту
- **GIVEN** режим WINDOWS включён
- **WHEN** 5 секунд не нажимается ни одна команда режима (WT-WIN-3)
- **THEN** режим выключается, и бейдж гаснет сам

#### Scenario: Подрежим RESIZE
- **GIVEN** режим WINDOWS включён
- **WHEN** пользователь нажимает r, а потом Esc
- **THEN** после r бейдж меняется на оранжевый «RESIZE»
- **AND** после Esc бейджа нет: RESIZE заменил WINDOWS, возврата в WINDOWS нет

#### Scenario: Copy mode и поиск
- **GIVEN** ни один режим не активен
- **WHEN** пользователь нажимает Ctrl+Shift+X, затем `/`, затем Esc
- **THEN** после Ctrl+Shift+X виден синий бейдж «COPY», после `/` — зелёный «SEARCH»
- **AND** после Esc бейджа нет

#### Scenario: Copy mode в неактивной панели
- **GIVEN** в левой панели открыт copy mode, виден бейдж COPY
- **WHEN** пользователь переходит в правую панель (Ctrl+Shift+L)
- **THEN** бейдж гаснет, хотя copy mode в левой панели остался
- **AND** при возврате в левую панель бейдж COPY появляется снова

#### Scenario: Copy mode поверх режима WINDOWS
- **GIVEN** режим WINDOWS включён
- **WHEN** пользователь нажимает Ctrl+Shift+X
- **THEN** бейдж показывает COPY, а не WINDOWS
- **AND** если после выхода из copy mode режим WINDOWS ещё не истёк, снова виден бейдж WINDOWS

#### Scenario: Оверлей без бейджа
- **GIVEN** ни один из четырёх режимов не активен
- **WHEN** пользователь открывает QuickSelect (Ctrl+Shift+U)
- **THEN** клавиши перехватывает QuickSelect, а бейджа нет

#### Scenario: Два окна
- **GIVEN** открыты два окна, режим WINDOWS включён в первом
- **WHEN** пользователь смотрит на второе окно
- **THEN** во втором окне бейджа нет

### Requirement: WT-UI-13 Имя воркспейса
Терминал SHALL всегда показывать у правого края панели вкладок имя текущего воркспейса серым цветом #6c7086, с бейджем режима или без него.
Платформы: все
История: FIXLOG 2026-08-01 «WezTerm: leader → липкий модальный режим WINDOWS»

Воркспейс по умолчанию называется `default`. Бейдж режима (WT-UI-12) стоит левее имени. Все окна одного запущенного WezTerm показывают одно и то же имя — активного воркспейса. Переключение воркспейсов — WT-PANE-10. При нехватке места имя обрезается слева (WT-UI-15).

#### Scenario: Воркспейс по умолчанию
- **GIVEN** WezTerm только что запущен
- **WHEN** пользователь смотрит на правый край панели вкладок
- **THEN** там написано `default`

#### Scenario: Переключение воркспейса
- **GIVEN** WezTerm запущен
- **WHEN** пользователь переключается на воркспейс `work` (режим WINDOWS, Shift+S, ввод `work`, Enter)
- **THEN** у правого края панели вкладок написано `work`

#### Scenario: Имя рядом с бейджем
- **GIVEN** включён режим WINDOWS
- **WHEN** пользователь смотрит на правую часть панели вкладок
- **THEN** слева — бейдж WINDOWS, справа от него — имя воркспейса

### Requirement: WT-UI-14 Частота обновления статуса
Терминал SHALL обновлять правую часть панели вкладок каждые 100 мс, чтобы бейдж режима и имя воркспейса менялись не позже чем через ~0,1 с после изменения.
Платформы: все
История: FIXLOG 2026-08-01 «WezTerm: leader → липкий модальный режим WINDOWS»

Обновление идёт постоянно, в каждом окне, и в фокусе, и без него. Вход в WINDOWS и RESIZE и выход из них клавишами, открытие и закрытие copy mode обновляют статус сразу, не дожидаясь очередного срока.

#### Scenario: Бейдж без заметной задержки
- **GIVEN** ни один режим не активен
- **WHEN** пользователь нажимает Ctrl+Shift+Space
- **THEN** бейдж WINDOWS появляется не позже чем через ~0,1 с

#### Scenario: Окно без фокуса
- **GIVEN** в окне включён режим WINDOWS, затем фокус переведён в другое приложение
- **WHEN** режим выключается по таймауту
- **THEN** бейдж в этом окне гаснет, хотя окно не в фокусе

### Requirement: WT-UI-15 Правая часть панели вкладок при нехватке места
Правой части панели вкладок (бейдж режима и имя воркспейса) терминал SHALL отдавать только ширину, оставшуюся после вкладок и кнопки «+»; если её не хватает, правая часть MUST обрезаться слева — сначала бейдж, затем имя воркспейса.
Платформы: все
История: FIXLOG 2026-08-01 «WezTerm: leader → липкий модальный режим WINDOWS»

Бейдж вместе с именем `default` занимает около 38 знакомест. Вкладки сужаются, только когда сами не помещаются в ширину окна, и тогда занимают её почти целиком. Поэтому при нескольких вкладках с длинными названиями (заголовок панели pwsh или nvim обычно длиннее 24 знакомест) бейдж режима виден частично или не виден вовсе, хотя режим включён и перехватывает клавиши.

#### Scenario: Бейдж обрезан
- **GIVEN** панель вкладок шириной 120 знакомест, 4 вкладки с названиями длиннее 24 знакомест, воркспейс `default`, включён режим WINDOWS
- **WHEN** пользователь смотрит на правую часть панели вкладок
- **THEN** вкладки занимают 96 знакомест, кнопка «+» — 3, правой части остаётся 21
- **AND** видны только хвост бейджа «sc выход» и имя `default`, надписи WINDOWS нет

#### Scenario: Вкладки не помещаются
- **GIVEN** панель вкладок шириной 120 знакомест, 5 вкладок с длинными названиями, воркспейс `default`, включён режим WINDOWS
- **WHEN** пользователь смотрит на панель вкладок
- **THEN** каждая вкладка сужена до 22 знакомест, правой части остаётся 7
- **AND** бейджа не видно совсем, от имени воркспейса видно «efault»
