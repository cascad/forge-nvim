# Spec Delta

## ADDED Requirements

### Requirement: WT-KEYS-10 Windows — подмена сочетаний nvim_forge
На Windows терминал SHALL перехватывать сочетания из таблицы ниже и SHALL доставлять их дальше так: если активная панель объявлена nvim_forge (WT-KBD-9), вместо сочетания уходит его подменная клавиша, и nvim_forge выполняет то же, что по исходному сочетанию на macOS; если панель не объявлена, программа получает исходное нажатие так же, как без подмены (WT-KBD-6, WT-KBD-9). Так на Windows работают сочетания nvim_forge, которые через ConPTY не доходят до nvim отдельной клавишей. Образец — Ctrl+[ → F13 (WT-KEYS-6). Шелл, Claude Code и nvim без объявления разницы не видят. Привязки буквенных и знаковых сочетаний заданы по физической позиции клавиши (WT-KEYS-2), поэтому подмена одинакова на русской и английской раскладке. Подмена — глобальная привязка терминала: она действует там же, где остальные глобальные сочетания (WT-KEYS-3), в том числе в режиме WINDOWS (WT-WIN-4). На macOS и Linux подмен нет: там nvim различает эти сочетания сам (WT-KBD-2).

| Сочетание | Клавиша nvim_forge | Действие в nvim_forge |
|---|---|---|
| Ctrl+Shift+F | `<C-S-f>` | панель поиска |
| Ctrl+Shift+P | `<C-S-p>` | палитра команд Telescope |
| Ctrl+Shift+E | `<C-S-e>` | фокус в проводник и обратно |
| Ctrl+Shift+D | `<C-S-d>` | панель отладки |
| Ctrl+Shift+F5 | `<C-S-F5>` | перезапуск сессии DAP |
| Ctrl+. | `<C-.>` | code action |
| Ctrl+Enter | `<C-CR>` | выполнить выделение в pwsh (визуальный режим) |
| Ctrl+/ | `<C-/>` | переключить комментарий |
| Ctrl+Space | `<C-Space>` | вызвать автодополнение (режим вставки) |

В таблицу входят сочетания, которые nvim_forge привязывает и которые на Windows приходят в nvim другой клавишей или не приходят вовсе (WT-KBD-6). Ctrl+Shift+F5 входит по решению владельца, хотя приходит отдельной клавишей `<F41>`: подмена делает его независимым от terminfo. Ctrl+; и Shift+Enter в таблицу не входят: nvim_forge на них ничего не вешает. Сами подменные клавиши — договорённость конфига и nvim_forge, требования к ним — WT-KBD-9.
Платформы: windows
История: FIXLOG «WezTerm + nvim_forge: сочетания nvim_forge на Windows через подмену клавиш»
Проверка: tests/wezterm/key-ownership.test.lua (WT-KEYS-10) | вручную (windows; результат — в tests/manual/wezterm-windows.md)

#### Scenario: Ctrl+Shift+F, P, E и D в nvim_forge
- **GIVEN** Windows, nvim_forge объявил себя (WT-KBD-9), нормальный режим, русская или английская раскладка
- **WHEN** пользователь нажимает Ctrl+Shift+F, затем, закрыв панель, Ctrl+Shift+P, Ctrl+Shift+E и Ctrl+Shift+D
- **THEN** открывается панель поиска, затем палитра команд Telescope, фокус переходит в проводник, открывается панель отладки
- **AND** поиск по буферу (`<C-f>`), поиск файла (`<C-p>`) и прокрутка на полэкрана (`<C-d>`) не срабатывают

#### Scenario: Ctrl+Enter
- **GIVEN** Windows, nvim_forge объявил себя
- **WHEN** пользователь нажимает Ctrl+Enter в нормальном режиме, затем в визуальном режиме с выделенной строкой `Write-Output 1`
- **THEN** в нормальном режиме нижняя панель nvim_forge не переключается (nvim не получает `<NL>`)
- **AND** в визуальном режиме выделенное выполняется в pwsh, выводится `1`

#### Scenario: Ctrl+/ и Ctrl+. на русской раскладке
- **GIVEN** Windows, русская раскладка, nvim_forge объявил себя, нормальный режим, к буферу подключён LSP
- **WHEN** пользователь нажимает Ctrl + физическую `/`, затем Ctrl + физическую `.`
- **THEN** строка под курсором комментируется
- **AND** открывается выбор code action

#### Scenario: Ctrl+Space в режиме вставки
- **GIVEN** Windows, nvim_forge объявил себя, режим вставки
- **WHEN** пользователь нажимает Ctrl+Space
- **THEN** открывается меню автодополнения

#### Scenario: Ctrl+Shift+F5 при отладке
- **GIVEN** Windows, nvim_forge объявил себя, идёт сессия DAP
- **WHEN** пользователь нажимает Ctrl+Shift+F5 в окне кода, затем в окне терминала DAP
- **THEN** сессия перезапускается в обоих случаях

#### Scenario: Программы без объявления
- **GIVEN** Windows, в панели pwsh, Claude Code или `nvim --clean`, панель не объявлена
- **WHEN** пользователь нажимает любое сочетание из таблицы
- **THEN** программа получает то же, что получила бы без подмены (WT-KBD-6, WT-KBD-9)
- **AND** например, `nvim --clean` на Ctrl+Shift+F получает `<C-f>`, а на Ctrl+Space не получает ничего

#### Scenario: Соседняя панель
- **GIVEN** Windows, в вкладке две панели: nvim_forge, объявивший себя, и pwsh
- **WHEN** фокус в pwsh и пользователь нажимает Ctrl+Shift+F
- **THEN** pwsh получает исходное нажатие: объявление действует только для панели nvim_forge

#### Scenario: Режим WINDOWS
- **GIVEN** Windows, nvim_forge объявил себя, включён режим WINDOWS
- **WHEN** пользователь нажимает Ctrl+Shift+F
- **THEN** открывается панель поиска nvim_forge
- **AND** режим WINDOWS остаётся включённым (WT-WIN-4)

#### Scenario: После выхода из nvim_forge
- **GIVEN** Windows, в панели работал nvim_forge и завершился обычным образом (`:qa`)
- **WHEN** пользователь в шелле этой панели нажимает Ctrl+Shift+F или Ctrl+Space
- **THEN** шелл получает исходное нажатие, подмены нет

#### Scenario: Аварийное завершение nvim_forge
- **GIVEN** Windows, nvim_forge в панели завершился аварийно и не снял объявление
- **WHEN** пользователь в шелле этой панели нажимает Ctrl+Shift+F
- **THEN** шелл получает подменную клавишу, а не исходное нажатие
- **AND** после следующего запуска и обычного выхода nvim_forge или после сброса объявления командой в шелле (docs/WEZTERM.md) шелл снова получает исходное нажатие

#### Scenario: Привязки по платформам
- **GIVEN** конфиг загружен для Windows, macOS и Linux
- **THEN** на Windows на каждое сочетание таблицы ровно одна привязка вне режимов, буквы и знаки — по физической позиции
- **AND** на macOS и Linux таких привязок нет
- **AND** у nvim_forge на каждую подменную клавишу есть привязка в режимах нормальном, визуальном, select, ожидания оператора, вставки, командной строки и терминала, и она делает то же, что исходное сочетание в этом режиме

## MODIFIED Requirements

### Requirement: WT-KEYS-1 Встроенные привязки клавиш WezTerm отключены
Терминал SHALL NOT применять встроенный набор привязок клавиш WezTerm (`disable_default_key_bindings = true`): действует только то, что явно задано в `wezterm.lua`. Встроенные привязки WezTerm заданы по символу, поэтому работали бы только на английской раскладке. Часть из них забирала клавиши у nvim: Ctrl+Shift+F, Ctrl+Shift+P, Ctrl+PageUp/PageDown, Alt+Enter. Отключение касается только клавиатуры. Встроенные привязки мыши действуют. Таблицы copy mode и search mode конфиг строит из встроенных таблиц WezTerm (wezterm-scrollback).
Платформы: все
История: FIXLOG §41, §42, «WezTerm + nvim_forge: сочетания nvim_forge на Windows через подмену клавиш»

#### Scenario: Встроенное сочетание без явной привязки уходит в программу
- **GIVEN** в панели nvim или шелл, английская или русская раскладка
- **WHEN** пользователь нажимает Ctrl+Shift+F, Ctrl+Shift+P, Ctrl+PageUp, Ctrl+PageDown или Alt+Enter
- **THEN** встроенное действие WezTerm (поиск, палитра команд, смена вкладки, полноэкранный режим) не выполняется, нажатие уходит программе (что она получает — WT-KBD-6)
- **AND** на Windows Ctrl+Shift+F и Ctrl+Shift+P — явные привязки этого конфига: панели, объявленной nvim_forge, они отдают подменную клавишу, остальным программам — исходное нажатие (WT-KEYS-10)

#### Scenario: Сочетания, у которых поменялся смысл
- **GIVEN** в панели шелл
- **WHEN** пользователь нажимает Ctrl+Shift+K или Ctrl+Shift+L (во встроенном наборе WezTerm это очистка скроллбэка и debug overlay)
- **THEN** срабатывают явные привязки этого конфига: фокус на панель выше и правее (WT-KEYS-3)

#### Scenario: Встроенных Cmd-сочетаний на macOS нет
- **GIVEN** macOS, в панели шелл
- **WHEN** пользователь нажимает Cmd+W, Cmd+K, Cmd+F или Cmd+1
- **THEN** WezTerm не закрывает вкладку, не очищает экран, не ищет и не переключает вкладку
- **AND** нажатие уходит программе без Super (WT-KBD-8)

#### Scenario: Мышь не затронута
- **GIVEN** шелл в панели
- **WHEN** пользователь выделяет текст мышью, отпускает кнопку или щёлкает средней кнопкой
- **THEN** работают встроенные привязки мыши WezTerm (выделение, копирование при отпускании, вставка; подробности — WT-CLIP)

### Requirement: WT-KEYS-3 Полный набор перехватов вне режимов
Вне режимов терминал SHALL перехватывать ровно сочетания из таблицы ниже (на Windows 48, на macOS 61) и SHALL передавать программе в панели все остальные нажатия. Кроме них, на Windows оконный слой WezTerm забирает Alt+Space и Alt+F4 (WT-KEYS-9). Ещё на Windows терминал перехватывает сочетания из таблицы WT-KEYS-10 и доставляет их дальше: панели, объявленной nvim_forge, — подменной клавишей, остальным программам — исходным нажатием. Эти подмены в таблицу ниже и в число 48 не входят: программа нажатие не теряет. Перехваченное сочетание программа не получает, даже если сама включила kitty или альтернативный экран. Клавишу без модификатора терминал вне режимов не перехватывает никогда; из сочетаний с одним Shift перехватываются только Shift+PageUp, Shift+PageDown и Shift+Insert. Super — это Cmd на macOS и клавиша Win на Windows. На Windows терминал SHALL NOT перехватывать ни одного сочетания с Super: Super-варианты шрифта есть только вне Windows (решение владельца 2026-09-27), а сочетание с Win, которое ОС пропустила в WezTerm, уходит программе (WT-KBD-8). Что из пропущенного доходит до программы и в каком виде — wezterm-keyboard-protocol.

#### Scenario: Сочетания нет в таблице
- **GIVEN** в панели nvim, шелл или Claude Code, режимов нет
- **WHEN** пользователь нажимает сочетание, которого нет в таблице (например, Ctrl+Shift+B, Ctrl+Shift+Y, Alt+Enter, Ctrl+B)
- **THEN** WezTerm ничего не делает и передаёт нажатие программе

#### Scenario: Ctrl+C на macOS не перехватывается
- **GIVEN** macOS, в панели долгоиграющая команда
- **WHEN** пользователь нажимает Ctrl+C
- **THEN** программа получает Ctrl+C (прерывание), WezTerm его не перехватывает

#### Scenario: Win+Shift+S на Windows не перехватывается
- **GIVEN** Windows
- **WHEN** пользователь нажимает Win+Shift+S
- **THEN** у WezTerm на это сочетание привязки нет, оно остаётся системному снимку экрана

#### Scenario: Super-сочетания шрифта есть и на Windows
- **GIVEN** Windows, шрифт окна — 12
- **WHEN** пользователь нажимает Win+=, Win+- или Win+0 (с Shift или без)
- **THEN** размер шрифта не меняется: на Windows Super-сочетаний шрифта нет, шрифт меняют только Ctrl-сочетания (WT-STATE-6, WT-STATE-7)
- **AND** сочетание, которое ОС пропустила в WezTerm, уходит программе без Win (WT-KBD-8); остальные забирает сама Windows (например, Win+= — экранная лупа)

#### Scenario: Программа на альтернативном экране
- **GIVEN** в панели nvim, less или Claude Code (альтернативный экран, скроллбэка нет)
- **WHEN** пользователь нажимает Shift+PageUp или Shift+Insert
- **THEN** WezTerm выполняет свою привязку: прокрутка ничего не сдвигает, вставка уходит в программу как вставленный текст
- **AND** программа не получает клавиши Shift+PageUp или Shift+Insert как нажатие

#### Scenario: Перехват не зависит от протокола программы
- **GIVEN** программа в панели включила kitty (macOS) или работает через win32-input-mode (Windows)
- **WHEN** пользователь нажимает любое сочетание из таблицы
- **THEN** срабатывает действие WezTerm, и программа это нажатие не получает

#### Scenario: Отличия платформ
- **GIVEN** конфиг загружен
- **THEN** на Windows перехвачено 48 сочетаний: 47 общих плюс Ctrl+C, и ни одного с Super
- **AND** на macOS перехвачено 61 сочетание: 47 общих плюс шесть Super-сочетаний шрифта и Cmd+C, Cmd+V, Cmd+N, Cmd+T, Cmd+H, Cmd+M, Cmd+Q, Cmd+Shift+S
- **AND** на Windows `show-keys` показывает ещё по одной привязке на каждое сочетание таблицы WT-KEYS-10; в число 48 они не входят

#### Scenario: Super-сочетания шрифта на macOS
- **GIVEN** macOS, шрифт окна — 12
- **WHEN** пользователь нажимает Cmd+=, затем Cmd+Shift+-, затем Cmd+0
- **THEN** шрифт становится 13,2, затем 12, затем сбрасывается к сохранённому или к 12 (WT-STATE-6, WT-STATE-7)
- **AND** программа в панели этих нажатий не получает

### Requirement: WT-KEYS-4 Сочетания, оставленные nvim
Терминал SHALL NOT забирать себе перечисленные ниже сочетания, которыми пользуется nvim_forge, и SHALL доставлять их программе: на macOS и Linux — как есть; на Windows — подменной клавишей, если панель объявлена nvim_forge (WT-KEYS-10), а иначе исходным нажатием. Это Ctrl+Shift+F (`<C-S-f>`, панель поиска), Ctrl+Shift+P (`<C-S-p>`, палитра Telescope), Ctrl+Shift+E (`<C-S-e>`, проводник), Ctrl+Shift+D (`<C-S-d>`, отладка) и Ctrl+Shift+F5 (`<C-S-F5>`, рестарт DAP). Дальше — Ctrl+PageUp/Ctrl+PageDown (буферы), Alt+Enter и Ctrl+. (code action), Ctrl+Enter (`<C-CR>`), Ctrl+/ (комментарий), Ctrl+Space (автодополнение), Tab/Shift+Tab (буферы, автодополнение), Esc и Ctrl+B/Ctrl+J (панели nvim_forge). На macOS сюда же входит Cmd+Alt+L (`<D-A-l>`, форматирование). Шире: WezTerm не забирает себе сочетания Alt+клавиша без Ctrl (на Windows, кроме Alt+Space и Alt+F4 — WT-KEYS-9), F1–F12 с любыми модификаторами (на Windows, кроме Alt+F4) и Ctrl+букву, кроме Ctrl+V (все платформы) и Ctrl+C (Windows). Где WezTerm и nvim_forge всё же пересекаются — WT-KEYS-7. Что nvim из пропущенного различает, зависит от платформы: на macOS — всё (WT-KBD-2); на Windows nvim_forge различает сочетания из таблицы WT-KEYS-10 через подмену, а остальное приходит так, как описано в WT-KBD-6.
Платформы: все

- **WHEN** пользователь нажимает Ctrl+Shift+F
- **THEN** открывается панель поиска nvim_forge, WezTerm ничего не делает

#### Scenario: Ctrl+Shift+F в nvim на Windows
- **GIVEN** Windows, nvim_forge в панели и объявил себя (WT-KBD-9)
- **WHEN** пользователь нажимает Ctrl+Shift+F
- **THEN** WezTerm отдаёт nvim_forge подменную клавишу (WT-KEYS-10), и открывается панель поиска nvim_forge
- **AND** nvim без объявления (например, `nvim --clean`) получает то же сочетание как `<C-f>` (WT-KBD-6)

#### Scenario: Ctrl+Shift+J принадлежит WezTerm
- **GIVEN** в панели nvim_forge
- **WHEN** пользователь нажимает Ctrl+Shift+J
- **THEN** фокус переходит на панель WezTerm ниже, nvim нажатие не получает
- **AND** нижняя панель nvim_forge переключается на Ctrl+J, который WezTerm не перехватывает

#### Scenario: Ctrl+Shift+B свободен
- **GIVEN** в панели любая программа
- **WHEN** пользователь нажимает Ctrl+Shift+B
- **THEN** WezTerm нажатие не перехватывает; nvim_forge на `<C-S-b>` ничего не вешает (левая панель — Ctrl+B)
