## Purpose

Не мешает обычной работе сообщениями о неиспользуемом отладчике и даёт
понятную причину отказа при явном запуске конфигурации, которой он нужен.

## ADDED Requirements

### Requirement: IDE-DAP-4 codelldb проверяется при запуске

Редактор SHALL искать codelldb при явном запуске использующей его
конфигурации, а не при загрузке общего DAP. Открытие Go/обычного файла
и установка breakpoint MUST NOT показывать предупреждение об отсутствующем
codelldb. При его отсутствии запуск SHALL показать одно сообщение с
вариантами установки, не создавать DAP-сессию и сохранять доступ к редактору.
Настройки C/C++/Rust MUST оставаться доступными независимо от наличия бинарника.

Платформы: все
Проверка: tests/e2e/dap-discovery.test.lua (IDE-DAP-4)

#### Scenario: Go без codelldb
- **GIVEN** окружение без codelldb в PATH и приватных каталогах инструментов
- **WHEN** пользователь открывает Go-файл, загружая DAP для Go
- **THEN** предупреждения codelldb нет; общий DAP зарегистрирован
- **AND** breakpoint можно поставить без запуска отладчика и установки tools

#### Scenario: breakpoint в обычном файле
- **WHEN** пользователь ставит breakpoint в обычном текстовом файле
- **THEN** загрузка общего DAP не сообщает об отсутствующем codelldb

#### Scenario: отсутствующий инструмент при запуске
- **WHEN** пользователь нажимает F5 для codelldb-конфигурации
- **THEN** видит одно сообщение об отсутствующем codelldb и установке
- **AND** сессии и ошибки missing adapter нет, файл доступен для редактирования
- **AND** повторная попытка снова сообщает о проблеме ровно один раз
