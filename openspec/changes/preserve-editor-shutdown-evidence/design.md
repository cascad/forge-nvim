# Design

## Context

См. proposal. Артефакты 29211834204778 / 29296420074026 и docker top
содержат первичный RPC timeout и живые child после SIGTERM. Старый helper
ограничивался qa!/2s, SIGTERM/2s и assert; caller ещё не успевал вывести
свою сохранённую ошибку. Всё выполняется в отдельном --rm контейнере.

## Goals / Non-Goals

**Goals:** завершить собственный child, сохранить первичную причину и
независимый cleanup verdict, оставить доказательства при ошибке startup.

**Non-Goals:** устранение неизвестного первичного RPC зависания; изменение
runtime/SDK, повышение 10s RPC или прежних 2s интервалов; управление чужими
процессами, process groups, Docker Desktop/WSL; скрытие forced kill как PASS.

## Decisions

1. Общий test-only editor_process.stop работает только с переданным handle.
   После прежних шагов добавляется SIGKILL и проверка завершения. Результат
   структурирован, каждый этап записывается в shutdown.json заранее/после.
   Номера PID служат наблюдению; поиск/kill по имени не применяется.
2. Первый RPC timeout сохраняется до SIGTERM. Последующие snapshot ошибки
   не заменяют его. Editor stop принимает необязательную исходную ошибку;
   при ошибке cleanup сообщение включает обе причины. Startup wrappers и
   два затронутых Git callers передают её явно.
3. После подтверждённого exit и сохранения artifacts runtime удаляется даже
   при принудительной остановке; сам тест остаётся FAIL. При невозможности
   завершить/сохранить runtime оставляется с явным путём.
4. Реальные clean Neovim процессы проверяют обычный qa! и POSIX SIGSTOP.
   Имя сигнала передаётся native API, без Linux/macOS чисел. SIGSTOP ветка
   Windows SKIP, обычный RPC/quit выполняется нативно на Windows. Исходный
   stop_process из 5e4dfe8 можно экспортировать в явном test-only legacy
   adapter без изменения его тела: RED должен дойти до старого assert.

## Risks / Trade-offs

- Child остановлен тестом → обязательный finally SIGKILL только этого handle.
- Forced shutdown скроет дефект → отдельный ok=false/error, исходная ошибка
  сохраняется; caller не получает зелёный результат из успешного kill.
- Копирование artifacts само упало → обе ошибки сохраняются, runtime остаётся.
- Зелёный Git повтор → только результат регресса; первичный IDE-047 остаётся
  открытым до отдельной установленной причины.
