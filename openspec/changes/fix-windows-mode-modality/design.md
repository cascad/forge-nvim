# Design

## Context

Мотивация и воспроизведения — в proposal.md (Why), требования — в delta в `specs/`.

Подход ограничивает то, как WezTerm 20240203 решает, кому отдать нажатие (`wezterm-gui/src/termwindow/keyevent.rs`, `termwindow/mod.rs`):

- Нажатие проверяется в нескольких проходах. Сначала идут raw-проходы: по физической позиции клавиши, потом по сырому коду, и в них ищутся только привязки. Затем «приготовленный» проход, в котором клавиша может уйти программе или экрану.
- В каждом проходе порядок один: таблица оверлея активной панели (copy_mode или search_mode), потом стек таблиц окна сверху вниз (WINDOWS, RESIZE), потом `config.keys`, потом программа или открытый экран.
- `prevent_fallback` у записи стека обрывает поиск ниже неё. В приготовленном проходе на месте «не нашли» подставляется `Nop`, и нажатие поглощается. В raw-проходе `config.keys` просматривается всё равно, отсюда платформенная разница из proposal («Нюанс»).
- Таймаут записи стека продлевается только при совпадении в её собственной таблице. Подставленный `Nop` его не продлевает.
- Модальные экраны WezTerm — выбор панели, выбор символа, палитра — получают клавишу в приготовленном проходе раньше таблиц. Привязки по физической позиции срабатывают ещё раньше, в raw-проходе.
- `PopKeyTable` снимает верхнюю запись стека окна, `ClearKeyTableStack` — весь стек окна. Таблицы copy mode и search mode живут на оверлее панели, и эти действия их не трогают.
- Отпускание клавиши таблицы не проверяют. В win32-input-mode (Windows) и в kitty с отчётом о событиях (macOS) оно уходит программе, в том числе сейчас — для команд режима.

Как устроен код сейчас (`wezterm.lua`):

- `config.keys` собирается примерно из десяти мест: литерал, `table.insert` и помощник `map()`. Последние записи — Cmd-сочетания macOS.
- Таблицы `windows` и `resize_pane` — литералы.
- Команды группы «выходят» начинаются с `PopKeyTable`.
- RESIZE включается с `replace_current`, а WINDOWS, включённый из RESIZE по Ctrl+Shift+Space, ложится поверх него.

## Goals / Non-Goals

**Goals:**
- Один механизм модальности на оба слоя, WINDOWS и RESIZE.
- Сочетания терминала в режимах берутся из того же списка, что `config.keys`, без второй ручной копии, и ведут себя одинаково на Windows и macOS.
- Пометка «сочетание открывает экран» ставится там же, где сочетание объявлено. Правило «экран открывается при выключенном режиме» проверяется командой без GUI, на настоящем разборе конфига.

**Non-Goals:**
- Набор перехватов вне режимов и правило `phys:` (WT-KEYS-2, WT-KEYS-3, change `resolve-key-ownership-conflicts`). Копии в режимах подхватят их изменения сами.
- Бейдж COPY/SEARCH поверх WINDOWS (WT-UI-12). Если владелец захочет видеть WINDOWS поверх поиска, это отдельный change с delta к WT-UI-12.
- Выключение режимов при смене шрифта и перечитывании конфига (WT-WIN-2; `review-baseline`, OQ7).
- WINDOWS, включённый по Ctrl+Shift+Space из RESIZE, остаётся слоем поверх RESIZE, а не заменой (WT-WIN-11).
- Ограничение русской раскладки на экранах, которые сравнивают символ (WT-WIN-7, WT-PANE-4, WT-SCROLL-12).
- Поведение внутри copy mode и search mode, в том числе Enter в поиске (WT-SCROLL, change `change-search-enter-accept`).
- Перестройка файла (`restructure-wezterm-config`) и переписывание `docs/WEZTERM.md` целиком (`sync-docs-with-baseline`). Здесь правится только раздел режима WINDOWS.
- Отпускание клавиш, которое WezTerm передаёт программе мимо таблиц. Его можно только проверить (решение 13).

## Decisions

Решения владельца, на которых стоит change:

**1. Решение владельца 2026-09-27: клавиши без команды в режиме проглатываются (решение №1, семантика `prevent_fallback`).**
- Отклонено: оставить как есть. Сейчас клавиши без команды уходят в программу, и режим модальный только наполовину (divergence 48).
- Отклонено: `until_unknown`, то есть любая чужая клавиша выключает режим и уходит в программу. Опечатка обрывает серию команд, а буква всё равно попадает в nvim.

**2. Решение владельца 2026-09-27: `o` переводит фокус на следующую панель по кругу (решение №2).**
- Отклонено: оставить поворот панелей `RotatePanes("Clockwise")`, как в WT-WIN-6 базовой линии. Он не совпадает ни с FIXLOG («o — цикл»), ни с docs («перейти в следующую панель по кругу»).

**3. Решение владельца 2026-09-27: `q`, `x` и всё, что открывает запрос, экран или оверлей, сперва выключает режим (правило WT-WIN-19).**
- Отклонено: оставить режим включённым поверх экрана выбора и запроса, как сейчас. Вместе с решением 1 режим проглатывал бы метки выбора и `y` в запросе, и подтвердить с клавиатуры было бы нельзя.

**4. Решение владельца 2026-09-27: подрежим RESIZE подчиняется тем же правилам, что WINDOWS (вопрос 1, вариант A).** Клавиши без команды он проглатывает, сочетания терминала ведут себя по решению 5.
- Отклонено (B): RESIZE, как сейчас, пропускает чужие клавиши в программу. Получились бы два слоя с разной семантикой, хотя RESIZE включается из WINDOWS и выглядит его частью.
- Отклонено (C): RESIZE выключается от первой чужой клавиши (`until_unknown`). Это третий механизм ради одного слоя.

**5. Решение владельца 2026-09-27: сочетания терминала из `config.keys` работают в режимах одинаково на Windows и macOS (вопрос 2, вариант A).**
- Их копии генерируются в таблицы режимов из того же списка, что `config.keys`.
- Каждое такое сочетание продлевает таймаут режима, как команда режима.
- Сочетания, которые открывают экран или оверлей (Ctrl+Shift+W, Ctrl+Shift+U, Ctrl+Shift+X, Cmd+Q и любые будущие такие же), сперва выключают режим.
- Отклонено (B): перевести именованные клавиши сочетаний (Tab, Enter, стрелки, PageUp/PageDown, Insert) на `phys:`, чтобы они совпадали в raw-проходе, как буквенные. Это меняет WT-KEYS-2 (именованные клавиши остаются именованными) и держится на внутреннем устройстве проходов WezTerm.
- Отклонено (C): одна строка `prevent_fallback`, без копий. Сочетания на именованных клавишах тогда на Windows проглатываются, а на macOS частично работают, то есть две ОС ведут себя по-разному.
- Отклонено (D): сочетание терминала выключает режим, а потом выполняется. Противоречит решению 1 и рвёт серию вида «вкладка → переход → сплит».
- Цена варианта A: сочетание терминала, нажатое в режиме, продлевает его ещё на 5 секунд.

Технические решения:

**6. Проглатывание — `prevent_fallback = true` у обоих входов.** Это `ActivateKeyTable` для `windows` (Ctrl+Shift+Space) и для `resize_pane` (`r`, с прежним `replace_current`). Копия Ctrl+Shift+Space в RESIZE (решение 7) несёт то же действие, поэтому WINDOWS поверх RESIZE тоже проглатывает.
- Альтернатива: запись-ловушка «любая клавиша». Отклонено: такой привязки в WezTerm нет.

**7. Копии сочетаний делаются одним проходом по готовому `config.keys` в конце сборки.** Проход идёт после последней записи в `config.keys` (сейчас это Cmd-сочетания macOS). Для каждой пары (клавиша, модификаторы) из `config.keys` в таблицы `windows` и `resize_pane` добавляется запись с тем же действием. Если пара в таблице режима уже занята, она пропускается: команда режима важнее. Сейчас так только с Ctrl+Shift+Space в `windows`.
- Так WT-KEYS-8 («одна запись на пару») выполняется по построению, а новые сочетания, в том числе из `resolve-key-ownership-conflicts`, попадают в режимы сами.
- Альтернатива: дописать копии руками в литералы таблиц. Отклонено: получится вторая копия списка, которая разойдётся с первой при следующей правке.
- Альтернатива: собирать `config.keys` и таблицы режимов из одной декларативной таблицы. Здесь отклонено: это шаг `restructure-wezterm-config` (его решение 4). Этот change делает минимальную правку в нынешнем устройстве файла.
- Работает, только если проход идёт после последней записи в `config.keys`. Нарушение ловит проверка покрытия (решение 12).

**8. Пометка «открывает экран» ставится там, где сочетание объявлено.**
- Помощник получает вид `map(key, mods, action, opts)`. Четвёртый аргумент необязателен; `opts.leaves_mode = true` стоит у Ctrl+Shift+W, Ctrl+Shift+U, Ctrl+Shift+X и Cmd+Q.
- Пометка хранится в локальной таблице рядом с `config.keys`, по ссылке на запись. В саму запись привязки лишних полей не пишется: WezTerm разбирает её как свою структуру.
- В таблице режима копия помеченного сочетания — `Multiple{ ClearKeyTableStack, <действие> }`. В `config.keys` действие не меняется.
- Альтернатива: узнавать «экранные» действия по типу `act.*` в Lua. Отклонено: значения `act.*` непрозрачны, и их вид зависит от версии WezTerm.
- Альтернатива: список пар «открывают экран» внутри прохода копирования. Отклонено: знание отрывается от объявления сочетания и при правках расходится с ним.
- Независимый оракул — в проверках (решение 12): там экранные действия узнаются по имени в выводе `show-keys`.
- Сигнатура `map(key, mods, action, opts)` совпадает с задуманной в `restructure-wezterm-config`.

**9. «Выключить режим до действия» — это `ClearKeyTableStack`, а выход по Esc, Enter и Ctrl+Shift+Space — `PopKeyTable`.**
- С `ClearKeyTableStack` начинаются команды группы «выходят» (q, x, a, `,`, w, Shift+S, `[`, f, Space, b, e, `;`, m, d) и копии помеченных сочетаний.
- Esc, Enter и Ctrl+Shift+Space снимают только верхний слой (WT-WIN-11).
- Почему не `PopKeyTable` везде: если WINDOWS лежит поверх RESIZE, после `PopKeyTable` под запросом остался бы RESIZE. Теперь он проглатывает клавиши, и запрос не получал бы ввод, пока RESIZE не истечёт.
- Альтернатива: Ctrl+Shift+Space из RESIZE заменяет RESIZE, а не ложится поверх. Тогда в стеке всегда один слой, и `PopKeyTable` равносилен выходу из всех слоёв. Отклонено: это меняет WT-WIN-11 («после выхода из WINDOWS снова RESIZE») без решения владельца. Если понадобится, это отдельный change.
- `ClearKeyTableStack` не трогает таблицы copy mode и search mode, они живут на оверлее панели. Поэтому `[` и Ctrl+Shift+X из режима по-прежнему приводят в copy mode.

**10. `o` → `ActivatePaneDirection("Next")`.** Порядок — индекс панели во вкладке, после последней идёт первая. Зум снимается, потому что `unzoom_on_switch_pane` по умолчанию включён и конфиг его не трогает. `q` и `x` переходят в группу из решения 9.

**11. Для режима поверх уже открытого экрана своего кода нет.** Порядок из WT-WIN-21 получается сам из порядка поиска WezTerm (Context) и решения 6: сначала таблица copy mode или search mode на оверлее панели, потом стек окна с `prevent_fallback`, потом `Nop`. Исключений два, оба записаны в WT-WIN-21 как ограничения WezTerm:
- Space в copy mode: `phys:Space` режима совпадает в raw-проходе раньше, чем имя `Space` в copy mode;
- модальные экраны (выбор панели, выбор символа, палитра): они получают клавиши приготовленного прохода раньше таблиц.

Отклонённые альтернативы:
- Запретить вход в режим поверх экрана. Отклонено: в 20240203 из Lua не видно, открыт ли модальный экран.
- Перевести Esc, Enter и стрелки в таблицах режимов на `phys:`, чтобы и поверх модальных экранов поведение совпало на двух ОС. Отклонено вместе с вариантом B из решения 5 (WT-KEYS-2).

**12. Проверки идут по настоящему разбору конфига, для обеих ОС.** *Уточнено при реализации:* к этому моменту `add-wezterm-spec-checks` дал общий тестовый слой, и шесть сценариев стали проверками с меткой «windows-mode: …» в `tests/wezterm/windows-mode.test.lua` (поддельный `wezterm`, виды Windows, macOS и Linux). Итог разбора настоящим WezTerm сверяют эталоны `show-keys` (`tests/wezterm/snapshot.test.lua`). Отдельный `tests/wezterm-keys.scenarios.sh` не заводился — это была бы вторая обвязка ради того же. Строки `Проверка:` delta указывают на `windows-mode.test.lua`. Исходный план ниже сохранён для истории.

 Файл — `tests/wezterm-keys.scenarios.sh`: его создаёт или дополняет тот, кто применяется первым, этот change или `change-search-enter-accept`.
- Сначала проверяется, что конфиг загружается без ошибок: `ls-fonts`, в stderr нет `ERROR`.
- Потом снимается `show-keys --lua` с приведением регистра `phys:` к одному виду (research: регистр случаен от запуска к запуску).
- Вид macOS получается обёрткой: она выставляет `wezterm.target_triple = "aarch64-apple-darwin"` и загружает `wezterm.lua` (research: так появляются Cmd-сочетания и пропадает Ctrl+C).

Сценарии (каждый — для вида Windows и вида macOS):
- «windows-mode: вход в режимы проглатывает чужие клавиши»: у каждого `ActivateKeyTable` для `windows` и `resize_pane`, где бы он ни стоял, есть `prevent_fallback = true`;
- «windows-mode: выходы из режима»: Esc, Enter и Ctrl+Shift+Space в `windows`, Esc и Enter в `resize_pane` → `PopKeyTable`;
- «windows-mode: o — следующая панель»;
- «windows-mode: какие команды выходят из режима»: группы WT-WIN-19 поимённо. У «остаются» нет ни `ClearKeyTableStack`, ни `PopKeyTable`. У «выходят» действие — `Multiple`, и первым в нём идёт `ClearKeyTableStack`;
- «windows-mode: сочетания терминала есть в таблицах режимов»: множество пар из `keys` (для `windows` — без Ctrl+Shift+Space) совпадает с множеством пар-копий в `windows` и в `resize_pane`. Действие копии то же самое или обёрнуто по решению 8;
- «windows-mode: сочетания, открывающие экран, выходят из режима»: оракул по имени действия. Любая запись в `windows` или `resize_pane`, в действии которой есть `CloseCurrentPane`, `QuickSelect`, `QuickSelectArgs`, `ActivateCopyMode`, `Search`, `QuitApplication`, `PaneSelect`, `CharSelect`, `ActivateCommandPalette`, `ShowLauncher`, `ShowLauncherArgs`, `ShowTabNavigator`, `PromptInputLine`, `InputSelector` или `ShowDebugOverlay`, начинается с `ClearKeyTableStack`.

Мутация: каждый сценарий падает на копии `wezterm.lua`, снятой до правки.

Если к моменту применения уже есть проверки `add-wezterm-spec-checks` (`tests/wezterm/windows-mode.test.lua`, эталоны `show-keys`), они правятся в том же коммите. Проверки WT-WIN переписываются под delta, эталоны обновляются через `--update-golden` с просмотром diff.

- Альтернатива: только юнит-проверки на поддельном модуле `wezterm`. Как единственный путь отклонено: подделки в репо может ещё не быть, а `show-keys` показывает итог разбора самим WezTerm.
- Поведение в GUI без GUI не проверить: что экран получает клавиши, что буква не напечатана, что делает Esc на macOS. На Windows это проверяется вручную сразу, на macOS — при доступе к Mac. Результат пишется в запись FIXLOG.

**13. Отпускание проглоченной клавиши проверяется на ConPTY-стенде, код не меняется.** WezTerm передаёт отпускание мимо таблиц (Context), поэтому для проглоченной буквы программа на Windows получит в win32-input-mode одинокое отпускание.
- Стенд уже есть (память `wezterm-key-debugging`): Python ctypes и `conpty.dll` из поставки WezTerm, флаги RESIZE_QUIRK | WIN32_INPUT_MODE.
- Он подаёт pwsh и nvim одну запись отпускания `ESC[vk;sc;uc;0;cs;1_`, без нажатия, и сравнивает экран до и после. Символа на экране быть не должно.
- Результат пишется в FIXLOG строкой «Проверено вручную».
- В `tests/` стенд не кладётся: он проверяет программы, а не конфиг, и тянет новую зависимость (Python). Если стенд вырастет в набор проверок, это отдельный change.
- Альтернатива: не проверять вовсе. Отклонено: WT-WIN-20 обещает, что программа нажатие не получает, а стенд уже готов.

**14. Комментарии `wezterm.lua`.**
- `405-413`, модель режима: клавиши без команды проглатываются, сочетания терминала работают.
- `562-569`, правило выхода: `ClearKeyTableStack` и пометка `leaves_mode`.
- `646-647`: вместо «один Esc = выход из любого модального слоя» — «Esc и Enter из RESIZE ведут сразу в обычный ввод; Esc снимает только верхний слой (WT-WIN-11)».

То, что уже записано в спеке, в комментариях заменяется ссылкой на ID.

## Risks / Trade-offs

- [Порядок проходов и поведение модальных экранов выведены из исходника 20240203, в GUI не проверялись] → Ручная проверка на Windows до записи FIXLOG, на macOS — при доступе к Mac. Если GUI разойдётся со спекой, change возвращается на уточнение спеки, а не правится молча.
- [Копирование окажется раньше последней записи в `config.keys`, и часть сочетаний не попадёт в режимы] → Сценарий «сочетания терминала есть в таблицах режимов» сравнивает множества пар на обеих ОС.
- [Новое сочетание, открывающее экран, добавят без пометки `leaves_mode`] → Оракул по имени действия в сценарии «сочетания, открывающие экран, выходят из режима».
- [Сочетание терминала держит режим ещё 5 секунд, и серия Ctrl+Shift+PageDown не даёт ему погаснуть] → Это решение владельца. Бейдж WINDOWS виден, выход — Esc.
- [WINDOWS, включённый поверх search mode, проглатывает набор шаблона, а бейдж показывает SEARCH] → Описано в WT-WIN-21, выход — Ctrl+Shift+Space или таймаут. Бейдж — Non-Goal.
- [Отпускание проглоченной клавиши доходит до программы (win32-input-mode, kitty с отчётом о событиях)] → Так было и для команд режима. На Windows проверяется стендом (решение 13), на macOS — вручную в Claude Code.
- [Названия части сценариев остались от прежнего поведения, например «Буква без команды уходит в программу» и «Метки перехватывает сам режим». OpenSpec 1.13.2 при архивации не даёт убрать сценарий из MODIFIED-требования] → Тела этих сценариев прямо говорят «больше не уходит» и «больше не перехватывает».
