# Design

## Context

IDE-026 воспроизведён при закрытии после появления истории, до окончания use_entry. Закреплённый Diffview 4516612 совпадает с upstream HEAD. Закрытие уничтожает FileEntry/окна, пока create_buffer/open_files ещё ожидают Git. Существующий ordinary Git e2e намеренно ждёт cur_entry.opened и эту гонку не покрывает.

## Goals / Non-Goals

**Goals:** общий для ОС адаптер жизненного цикла, немедленный возврат фокуса, безопасная очистка конкретного view, real e2e раннего закрытия и повторного открытия.

**Non-Goals:** форк/patch private методов Diffview, новый Git backend, Neogit IDE-028, прямое программное закрытие private объектов сторонним кодом и произвольное уничтожение native tab через tabclose во время загрузки.

## Decisions

- События view_opened и локальные file_open_pre/post учитывают выполняющиеся открытия. Пока загрузка не закончилась, запрос закрытия возвращает исходный tab/window; фактическое уничтожение view откладывается до безопасной точки. Нормальное готовое закрытие остаётся непосредственным. Контроллер ожидает также начальную готовность и обновление панели истории, включая пустой результат.
- Пользовательская команда DiffviewClose обслуживается адаптером; существующие Forge aliases, F4/Alt-w и q продолжают вызывать эту команду. Очистка адресуется сохранённому объекту view, поэтому другой текущий tab не становится целью позднего callback. Методы backend не подменяются.
- Тестовая Git-прокладка через публичный git_cmd задерживает реальный git show до файлового сигнала. Это управление временем внешнего процесса; Git-данные, плагины и пользовательские действия настоящие. Настройка существует только в private тестовой копии конфигурации. Отдельно проверяется естественное быстрое закрытие без прокладки.
- Сохраняются существующие незакоммиченные изменения и append-only FIXLOG. Новый change добавляет IDE-GIT-5 к активной базовой линии git-workflow.

## Risks / Trade-offs

- Короткое время закрывающийся tab живёт в фоне до окончания backend → фокус возвращается сразу, тесты проверяют очистку после реального завершения и отсутствие влияния на другой view.
- Событие post приходит внутри coroutine → уничтожение выполняется после возврата callback, не в середине его стека.
- В начале ещё нет file_open_pre → учитывать ready/updating, отдельно тестировать мгновенное закрытие и пустой diff.
- Git зависает/завершается ошибкой → диагностика и ограниченные ожидания теста; проверять, что управляемая задержка не подменяет успешный Git-ответ.
- Mac/GUI недоступны здесь → команды и явная отметка непроверенной среды.
