## Why

IDE-007: после принятия сигнатуры LuaSnip оставляет предлагаемые параметры,
когда пользователь начинает печатать вне активного поля. В completion.lua
есть только явное сворачивание по Esc (§30 FIXLOG). Ghost text выключен;
нужно отличить placeholders от уже написанных аргументов и меню completion.
Новое требование IDE-SNIP-1 закрепляет безопасную отмену предложения.

## What Changes

- Ручной ввод вне активного поля принятой сигнатуры убирает нетронутые
  параметры и завершает snippet-сессию, сохраняя ввод и заполненные аргументы.
- Ввод в выделенное поле, Tab/Shift-Tab и завершённый вызов продолжают работать.
- Движение курсора само по себе не меняет текст; обычный код и другие буферы
  не затрагиваются. Сложные шаблоны не очищаются по поиску скобок в строке.
- Настоящий completion/LuaSnip E2E и общий Windows/Ubuntu регресс; Mac отдельно.

## Capabilities

### New Capabilities

- `snippet-editing`: IDE-SNIP-1, ручной ввод и отмена неактивных параметров.

### Modified Capabilities

Нет: базовая линия редактора ещё не снята, прежних требований snippet нет.

## Impact

lua/plugins/completion.lua и небольшой helper взаимодействия с LuaSnip;
tests/e2e с fixture, registry, docs/FIXLOG/история/roadmap. Общий код без
OS-веток и новых скачиваемых зависимостей.
