# Design

## Context

Мотивация — proposal.md, раздел Why. Ограничения:

- В `install-macos.sh` исправленная логика уже есть и проверена 61 сценарием под bash 5.2 и 3.2.57 (FIXLOG §43): каталог скрипта один раз на верхнем уровне, `resolve_path`, `link_wezterm_config`, `backup_path`. В `install-linux.sh` — старая копия.
- Бутстрапа, как на macOS, у `install-linux.sh` нет: при `curl | bash` рядом нет ни чекаута, ни `wezterm.lua`, и шаг подключения честно пропускается.
- Linux не входит в две машины владельца («по возможности» в `openspec/config.yaml`). Проверка — песочница в WSL: переменная `DISPLAY` изображает GUI-сессию, настоящего рабочего стола нет.
- OpenSpec 1.13.2 сохраняет имена сценариев в MODIFIED. Все девять прежних имён WT-LOAD-13 оставлены, их тела описывают новое поведение.
- Объём решён владельцем 2026-09-27 (Decision 6): только исправления 1–5 и команда в шапке. Окружение сессии Linux (аналог launchd), профили шелла и проверка загрузки не затрагиваются.

## Goals / Non-Goals

**Goals:**

- Исправить пять дефектов WT-LOAD-13 так, чтобы macOS и Linux исполняли один и тот же код подключения, а не две копии.
- Сделать ручную команду в шапке `wezterm.lua` рабочей на чистом HOME.
- Закрыть каждый сценарий WT-LOAD-13 проверкой в `tests/install-linux.scenarios.sh`.

**Non-Goals:**

- Нейтрализация перекрытий (`~/.wezterm.lua`, `WEZTERM_CONFIG_FILE`) и проверка итога на Linux — владелец решил не делать (Decision 6).
- Режим установки в `~/.config/nvim` у `install-linux.sh`: по умолчанию он клонирует весь монорепо, как MAC-INST-10. На macOS этот режим становится симлинком `~/.config/nvim` → `<чекаут>/nvim_forge` (change `fix-macos-installer`, Q12 = B). Тот же симлинк на Linux — follow-up change после этого. Общий файл функций (Decision 1) ему пригодится: правило «уже ведёт → не трогать, иначе бэкап и симлинк» у него то же.
- Шаги пакетов, Nerd Font и установки пакета WezTerm на Linux.
- Флаги Linux в документации (divergence 12, change `sync-docs-with-baseline`).
- Бутстрап `curl | bash` с клоном и перезапуском на Linux, как MAC-INST-3.

## Decisions

1. **Один файл функций подключения на оба установщика: `nvim_forge/scripts/lib/wezterm-link.sh`.**
   - В нём `resolve_path`, `link_wezterm_config` и проверка «путь внутри чекаута».
   - `backup_path` остаётся в каждом установщике: её вызывает и установка конфига, которая работает и без файла функций (при `curl | bash` на Linux). Контракт вызывающего записан в шапке файла: функции `step`, `info`, `backup_path`.
   - Код совместим с bash 3.2, потому что его исполняет и macOS.
   - Почему общий файл: дефекты существуют ровно потому, что §43 починил одну из двух копий. Потребителей два, и оба реальные, так что граница себя оправдывает.
   - Отвергнуто:
     - скопировать функции в `install-linux.sh` — повторяет причину бага;
     - оставить копии и добавить тест на их побайтное совпадение — проверка проблемы, которую можно просто убрать.
   - Файл подключается по пути от каталога скрипта (`$SCRIPT_DIR/lib/wezterm-link.sh`), если он там есть, и до первого вызова его функций: в `install-macos.sh` `resolve_path` зовёт уже поиск `wezterm.lua`. Файл лежит рядом, когда скрипт запущен из чекаута или из установленного конфига, куда `lib/` копируется вместе с `nvim_forge/`. Скрипт, скачанный отдельно и запущенный как файл, файла не находит и, как и сейчас, пропускает шаг с `wezterm.lua not found near the config; skipping terminal config link`.
2. **Каталог скрипта — один раз на верхнем уровне**, через `${BASH_SOURCE[0]:-}` и проверку, что это реальный файл, как в `install-macos.sh`. Его используют и шаг WezTerm, и установка конфига.
   - Побочный эффект в режиме `~/.config/nvim`, который вне охвата: при `curl | bash` «запущен из чекаута» становится ложью, а не угадывается от текущего каталога. Это правдивый ответ, записан в Risks.
3. **`XDG_CONFIG_HOME` внутри чекаута не учитывается.**
   - Каталог для симлинка — `${XDG_CONFIG_HOME:-~/.config}`. Исключение — `XDG_CONFIG_HOME` после раскрытия симлинков лежит внутри корня чекаута (с разделителем на конце, чтобы `/repo-other` не считался внутри `/repo`); тогда берётся `~/.config`.
   - На macOS ту же задачу решает `XDG_CONFIG_HOME` из launchd. На Linux аналога нет вне вопроса о паритете, поэтому берётся шелл.
4. **Ручная команда в шапке:** `mkdir -p ~/.config/wezterm && ln -sf "$PWD/wezterm.lua" ~/.config/wezterm/wezterm.lua` (из корня репо) и строка «или `./nvim_forge/scripts/install-linux.sh`». `ln -sf` без бэкапа — осознанный выбор ручного способа: пользователь видит, что заменяет.
5. **Тесты — `tests/install-linux.scenarios.sh` по образцу macOS.**
   - Свой HOME, `env -i`, `DISPLAY=:0`, `FORGE_NVIM_SKIP_DEPS=1`, `FORGE_NVIM_DEPS_ONLY=1`.
   - Заглушки: `wezterm` — пакет уже стоит, `fc-list` — шрифт уже есть. Сети нет.
   - L1–L10 соответствуют сценариям WT-LOAD-13. L11 вынимает строку команды для Linux из шапки `wezterm.lua` и выполняет её в чистом HOME, так что шапка и тест не разъедутся.
   - `mk_checkout` в обоих наборах копирует и `nvim_forge/scripts/lib/`.
   - Набор macOS прогоняется в этом же change: он исполняет тот же общий код.
6. **Решение владельца 2026-09-27: паритет с macOS — только исправления 1–5 и команда в шапке (Q13 = A).**
   - Шаг Linux чинит собственные дефекты (1–5) и больше ничего не делает. Перекрытия (`~/.wezterm.lua`, `WEZTERM_CONFIG_FILE`) по-прежнему молча перекрывают симлинк, код 0. Сценарий WT-LOAD-13 «перекрытия не нейтрализуются и итог не проверяется» не меняется, новых требований нет.
   - Отвергнуто владельцем:
     - (B) предупреждения без правок: называть `~/.wezterm.lua` и `WEZTERM_CONFIG_FILE`, проверять загрузку через `ls-fonts`;
     - (C) полный паритет: бэкап `~/.wezterm.lua`, блок `unset` в профилях, окружение сессии вместо launchd, проверка итога с кодом 1.
   - Следствие для конструкции: в общий файл (Decision 1) уходят только функции подключения. Нейтрализация и проверка итога остаются в `install-macos.sh`: у них один потребитель, и граница для них себя не оправдала бы.
   - Режим `~/.config/nvim` на Linux (на macOS решён симлинком, Q12 = B) — не здесь, follow-up change (Non-Goals).

## Risks / Trade-offs

- [Общий файл меняет и `install-macos.sh`, который правит change `fix-macos-installer`] → тот change тоже трогает функции подключения. Он выделяет из `link_wezterm_config` общую функцию «симлинк с бэкапом» для `~/.config/nvim` и зовёт проверку «путь внутри чекаута» для `XDG_CONFIG_HOME` (его Decisions 10 и 13). Кто применяется вторым, переносит правки другого в общий файл, а не заводит копию. Набор macOS (bash 5.2 и 3.2.57) обязателен в обоих changes.
- [WSL — не рабочий стол Linux] → проверяется только файловая логика и выбор каталога. GUI-сессия изображается `DISPLAY`. Поведение настоящего WezTerm на Linux не проверяется, как и сегодня.
- [Режим `~/.config/nvim` при `curl | bash` перестаёт угадывать чекаут по текущему каталогу] → новое поведение правдивое, а угадывание срабатывало только случайно. Режим целиком решается в `fix-macos-installer`.
- [Самоссылка, оставленная старой версией (дефект 1)] → новый установщик её не чинит: `wezterm.lua` репо тогда не файл, и шаг пропускается. Восстановление руками (`git checkout -- wezterm.lua`) описывается в записи FIXLOG.

## Migration Plan

- Пользователю достаточно запустить `install-linux.sh` ещё раз:
  - верный относительный симлинк и каталог-симлинк на чекаут больше не трогаются;
  - битый каталог-симлинк чинится.
- Тем, у кого старая версия уже заменила `wezterm.lua` репо самоссылкой: `git checkout -- wezterm.lua` в чекауте (или вернуть `wezterm.lua.backup-*`), затем удалить лишний бэкап. Инструкция — в записи FIXLOG.
- Откат — revert `install-linux.sh`, `lib/wezterm-link.sh` и подключения в `install-macos.sh`. Формат состояния (бэкапы, симлинки) не меняется.
