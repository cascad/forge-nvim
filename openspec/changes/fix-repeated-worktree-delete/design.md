# Design

## Context

См. proposal.md. IDE-034 освобождает cwd редактора, IDE-035 превращает исчезнувший process cwd в обычную ошибку Git. Однако сам `git -C linked show` меняет cwd живого Git и может удерживать каталог до завершения вывода. CLI A/B в .tests/ide038-show-cwd-cli.json: 524288 байт, процесс жив, remove 255 с -C и 0 без -C при явном git-dir. Private real editor live gate на том же классе чтения дал remove 255 (2580195205900).

Шесть естественных повторов с observer прошли; remove cwd и cwd всех окон уже main. Это не доказывает владельца handle первоначального случайного сбоя 551474721600. Исправляется установленный класс object read, не все причины Permission denied.

## Goals / Non-Goals

**Goals:** сохранить репозиторий/HEAD каждого запроса, убрать ненужное удержание cwd в object read, отличать живой Git от задержанного результата, защитить исходный IDE-035 и последующие stage/unstage.

**Non-Goals:** собственный Git backend, ожидание по произвольной паузе, blind retry/force, завершение чужих процессов, устранение всех внешних блокировок, изменения Neogit/SDK, IDE-039/040 и Mac-проверка без машины.

## Decisions

1. Все Repo commands запускаются с явным process cwd в общем git-dir (`self.commondir` либо штатный get_commondir на первом config-запросе). Show сохраняет выбранный absolute git-dir/HEAD без перехода в worktree, остальные команды получают -C выбранного toplevel. Это покрывает и редактор, уже находящийся в linked: унаследованный cwd оказался недостаточен (5849083854000, Git 255). Не нужен разбор формы аргументов show в command builder.
2. В Git gate добавить отдельный режим живого чтения: большой tracked blob заполняет pipe, marker подтверждает живой PID Git до remove. После release возвращаются настоящий вывод и код. Режим completed IDE-035 сохраняется. Proxy освобождает собственный cwd; удерживать каталог должен настоящий Git в baseline.
3. Общие UI шаги двух наборов вынести в test helper. Новый набор проверяет live remove, dirty cancel с разными main/linked HEAD и live read при уже текущем linked cwd; исходный completed gate и его upstream red replay сохраняются. Blob разбит на обычные строки, чтобы не подменять проверку ограничением длины regex/строки.
4. Один существующий hash applier получает companion files внутри декларации плагина: сначала проверяет все исходные/итоговые SHA и рассчитывает изменения, затем пишет. Cmd.lua сохраняет защиту нестабильного cwd и принимает очищаемый перед spawn флаг стабильного metadata cwd; repo.lua задаёт этот cwd и -C для файловых команд. Старый известный cmd.lua IDE-035 обновляется через previous. Check не пишет, неизвестный companion отклоняется до записи любого файла. Manifest включает hashes всех файлов. Явные prepare/Lazy build обновляют существующую установку; отдельного runtime механизма нет.

## Risks / Trade-offs

- Выбор неверного репозитория при унаследованном cwd → сохранять явный absolute git-dir и проверять разные HEAD плюс реальный index main/linked.
- Наследование linked cwd оставляет блокировку → отдельный E2E начинает чтение при cwd редактора linked; process cwd должен быть common git-dir.
- Несколько файлов backport → предварительная проверка всех hashes, LF/CRLF/migration/unknown companion E2E, каждый файл пишется атомарно. Ошибка I/O после начала записи может потребовать повторной явной подготовки; неизвестные исходники не меняются.
- Gate сам удерживает cwd → переносить proxy в main, проверять PID настоящего Git и его код/вывод.
- Первоначальный отказ мог иметь другого владельца → сохранить исходный артефакт и это ограничение, не закрывать внешние/неподтверждённые причины по зелёному повтору.

## Migration Plan

Явно повторить prepare_editor и Docker build, на существующей установке Lazy build gitsigns.nvim. До обновления plugin pin штатно снять известный backport. После upstream исправления повторить оба регресса и удалить временную декларацию.
