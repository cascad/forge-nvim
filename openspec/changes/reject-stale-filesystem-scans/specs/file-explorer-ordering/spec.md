# Spec Delta

## Purpose

Files сохраняет актуальный результат создания файла при изменённом порядке
завершения полных сканирований, сохраняя автоматическое обновление дерева.

## ADDED Requirements

### Requirement: IDE-FILE-5 Старое полное сканирование не стирает новый результат

Files SHALL сохранять уже показанный результат создания файла, когда более
раннее полное сканирование того же дерева завершается после нового полного
сканирования. Созданный файл MUST оставаться доступным в раскрытом каталоге
и открываться Enter без ручного refresh/повторного раскрытия. Автоматические
обновления, async scan и follow MUST оставаться доступными. Независимая
загрузка двух каталогов в одном актуальном дереве SHALL сохранять оба результата.

Платформы: все.
Проверка: будущий tests/e2e/file-scan-order.test.lua; source mechanism —
tests/diagnostics/file-create-order.lua, FIXLOG §178.

#### Scenario: Старый full-root ответ после нового
- **GIVEN** начато полное сканирование с закрытым каталогом
- **AND** пользователь создал в нём файл через a и новый полный результат уже показал файл
- **WHEN** завершается старое полное сканирование
- **THEN** файл остаётся виден, Enter открывает его, запись меняет настоящий файл
- **AND** старый результат не оставляет раскрытый пустой каталог вместо нового дерева

#### Scenario: Обычное создание без задержки
- **WHEN** пользователь создаёт каталог/Unicode файл через A/a и открывает Enter
- **THEN** диск и дерево согласованы, файл можно редактировать и сохранить

#### Scenario: Независимые загрузки папок
- **GIVEN** два каталога с разными дочерними файлами в актуальном дереве
- **WHEN** пользователь раскрывает оба каталога
- **THEN** дочерние файлы обоих каталогов доступны без повторного раскрытия

#### Scenario: Последующие обновления
- **GIVEN** дерево сохранило новый файл после запоздавшего старого ответа
- **WHEN** пользователь создаёт следующий файл или срабатывает настоящий watcher
- **THEN** новый результат появляется, фокус и существующие файлы остаются доступны
