# Design

## Context

См. proposal.md. Проба запускает несколько независимых ConPTY, а общий
`layout` выбирается по foreground HKL один раз. Временный наблюдатель дал
66 PASS на EN; это не устанавливает причину двух прежних RU FAIL.

## Goals / Non-Goals

**Goals:** воспроизводимая read-only диагностика с исходным вердиктом и
метаданными каждого приватного сеанса; отдельные артефакты каждого запуска.

**Non-Goals:** смена раскладки, управление внешними окнами, обновление fixture,
ослабление сравнений или объявление IDE-039 исправленным.

## Decisions

1. Отдельная команда импортирует настоящую пробу и делегирует её main/probe.
   Наблюдатели Session/read_keys только сохраняют параметры, синтетические
   записи стенда и HKL до/после создания и перед вводом. Обычный runner не
   меняется. Альтернатива — переписать основной тест — увеличивает риск
   скрыть исходный регресс во время расследования.
2. HKL переднего окна, потока наблюдателя и primary thread дочернего reader
   подписываются раздельно. Ни одно из этих значений не называется фактической
   раскладкой переводящего потокa OpenConsole. Последнюю ещё предстоит доказать.
3. У каждого запуска уникальный каталог `.tests/artifacts/conpty-layout-*`:
   log, actual, expected, difference, sessions, manifest с provenance/exit code.
   Полные JSON сохраняются и при PASS, и при FAIL; SKIP/exception явно различаются.
4. `--fixture` только читает явно выбранный эталон в этом процессе. Это позволяет
   настоящим ConPTY прогоном проверить путь FAIL с намеренно неверной частной
   копией. Исходный fixture проверяется SHA до/после; обновления не поддерживаются.

## Risks / Trade-offs

- Метаданные могут добавить задержку → короткие WinAPI read-only запросы,
  исходные таймауты и проверки сохраняются, накладные расходы наблюдаемы.
- HKL может смениться внутри длительного прогона → временные метки на каждой
  синтетической записи; отсутствие смены в одном повторе не доказывает причину.
- Намеренный FAIL может быть принят за исходный RU баг → явная provenance
  частного fixture и отдельная подпись результатов в истории.
- Другие ОС → явный SKIP без импорта Windows-only harness; это не Linux/Mac PASS.

## Migration Plan

Добавить команду и инструкцию. Выполнить native PASS и ожидаемый FAIL, проверить
артефакты и неизменность исходных файлов. Откат — удалить диагностическую
команду; runtime, SDK, pin и пользовательские данные не затрагиваются.
