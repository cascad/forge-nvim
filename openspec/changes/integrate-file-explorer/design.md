# Design

## Context

Neo-tree v3 и Nui уже закреплены в lazy-lock. Существуют a/A/r/m/x/p,
safe_rename и guarded_open_commands. Общие controls покрывают DAP/Outline;
один filetype neo-tree обслуживает три компонента. Заголовок Neo-tree — source
selector, его нельзя заменить обычной строкой. Backend связывает объект дерева
с исходным окном, поэтому выбор из zoom требует настоящего пользовательского E2E.

## Goals / Non-Goals

**Goals:** проверить штатные операции на диске, включить дерево в общий
маршрут, сохранить aliases/selector/буферы, Windows и Ubuntu E2E плюс Mac-команда.

**Non-Goals:** собственный file manager, remote FS, LSP file-operation матрица
всех языков, несохранённые буферы при переименовании, Git commit/worktree UI,
delete/trash, GUI/физические клавиши и автоматическая установка зависимостей.

## Decisions

- Штатные операции Neo-tree сохраняются, изменения только по обнаруженному
  воспроизведению. Диалоги и их отмена остаются ответственностью backend.
- Space w e открывает/фокусирует Files. Общие controls определяют компонент
  по источнику буфера; source-переходы через менеджер сохраняют единственный
  left-слот. Нижняя/правая панели не меняются.
- Заголовок показывает фокус вместе с Files/Buffers/Git. Общие q/Esc/? задаются
  после buffer-local mappings Neo-tree; полная штатная справка остаётся доступной.
- Zoom того же буфера сохраняет раскладку. Если backend читает курсор исходного
  окна, перед действием возвращается исходное окно с выбранной строкой.
- E2E — реальный дочерний Neovim с UI, Neo-tree/Nui и private project. Только
  nvim_input для действий; чтение буферов/диска/API для ожидания и доказательств.
  Подмены fs_actions, vim.ui.input, файловых callback и таймеров не используются.

## Risks / Trade-offs

- Асинхронный render/follow: ждать готового дерева/диалога, ошибки не принимать
  как штатный prompt. Проверять lifecycle-регресс из IDE-PANEL-3.
- Сохранённые буферы могут получать новый buffer id при штатном rename/move;
  контракт — путь/содержимое/редактирование, не номер буфера.
- Конфликт пути проверяется с явным отказом от overwrite, без удаления данных.
- macOS/GUI здесь недоступны; это открытая проверка владельца, не PASS.

## Уточнения после воспроизведений

- m использует штатный show_path=absolute. В прежнем режиме get_unused_name
  сохранял родительский префикс и добавлял введённый полный путь к нему повторно.
- Space E выполняет reveal один раз при открытии. При уже видимом Files
  явный reveal сохранён; второй navigate при первом открытии был лишним и
  мог позже обратиться к пути до rename. E2E ждёт _ready настоящего renderer.
- Перед именованной командой Neo-tree из zoom исходному окну возвращается
  выбранная строка и view. Перенос делается после закрытия overlay/WinEnter:
  backend восстанавливает курсор при возврате в окно. Общий adapter mappings
  сохраняет config/desc и делегирует state.commands без подмены модулей.
- requested в ide.state хранит выбор пользователя отдельно от наблюдаемой
  видимости. При смене источника current() может очистить старое окно, но
  after_render принимает новый видимый источник только внутри выбранного
  backend. Это сохраняет также защиту Outline от позднего открытия Neo-tree.
- Selector рендерится штатным get_selector с native mouse targets вместе с
  индикатором фокуса; на узкой панели подписи могут сокращаться.
- E2E использует публичный normal G по видимой строке: '/' занят fuzzy finder.
  После Git/render строка может сдвинуться, поэтому locator повторно читает её.
  Литерал '<' в nvim_input передаётся как <lt>. Это уточнения транспорта теста.
- Финальный регресс нашёл совпадающие <esc> (defaults) и <Esc> (наш override).
  Lua pairs применял одну клавишу дважды; иногда оставался native cancel,
  который не возвращает фокус в код. Override использует исходное имя <esc>.
  Постоянный E2E проверяет один канонический Esc в runtime mappings и пять
  циклов help → дерево → код. Диагностические обёртки отмены удалены.
