## ADDED Requirements

### Requirement: IDE-FILE-7 Отказ файловой операции не блокирует редактор
fride SHALL сохранять управление редактором после ошибки файловой операции,
без modal hit-enter и необходимости прерывать процесс. Normal delete SHALL
выполнять файловый IO асинхронно, сохраняя подтверждение, защиту root/modified
buffers и штатные события. Полная причина ошибки MUST оставаться в Logs/history;
ошибка не считается успешным удалением и не вызывает автоматический retry.
Платформы: все
История: FIXLOG §303
Проверка: tests/e2e/filesystem-errors.test.lua

#### Scenario: Удаление пустого каталога и отмена
- **WHEN** пользователь подтверждает или отменяет native Files dialog
- **THEN** dialog закрывается, normal input/возврат в код/редактирование доступны
- **AND** Enter prompt не ожидает completion filter

#### Scenario: ОС отказывает в удалении
- **GIVEN** реальная блокировка Windows либо POSIX permission denial
- **WHEN** пользователь подтверждает удаление
- **THEN** ошибка с путём доступна в Logs, оставшиеся файлы сохранены
- **AND** можно открыть/изменить/сохранить другой файл и повторить после снятия причины

#### Scenario: Файловый IO ещё не завершён
- **WHEN** native delete ожидает IO
- **THEN** пользователь может вернуться в код и сохранить другой файл
- **AND** native completion применяется один раз после ответа ОС

#### Scenario: Нативная ошибка или длинное сообщение
- **WHEN** Neovim показывает ошибку либо длинное сообщение
- **THEN** история сохраняется, а следующий пользовательский ввод не требует Enter
- **AND** обычные explicit confirm dialogs по-прежнему требуют решения пользователя

#### Scenario: Новая правка во время ожидания результата удаления
- **WHEN** пользователь изменяет открытый файл до завершения async cleanup
- **THEN** cleanup не уничтожает modified buffer
- **AND** пользователь может явно сохранить оставшийся текст
