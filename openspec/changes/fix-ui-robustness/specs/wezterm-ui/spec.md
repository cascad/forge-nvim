## MODIFIED Requirements

### Requirement: WT-UI-1 Шелл по умолчанию на Windows
На Windows терминал SHALL запускать в каждой новой вкладке, панели и окне PowerShell 7 (`pwsh.exe -NoLogo`), если `pwsh.exe` есть в одном из каталогов PATH процесса WezTerm — файлом (установка MSI или winget) или псевдонимом Microsoft Store в `%LOCALAPPDATA%\Microsoft\WindowsApps`, который как файл не открывается, — иначе `powershell.exe -NoLogo` (Windows PowerShell 5.1); `cmd.exe` по умолчанию MUST NOT запускаться.
Платформы: windows
История: FIXLOG 2026-05-31 «WezTerm: шелл/диск, дополнение путей, шрифт, Ctrl+C/V» (проблема 1), §18
Проверка: tests/wezterm/ui.test.lua (сценарии «PowerShell 7 установлен файлом», «PowerShell 7 из Microsoft Store», «PowerShell 7 нет», «Оба варианта установлены» — по программе в конфиге при поддельном PATH); вручную на windows (сценарии «PowerShell 7 из Microsoft Store» и «Смена диска командой cd», результат — в записи FIXLOG)

Если `pwsh.exe` есть в нескольких каталогах PATH, запускается найденный первым по порядку PATH. PATH берётся из окружения, с которым запущен процесс WezTerm; перечитывание конфига его не обновляет, но ищет `pwsh.exe` в тех же каталогах заново. `-NoLogo` убирает баннер PowerShell при старте. Шелл по умолчанию не действует там, где программа задана явно: `wezterm start -- <программа>`, выгрузка истории в nvim (WT-SCROLL-13). Настройки самого шелла — дополнение путей и история PSReadLine, UTF-8 на входе и выходе консоли — конфиг WezTerm не задаёт: их задаёт профиль PowerShell пользователя вне репо. У PowerShell 7 свой профиль (`Documents\PowerShell\`), и чтобы в нём действовали те же настройки, что в Windows PowerShell (`Documents\WindowsPowerShell\`), он подключает профиль Windows PowerShell; как это сделать — `docs/WEZTERM.md`.

#### Scenario: PowerShell 7 установлен файлом
- **GIVEN** `pwsh.exe` лежит в каталоге из PATH, например `C:\Program Files\PowerShell\7\`
- **WHEN** пользователь открывает новую вкладку (Ctrl+Shift+T)
- **THEN** в ней запущен PowerShell 7 без баннера

#### Scenario: PowerShell 7 из Microsoft Store
- **GIVEN** PowerShell 7 установлен из Microsoft Store, в PATH есть только его псевдоним в `%LOCALAPPDATA%\Microsoft\WindowsApps`
- **WHEN** пользователь запускает WezTerm ярлыком и открывает вкладку
- **THEN** в ней запущен PowerShell 7 без баннера (`$PSVersionTable.PSVersion.Major` — 7)

#### Scenario: PowerShell 7 нет
- **GIVEN** `pwsh.exe` нет ни в одном каталоге PATH — ни файлом, ни псевдонимом
- **WHEN** пользователь запускает WezTerm
- **THEN** запущен Windows PowerShell (`powershell.exe`) без баннера
- **AND** терминал стартует, а не падает на отсутствующем pwsh

#### Scenario: Смена диска командой cd
- **GIVEN** в панели шелл по умолчанию, текущий каталог на диске C:
- **WHEN** пользователь вводит `cd D:\`
- **THEN** текущим становится диск D: (в `cmd.exe` без `/d` этого бы не произошло)

#### Scenario: pwsh установлен при работающем WezTerm
- **GIVEN** WezTerm запущен, когда `pwsh.exe` в PATH не было, потом PowerShell 7 установлен через MSI или winget
- **WHEN** пользователь открывает новую вкладку или перечитывает конфиг (Ctrl+Shift+R)
- **THEN** по-прежнему запускается `powershell.exe`
- **AND** `pwsh.exe` начинает запускаться после перезапуска WezTerm с обновлённым PATH

#### Scenario: Оба варианта установлены
- **GIVEN** PowerShell 7 установлен и из Microsoft Store, и через MSI; в PATH каталог `C:\Program Files\PowerShell\7\` стоит раньше `%LOCALAPPDATA%\Microsoft\WindowsApps`
- **WHEN** пользователь открывает новую вкладку
- **THEN** запущен `pwsh.exe` из `C:\Program Files\PowerShell\7\`

### Requirement: WT-UI-4 Шрифт и запасные шрифты
Терминал SHALL рисовать текст шрифтом CaskaydiaCove Nerd Font, а символы, которых в нём нет, MUST брать из встроенных в WezTerm JetBrains Mono, Noto Color Emoji и Symbols Nerd Font Mono, затем из любого установленного в ОС шрифта, где символ есть; сообщение об ошибке шрифта MUST появляться, только если не установлен сам CaskaydiaCove Nerd Font, а предупреждений о символах, которых нет ни в одном шрифте, MUST NOT быть.
Платформы: все
История: FIXLOG 2026-05-31 «WezTerm: шелл/диск, дополнение путей, шрифт, Ctrl+C/V» (проблема 3)
Проверка: tests/wezterm/ui.test.lua (список шрифтов на windows, macos и linux — сценарий «Нет запасного шрифта из списка»); `wezterm ls-fonts --text` на windows (сценарии «Шрифт установлен» и, с пробным конфигом, «Основной шрифт не установлен»); вручную на macos (сценарий «Нет запасного шрифта из списка», результат — в записи FIXLOG)

Основной шрифт указан двумя именами, «CaskaydiaCove NF» и «CaskaydiaCove Nerd Font»; установленный Nerd Fonts 3.x находится по обоим, это один и тот же файл. Других шрифтов в списке нет, одинаково на всех ОС: на машине без CaskaydiaCove текст рисуется встроенным JetBrains Mono, иконки Nerd Font — встроенным Symbols Nerd Font Mono. Сам шрифт ставится отдельно: на Windows вручную (`winget install --id DEVCOM.CascadiaCodeNerdFont`), на macOS — установщиком (MAC-INST-6). Если его нет, открывается отдельное окно «wezterm Configuration Error» с текстом «Unable to load a font specified by your font=wezterm.font('<имя>', …) configuration. Fallback(s) are being used instead…», по сообщению на каждое из двух имён; позже, при первом жирном или курсивном тексте, туда же могут добавиться сообщения о вариантах этого шрифта. Отсутствие любых других шрифтов, в том числе Consolas, Cascadia Mono и Inconsolata Nerd Font Mono, сообщений не даёт. `wezterm ls-fonts` сообщений об ошибках шрифтов не печатает, но `wezterm ls-fonts --text <текст>` показывает, каким шрифтом рисуется каждый символ. Если символа нет ни в одном шрифте, рисуется заглушка без уведомления. Размер шрифта — WT-STATE.

#### Scenario: Шрифт установлен
- **GIVEN** CaskaydiaCove Nerd Font установлен
- **WHEN** шелл или nvim выводит текст и иконки Nerd Font
- **THEN** текст рисуется CaskaydiaCove, иконки видны

#### Scenario: Символа нет в основном шрифте
- **GIVEN** CaskaydiaCove Nerd Font установлен
- **WHEN** вывод содержит эмодзи или иероглиф, которого в нём нет
- **THEN** символ берётся из встроенного в WezTerm шрифта или из шрифта ОС, где он есть
- **AND** уведомления о недостающих глифах нет

#### Scenario: Символа нет ни в одном шрифте
- **GIVEN** вывод содержит символ, которого нет ни в одном шрифте
- **WHEN** WezTerm его рисует
- **THEN** на месте символа заглушка
- **AND** уведомления нет

#### Scenario: Основной шрифт не установлен
- **GIVEN** на машине нет CaskaydiaCove Nerd Font
- **WHEN** пользователь запускает WezTerm
- **THEN** открывается окно «wezterm Configuration Error» с сообщением «Unable to load a font specified by your font=wezterm.font('CaskaydiaCove NF', …) configuration…» и таким же для «CaskaydiaCove Nerd Font», других сообщений о шрифтах в нём нет
- **AND** текст рисуется встроенным JetBrains Mono, иконки Nerd Font видны

#### Scenario: Нет запасного шрифта из списка
- **GIVEN** macOS после установщика: CaskaydiaCove Nerd Font установлен, а Consolas, Cascadia Mono и Inconsolata Nerd Font Mono в системе нет
- **WHEN** пользователь запускает WezTerm
- **THEN** окна «wezterm Configuration Error» нет
- **AND** текст рисуется CaskaydiaCove, как обычно

### Requirement: WT-UI-10 Панель вкладок
Терминал SHALL всегда показывать панель вкладок внизу окна, даже при одной вкладке, в простом однострочном стиле (не «fancy»), с шириной вкладки не больше 24 знакомест.
Платформы: все
История: FIXLOG 2026-08-01 «WezTerm: leader → липкий модальный режим WINDOWS»
Проверка: tests/wezterm/ui.test.lua (сценарии «Одна вкладка», «Длинное название вкладки» — по заголовку вкладки из конфига); вручную на windows (все сценарии, результат — в записи FIXLOG)

Слева направо: вкладки в виде « N: <название> », где N считается с 1, а название — имя вкладки (WT-PANE-11) или заголовок её активной панели; затем кнопка «+»; справа — бейдж режима и имя воркспейса (WT-UI-12, WT-UI-13); левая часть статуса пуста. Длинное название вкладки обрезается справа по ширине вкладки. Если вкладки вместе с кнопкой «+» и местом под правую часть не помещаются в ширину окна, они сужаются поровну; место под правую часть резервируется всегда (WT-UI-15). Работа мышью с панелью вкладок — WT-PANE-13. Панель видна и в полноэкранном режиме. Цвета — из схемы (WT-UI-3). Панель внизу с именем воркспейса справа — видимый признак того, что загружен этот конфиг (WT-LOAD-15).

#### Scenario: Одна вкладка
- **GIVEN** в окне одна вкладка
- **WHEN** пользователь смотрит на окно
- **THEN** панель вкладок видна внизу окна: « 1: <заголовок панели> », кнопка «+», справа имя воркспейса

#### Scenario: Длинное название вкладки
- **GIVEN** у вкладки название длиннее 24 знакомест
- **WHEN** оно показывается в панели вкладок
- **THEN** вкладка занимает не больше 24 знакомест, название обрезано

#### Scenario: Полноэкранный режим
- **GIVEN** окно переведено в полноэкранный режим
- **WHEN** пользователь смотрит на низ экрана
- **THEN** панель вкладок с бейджем и именем воркспейса по-прежнему видна

### Requirement: WT-UI-12 Бейдж активного режима
Пока в окне активен один из четырёх режимов — WINDOWS, RESIZE, copy mode или search mode, — терминал SHALL показывать справа в панели вкладок, перед именем воркспейса, бейдж `▶ <РЕЖИМ>  ·  Esc выход` жирным тёмным (#1e1e2e) текстом на цвете режима; когда ни один из них не активен, бейджа MUST NOT быть.
Платформы: все
История: FIXLOG 2026-08-01 «WezTerm: leader → липкий модальный режим WINDOWS»

| Режим | Надпись | Цвет |
|---|---|---|
| WINDOWS (WT-WIN-1) | WINDOWS | жёлтый #f9e2af |
| RESIZE (WT-WIN-11) | RESIZE | оранжевый #fab387 |
| copy mode (WT-SCROLL-5) | COPY | синий #89b4fa |
| search mode (WT-SCROLL-9) | SEARCH | зелёный #a6e3a1 |

WINDOWS и RESIZE принадлежат окну: их бейдж виден, какая бы вкладка или панель ни была активна. COPY и SEARCH принадлежат панели: бейдж виден, пока активна панель, в которой открыт copy mode или search mode. Если одновременно активны WINDOWS/RESIZE и copy mode/search mode активной панели, бейдж показывает COPY/SEARCH. Бейдж меняется не позже чем через ~0,1 с после входа в режим или выхода из него, в том числе по таймауту (WT-UI-14). WINDOWS и RESIZE, а с ними и бейдж, гаснут и при перечитывании конфига и смене шрифта в окне (WT-STATE-5, WT-STATE-6). Других индикаторов нет: оверлеи, которые тоже перехватывают ввод, — QuickSelect, лаунчер, палитра команд, выбор символа, запросы имени вкладки и воркспейса, подтверждение закрытия панели, debug overlay — своего бейджа не дают. В каждом окне бейдж свой. Бейдж виден целиком при любом числе вкладок и любой длине их названий (WT-UI-15).

#### Scenario: Вход в режим WINDOWS и выход
- **GIVEN** ни один режим не активен, бейджа нет
- **WHEN** пользователь нажимает Ctrl+Shift+Space, а потом Esc
- **THEN** после входа справа появляется жёлтый бейдж «▶ WINDOWS  ·  Esc выход»
- **AND** после Esc бейдж гаснет

#### Scenario: Выход по таймауту
- **GIVEN** режим WINDOWS включён
- **WHEN** 5 секунд не нажимается ни одна команда режима (WT-WIN-3)
- **THEN** режим выключается, и бейдж гаснет сам

#### Scenario: Подрежим RESIZE
- **GIVEN** режим WINDOWS включён
- **WHEN** пользователь нажимает r, а потом Esc
- **THEN** после r бейдж меняется на оранжевый «RESIZE»
- **AND** после Esc бейджа нет: RESIZE заменил WINDOWS, возврата в WINDOWS нет

#### Scenario: Copy mode и поиск
- **GIVEN** ни один режим не активен
- **WHEN** пользователь нажимает Ctrl+Shift+X, затем `/`, затем Esc
- **THEN** после Ctrl+Shift+X виден синий бейдж «COPY», после `/` — зелёный «SEARCH»
- **AND** после Esc бейджа нет

#### Scenario: Copy mode в неактивной панели
- **GIVEN** в левой панели открыт copy mode, виден бейдж COPY
- **WHEN** пользователь переходит в правую панель (Ctrl+Shift+L)
- **THEN** бейдж гаснет, хотя copy mode в левой панели остался
- **AND** при возврате в левую панель бейдж COPY появляется снова

#### Scenario: Copy mode поверх режима WINDOWS
- **GIVEN** режим WINDOWS включён
- **WHEN** пользователь нажимает Ctrl+Shift+X
- **THEN** бейдж показывает COPY, а не WINDOWS
- **AND** если после выхода из copy mode режим WINDOWS ещё не истёк, снова виден бейдж WINDOWS

#### Scenario: Оверлей без бейджа
- **GIVEN** ни один из четырёх режимов не активен
- **WHEN** пользователь открывает QuickSelect (Ctrl+Shift+U)
- **THEN** клавиши перехватывает QuickSelect, а бейджа нет

#### Scenario: Два окна
- **GIVEN** открыты два окна, режим WINDOWS включён в первом
- **WHEN** пользователь смотрит на второе окно
- **THEN** во втором окне бейджа нет

### Requirement: WT-UI-13 Имя воркспейса
Терминал SHALL всегда показывать у правого края панели вкладок имя текущего воркспейса серым цветом #6c7086, с бейджем режима или без него.
Платформы: все
История: FIXLOG 2026-08-01 «WezTerm: leader → липкий модальный режим WINDOWS»

Воркспейс по умолчанию называется `default`. Бейдж режима (WT-UI-12) стоит левее имени. Все окна одного запущенного WezTerm показывают одно и то же имя — активного воркспейса. Переключение воркспейсов — WT-PANE-10. Имя видно целиком при любом числе вкладок; длинное имя сужает вкладки (WT-UI-15).

#### Scenario: Воркспейс по умолчанию
- **GIVEN** WezTerm только что запущен
- **WHEN** пользователь смотрит на правый край панели вкладок
- **THEN** там написано `default`

#### Scenario: Переключение воркспейса
- **GIVEN** WezTerm запущен
- **WHEN** пользователь переключается на воркспейс `work` (режим WINDOWS, Shift+S, ввод `work`, Enter)
- **THEN** у правого края панели вкладок написано `work`

#### Scenario: Имя рядом с бейджем
- **GIVEN** включён режим WINDOWS
- **WHEN** пользователь смотрит на правую часть панели вкладок
- **THEN** слева — бейдж WINDOWS, справа от него — имя воркспейса

### Requirement: WT-UI-15 Правая часть панели вкладок при нехватке места
Бейдж режима (WT-UI-12) и имя воркспейса (WT-UI-13) терминал SHALL показывать в панели вкладок целиком при любом числе вкладок и любой длине их названий; при нехватке места MUST сужаться вкладки, а не правая часть.
Платформы: все
История: FIXLOG 2026-08-01 «WezTerm: leader → липкий модальный режим WINDOWS»
Проверка: tests/wezterm/ui.test.lua (сценарии «Бейдж обрезан», «Вкладки не помещаются», «Мало вкладок», «Вход в режим не сдвигает вкладки», «Окно уже правой части» — по ширине заголовков вкладок из конфига); вручную на windows и macos (сценарии «Бейдж обрезан» и «Вкладки не помещаются», результат — в записи FIXLOG)

Место под правую часть резервируется всегда — в ширину самого длинного бейджа (WINDOWS) и имени текущего воркспейса: бейдж WINDOWS вместе с именем `default` занимает около 38 знакомест. Поэтому вход в режим и выход из него ширину вкладок не меняют, а без режима между кнопкой «+» и именем воркспейса может оставаться пустое место. Вкладки, которые вместе с кнопкой «+» не помещаются в оставшуюся ширину, сужаются поровну, каждая не шире 24 знакомест (WT-UI-10) и не уже одного знакоместа; название обрезается справа. Ширину окна конфиг оценивает по числу столбцов активной вкладки, поэтому у правого края панели может оставаться несколько пустых знакомест. Правая часть не помещается целиком, только если окно уже, чем она сама вместе с кнопкой «+» и одним знакоместом на каждую вкладку; тогда она обрезается слева — сначала бейдж, затем имя воркспейса.

#### Scenario: Бейдж обрезан
- **GIVEN** панель вкладок шириной 120 знакомест, 4 вкладки с названиями длиннее 24 знакомест, воркспейс `default`, включён режим WINDOWS
- **WHEN** пользователь смотрит на правую часть панели вкладок
- **THEN** бейдж «▶ WINDOWS  ·  Esc выход» и имя `default` видны целиком: бейдж больше не обрезается
- **AND** вкладки сужены поровну, примерно до 19 знакомест каждая, названия обрезаны справа

#### Scenario: Вкладки не помещаются
- **GIVEN** панель вкладок шириной 120 знакомест, 5 вкладок с длинными названиями, воркспейс `default`, включён режим WINDOWS
- **WHEN** пользователь смотрит на панель вкладок
- **THEN** каждая вкладка сужена примерно до 15 знакомест
- **AND** бейдж и имя `default` видны целиком

#### Scenario: Мало вкладок
- **GIVEN** панель вкладок шириной 120 знакомест, 2 вкладки с названиями длиннее 24 знакомест, воркспейс `default`
- **WHEN** пользователь смотрит на панель вкладок
- **THEN** каждая вкладка шириной 24 знакоместа, вкладки не сужены
- **AND** правая часть видна целиком у правого края

#### Scenario: Вход в режим не сдвигает вкладки
- **GIVEN** 4 вкладки с длинными названиями, ни один режим не активен
- **WHEN** пользователь нажимает Ctrl+Shift+Space
- **THEN** бейдж WINDOWS появляется целиком на зарезервированном месте
- **AND** вкладки сохраняют ширину и положение
