# Proposal

## Why

Три места, где внешний вид и окружение терминала расходятся с тем, что обещают комментарии, docs и FIXLOG:

- **WT-UI-1, PowerShell 7 из Microsoft Store не находится** (divergence 61). `exe_in_path` (`wezterm.lua:114-126`) засчитывает `pwsh.exe`, только если файл открывается на чтение. У PowerShell 7 из Store в PATH лежит только псевдоним `%LOCALAPPDATA%\Microsoft\WindowsApps\pwsh.exe`, а `io.open` на нём даёт «Invalid argument». Поэтому выбирается `powershell.exe` (`wezterm.lua:129-136`). Воспроизведение (проверено 2026-09-27 на машине владельца): `Get-Command pwsh` указывает на Store-пакет `Microsoft.PowerShell_7.6.6.0`, а дочерние процессы `wezterm-gui.exe` — `powershell.exe -NoLogo`. Комментарий `wezterm.lua:129` и `docs/WEZTERM.md:218` обещают pwsh, если он есть в PATH. FIXLOG §18 называет переход на pwsh 7 радикальным решением проблемы кодировок.
- **WT-UI-4, окно ошибки из-за запасных шрифтов** (divergence 62). Каждый шрифт из `font_with_fallback` (`wezterm.lua:189-199`), которого нет в системе, открывает окно «wezterm Configuration Error» с сообщением «Unable to load a font specified by your font=wezterm.font('<имя>', …)». Исключение — три шрифта, встроенных в WezTerm. Причина в исходнике 20240203: `wezterm-font/src/lib.rs`, `resolve_font_helper`; `is_fallback=false` у всех элементов `font_with_fallback`. Комментарий `wezterm.lua:189-192` задумывал тихий откат «на чужой машине». На macOS после `install-macos.sh` стоит только CaskaydiaCove. Значит, по исходнику, при каждом запуске будет три сообщения: Inconsolata Nerd Font Mono, Cascadia Mono, Consolas. На Mac это не проверено. `wezterm ls-fonts` таких сообщений не печатает, поэтому проверка установщика (WT-LOAD-11) их не ловит.
- **WT-UI-15, бейдж режима обрезается** (divergence 63). Правая часть панели вкладок получает только ширину, оставшуюся после вкладок, и обрезается слева. Причина в 20240203, `wezterm-gui/src/tabbar.rs`, `TabBarState::new`: место под правый статус не резервируется. Воспроизведение: при ширине 120 знакомест и 4 вкладках с заголовком pwsh длиннее 24 знакомест видно только «sc выход  default», надписи WINDOWS нет. При 5 вкладках видно только «efault». Настройки в коде: `wezterm.lua:243-246`, `758-784`. Комментарии `wezterm.lua:237-241` и `751-756` и FIXLOG 2026-08-01 считают бейдж надёжным индикатором режима, а имя воркспейса — видимый признак загруженного конфига (WT-LOAD-15).

## What Changes

- **WT-UI-15.** Бейдж режима и имя воркспейса видны в панели вкладок целиком при любом числе вкладок и любой длине их названий. При нехватке места сужаются вкладки: место под правую часть резервируется в ширину самого длинного бейджа, поэтому вход в режим вкладки не сдвигает. Правая часть может не поместиться, только если окно уже её самой вместе с кнопкой «+» и одним знакоместом на вкладку. Бейдж остаётся справа, как решено в FIXLOG 2026-08-01.
- **WT-UI-4.** Запасные шрифты в конфиге — только те, что гарантированно есть на этой ОС после установки по инструкции репо, плюс встроенные в WezTerm. Такого шрифта нет ни на одной ОС, поэтому в списке остаётся только CaskaydiaCove, а запасными служат встроенные (design). Если запасного шрифта нет в системе, сообщений об ошибке нет. Сообщение о том, что не установлен сам CaskaydiaCove Nerd Font, остаётся: по FIXLOG 2026-05-31 оно помогло найти проблему.
- **WT-UI-1.** PowerShell 7 — шелл по умолчанию на Windows, если он установлен: и из Microsoft Store (псевдоним в `%LOCALAPPDATA%\Microsoft\WindowsApps`, который не открывается на чтение), и через MSI или winget. Иначе, как и сейчас, Windows PowerShell 5.1. Профиль PowerShell 7 подключает профиль Windows PowerShell (dot-source), чтобы настройки PSReadLine (FIXLOG 2026-05-31) и UTF-8 (§18) были те же. Профиль лежит вне репо: его подключение — ручная задача этого change с ручной проверкой (design), а не код и не установщик.
- Абзацы, которые описывают обрезание правой части, приводятся к новому поведению: WT-UI-10 («место под правую часть не резервируется»), WT-UI-12 («бейдж обрезается»), WT-UI-13 («имя обрезается слева»). В WT-UI-12 меняется только эта фраза.
- Комментарии `wezterm.lua`, `docs/WEZTERM.md` и новая запись FIXLOG приводятся к итоговой спеке.
- Решения владельца от 2026-09-27 и отвергнутые варианты записаны в design.md, раздел Decisions:
  1. PowerShell 7 нужен шеллом по умолчанию сейчас, в том числе из Microsoft Store; профиль pwsh 7 подключает настройки Windows PowerShell.
  2. Бейджи для оверлеев, которые тоже перехватывают ввод (QuickSelect, лаунчер, палитра, CharSelect, запросы, подтверждение закрытия, debug overlay), и бейдж COPY/SEARCH при активной другой панели в этот change не входят: это отдельный change позже.
- Не входит: перенос бейджа в левый статус (FIXLOG 2026-08-01 выбрал правую часть); проверка шрифтов установщиком через `ls-fonts` (это WT-LOAD-11 и `fix-macos-installer`); бейджи оверлеев и бейдж COPY/SEARCH неактивной панели (решение владельца 2); настройка профилей PowerShell установщиком.

## Capabilities

### New Capabilities
Нет.

### Modified Capabilities
- `wezterm-ui`:
  - WT-UI-15 — правая часть больше не обрезается, сужаются вкладки;
  - WT-UI-10, WT-UI-12, WT-UI-13 — абзацы про обрезание правой части;
  - WT-UI-4 — отсутствие запасного шрифта больше не даёт окна ошибки;
  - WT-UI-1 — PowerShell 7 находится и из Store, и из MSI/winget (решение 1).

## Impact

- `wezterm.lua`:
  - `exe_in_path` и выбор `default_prog`;
  - `config.font`;
  - `update-right-status` и новый обработчик `format-tab-title` (ширину вкладок задаёт конфиг);
  - комментарии.
- `tests/wezterm/`: юнит-тесты выбора шелла, списка шрифтов и расчёта ширины вкладок с поддельным `wezterm`. Отрисовку панели вкладок и окно ошибки шрифтов проверять вручную, на Windows и на Mac.
- `docs/WEZTERM.md`: шелл по умолчанию (строка 218), панель вкладок. `nvim_forge/FIXLOG.md` — новая запись.
- Вне репо: профиль `Documents\PowerShell\Microsoft.PowerShell_profile.ps1` на Windows подключает `Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1`. Это ручной шаг до переключения шелла, проверяется вручную. Как подключить — в `docs/WEZTERM.md`.
- Платформы: WT-UI-1 — windows, остальное — все.
- Соседний change `sync-docs-with-baseline` правит те же комментарии `wezterm.lua` (бейдж, имена шрифтов) и переписывает `docs/WEZTERM.md`. Правки этого change делаются поверх его результата.
