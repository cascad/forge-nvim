# Design

## Context

Мотивация — в proposal.md, раздел Why. Требования — в `specs/wezterm-ui/spec.md` этого change. Здесь только то, что определяет способ исправления. Ссылки на исходник — WezTerm 20240203-110809-5046fc22.

- **Шелл.** `exe_in_path` (`wezterm.lua:114-126`) засчитывает `pwsh.exe`, если файл открывается через `io.open`, то есть через `fopen` из CRT. На псевдониме Microsoft Store (`%LOCALAPPDATA%\Microsoft\WindowsApps\pwsh.exe`, точка повторной обработки AppExecLink) `io.open` даёт «Invalid argument». Это проверено 2026-09-27 на машине владельца, там же `io.open` на файле из пакета в `C:\Program Files\WindowsApps\…` вернул OK. Сам WezTerm запускает программу по PATH через `portable-pty`. Видят ли псевдоним `wezterm.glob` (метаданные файла через Rust std) и `wezterm.read_dir` (листинг каталога), здесь не проверялось. Запускается ли псевдоним по полному пути, тоже не проверялось.
- **Профиль.** Настройки PSReadLine (FIXLOG 2026-05-31, проблема 2) и UTF-8 (§18) лежат в `Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1`, вне репо. PowerShell 7 читает свой профиль, `Documents\PowerShell\Microsoft.PowerShell_profile.ps1`. Установщики репо профили PowerShell не трогают: `install-windows.ps1` о них ничего не знает.
- **Шрифты.** Ошибки шрифтов показывает `resolve_font_helper` (`wezterm-font/src/lib.rs` @20240203). Сообщение выдаётся для каждого незагруженного атрибута без `is_fallback`. Флаг `is_fallback` стоит только у трёх встроенных шрифтов, а у всех элементов `font_with_fallback` его нет. Из Lua этот флаг не задаётся: это внутреннее поле `FontAttributes` без документации.
- **Панель вкладок.** Раскладку считает `TabBarState::new` (`wezterm-gui/src/tabbar.rs:280-560`). Ширина панели — ширина окна в знакоместах: `pixel_width / cell_width`, `termwindow/mod.rs:1906`. Вкладки сужаются, только если сами не помещаются в эту ширину. Правой части достаётся остаток, лишнее срезается слева. Заголовок вкладки даёт синхронный колбэк `format-tab-title`: вкладка, все вкладки, панели активной вкладки с `left`, `width`, `pixel_width`, конфиг, hover, `max_width`. Окна в нём нет. Асинхронные методы окна, например `get_dimensions`, из синхронного колбэка не вызываются. Ошибку в колбэке WezTerm пишет в журнал и рисует заголовок по умолчанию (`tabbar.rs:98-101`).
- **Тесты.** Тестов на `wezterm.lua` в `tests/` пока нет. `add-wezterm-spec-checks` (design, решение 3) описывает общий поддельный `wezterm` под `nvim -l` и файл `tests/wezterm/ui.test.lua`. Здесь используется та же подделка, вторая не появляется.

## Goals / Non-Goals

**Goals:**
- Выбор шелла — чистая функция от строки PATH и проверки «файл есть в каталоге». Выбор и запуск не расходятся: запускается ровно тот путь, который найден.
- PowerShell 7 включается вместе с теми же настройками PSReadLine и UTF-8, что уже работают в Windows PowerShell. Переключение шелла не должно откатить FIXLOG 2026-05-31 и §18.
- Ни на одной ОС нет окна ошибки из-за шрифта, кроме случая, когда нет самого CaskaydiaCove.
- Ширина вкладок — чистая функция от того, что есть в `format-tab-title`: без общего состояния между событиями, без асинхронных вызовов.
- Всё, что не зависит от GUI, проверяется детерминированно: без настоящего PATH, шрифтов и окна.

**Non-Goals:**
- Бейджи для оверлеев (QuickSelect, лаунчер, палитра, CharSelect, запросы, подтверждение закрытия, debug overlay) и бейдж COPY/SEARCH при активной другой панели. Это решение владельца 2 (D2), отдельный change.
- Перенос бейджа в левую часть панели (FIXLOG 2026-08-01) и изменение его текста и цветов (WT-UI-12).
- Проверка шрифтов установщиком через `ls-fonts` (WT-LOAD-11, `fix-macos-installer`) и установка дополнительных шрифтов.
- Настройка профилей PowerShell установщиком (D4).
- Шелл на macOS и Linux (WT-UI-2).
- Содержание заголовка вкладки (имя вкладки или заголовок панели, WT-PANE-11) и работа мышью с панелью вкладок (WT-PANE-13).

## Decisions

### D1. Шелл по умолчанию на Windows

Решение владельца 2026-09-27: вариант (a). PowerShell 7 — шелл по умолчанию. Он находится и из Microsoft Store (псевдоним в `%LOCALAPPDATA%\Microsoft\WindowsApps`, который не открывается на чтение), и из MSI или winget. Если PowerShell 7 нет — Windows PowerShell 5.1. Профиль pwsh 7 подключает те же настройки PSReadLine и UTF-8, что профиль 5.1 (dot-source).

Отвергнуты:
- (b) Всегда Windows PowerShell 5.1, без поиска pwsh. §18 называет pwsh 7 радикальным решением кодировок (родной UTF-8 без BOM), и он уже установлен.
- (c) Оставить как в коде: pwsh только при установке файлом, Store не считается. Тогда у владельца, у которого pwsh 7 из Store, работает 5.1, а комментарий и docs обещают pwsh.

### D2. Бейджи оверлеев

Решение владельца 2026-09-27: вариант (a). Бейджи оверлеев и бейдж COPY/SEARCH при активной другой панели в этот change не входят, это отдельный change позже. В WT-UI-12 меняется только фраза про обрезание. `active_key_table()` в 20240203 оверлеи не показывает, поэтому сначала нужно исследовать, можно ли их распознать из Lua.

Отвергнут вариант (b): добавить бейджи оверлеев здесь. Он меняет WT-UI-12 по существу и зависит от неисследованного API.

### D3. Поиск pwsh: наличие без открытия, порядок PATH, запуск найденного пути

- Каталоги PATH перебираются по порядку. В каждом `pwsh.exe` засчитывается, если он есть в каталоге как запись: проверка без открытия файла. Первый найденный полный путь идёт в `default_prog` вместе с `-NoLogo`. Если ничего не найдено — `powershell.exe -NoLogo`.
- Проверку наличия выбирает проба на машине владельца (задача 1.1). Сначала `wezterm.glob(<каталог>/pwsh.exe)`: один вызов на каталог, литеральный шаблон. Если glob псевдоним не видит — `wezterm.read_dir(<каталог>)` и поиск записи `pwsh.exe` без учёта регистра. Для каталогов, где `io.open` уже нашёл настоящий файл, листинг не нужен. Оба вызова есть в 20240203.
- Запускается найденный полный путь, а не имя. Так выбор и запуск не могут разойтись: `portable-pty` ищет программу по PATH своими правилами. Проба 1.1 проверяет, что WezTerm запускает псевдоним по полному пути.
- PATH читается в том же месте, где конфиг читает остальные факты о платформе. Функция поиска получает строку PATH и функцию «есть ли файл», поэтому тест подставляет обе.
- Поиск идёт при каждом вычислении конфига, как и сейчас. Поэтому перечитывание конфига находит pwsh, если он появился в каталоге, который уже есть в PATH (WT-UI-1).

Альтернативы:
- `io.open` (как сейчас) — не видит псевдоним, это и есть баг.
- Проверять только `%LOCALAPPDATA%\Microsoft\WindowsApps`. Это частный случай, он не учитывает порядок PATH и ломается, если каталог убран из PATH.
- `wezterm.run_child_process{ "where.exe", "pwsh" }`. Это отдельный процесс на каждое вычисление конфига, а оно повторяется при каждой смене шрифта в окне (WT-STATE-6). Выходит медленно, и может мелькнуть консоль.
- Запускать `pwsh.exe` без проверки. В WezTerm нет запасного варианта при ошибке запуска: вкладка откроется с ошибкой, а WT-UI-1 требует, чтобы терминал стартовал.

Журнал: вычисление конфига повторяется при каждой смене шрифта, поэтому выбор шелла в журнал не пишется, иначе будет шум. Выбор виден в снимке конфигурации `add-wezterm-spec-checks` (`tests/wezterm/golden/config.*`, поле `default_prog`), а на машине — по `$PSVersionTable` в новой вкладке.

### D4. Профиль PowerShell 7 — ручная задача этого change, вне репо

Подключение профиля входит в этот change как ручная задача с ручной проверкой, и выполняется до переключения шелла (Migration Plan). Без него переключение откатит проверенное поведение: Tab снова начнёт подставлять несуществующие пути (FIXLOG 2026-05-31, проблема 2), а консоль потеряет UTF-8 (§18).

В `Documents\PowerShell\Microsoft.PowerShell_profile.ps1` добавляется одна строка: dot-source профиля Windows PowerShell. Путь считается от `$PROFILE` (`Split-Path` дважды → `Documents`), а не от `$HOME\Documents`: папка «Документы» может быть перенаправлена в OneDrive. Строка срабатывает, только если файл есть (`Test-Path`). Если в профиле 5.1 найдутся команды, которые pwsh 7 не понимает, они обводятся проверкой `$PSVersionTable.PSVersion.Major`, а не копируются в отдельный профиль. Источник настроек остаётся один.

Строка и способ проверки описываются в `docs/WEZTERM.md`: документ для человека, и это единственное место в репо, откуда можно повторить настройку.

Альтернативы:
- Установщик `install-windows.ps1` пишет профиль сам. Это новое требование к установщику: его спеки нет, а профиль — личный файл пользователя, в котором может быть что угодно. Если понадобится, это отдельный change с delta.
- Скопировать настройки в профиль pwsh 7. Получатся два источника одних настроек, и они разойдутся.
- Автоматическая проверка через ConPTY-обвязку (conpty.dll и `pwsh -NoLogo` в псевдоконсоли, как в заметке про отладку клавиш). Профиль — окружение одной машины, такой тест в `tests/` падал бы на Mac и на чистой машине. Для разовой настройки хватает ручной проверки с записью в FIXLOG.

### D5. Шрифты: в списке только CaskaydiaCove, запасные — встроенные

`config.font` — `font_with_fallback` из двух имён основного шрифта: «CaskaydiaCove NF» и «CaskaydiaCove Nerd Font». Запасными служат встроенные JetBrains Mono, Noto Color Emoji и Symbols Nerd Font Mono, дальше — системный подбор шрифта для символа. Список одинаковый на всех ОС, ветки по ОС нет.

Шрифта, который гарантированно стоит на каждой ОС после установки по инструкции репо, кроме самого CaskaydiaCove, нет. Consolas есть только на Windows, Menlo — только на macOS, а Inconsolata Nerd Font Mono и Cascadia Mono не ставит ни один установщик репо. Встроенные шрифты есть везде и сообщений не дают.

Альтернативы:
- Список по ОС: Consolas на Windows, Menlo на macOS. Это ветка по ОС ради случая «CaskaydiaCove не установлен». Имя Menlo отсюда не проверить, а выигрыш — только вид текста на чужой машине.
- `is_fallback = true` у запасных элементов. Это внутреннее поле без документации, поведение держалось бы на устройстве конкретной версии.
- Ставить Inconsolata Nerd Font Mono установщиками. Лишние загрузки ради шрифта, который виден, только если нет основного.

### D6. Ширина вкладок: `format-tab-title` резервирует место под самую длинную правую часть

Обработчик `format-tab-title` строит заголовок в прежнем виде « N: <название> »: название — имя вкладки или заголовок её активной панели, не короче 5 знакомест, как у WezTerm по умолчанию. Потом заголовок обрезается справа до ширины `w`:

- `cols` — число столбцов активной вкладки, `max(left + width)` по панелям из аргумента;
- `R` — ширина самого длинного бейджа (WINDOWS) вместе с отступом плюс ширина « <имя воркспейса> ». Имя берётся из `wezterm.mux.get_active_workspace()`, ширина — `wezterm.column_width`;
- `w = min(max_width, 24, max(1, floor((cols − 3 − R) / n)))`, где 3 — кнопка «+», `n` — число вкладок.

Бейдж строит одна функция из одной таблицы режимов, её используют и `update-right-status`, и расчёт `R`. Если панелей в аргументе нет, заголовок режется до `max_width`, как у WezTerm по умолчанию.

Почему резерв под самый длинный бейдж, а не под текущий: в `format-tab-title` нет окна, значит, нет и активного режима. К тому же ширина вкладок не должна прыгать при входе в режим (WT-UI-15, сценарий «Вход в режим не сдвигает вкладки»). Цена — пустое место справа без режима, и только когда вкладки и так не помещаются.

`cols` меньше ширины панели в знакоместах на поля окна (6 + 14 физических пикселей) и остаток от деления. Оценка консервативна: справа остаётся несколько пустых знакомест, но правая часть не срезается. Это записано в WT-UI-15.

Альтернативы:
- Считать бюджет в `update-right-status`: там есть окно, `get_dimensions` и текущий режим. Результат клался бы в таблицу по id окна, а `format-tab-title` читал бы его. Это общее состояние между событиями, которое надо чистить от закрытых окон, и вкладки прыгают при входе в режим.
- Левая часть панели. FIXLOG 2026-08-01 выбрал правую, и proposal это исключает.
- Меньше `tab_max_width` и короче бейдж. Статическое решение: при достаточном числе вкладок правая часть снова срезается.
- Показывать в вкладках только номера. Теряются названия, а спека WT-UI-10 их требует.

### D7. Проверка: поддельный `wezterm` и `nvim -l`

`tests/wezterm/ui.test.lua` использует общую подделку (`add-wezterm-spec-checks`, решение 3). В подделку добавляются:
- `glob` и `read_dir` поверх таблицы «каталог → файлы»;
- `io.open`, который на псевдониме возвращает ошибку, как CRT;
- `font_with_fallback`, который записывает имена;
- `mux.get_active_workspace`, `column_width`, `truncate_right`;
- поддельные вкладки и панели для `format-tab-title`.

Проверки:
- (а) PATH `C:\A;C:\WinApps;C:\Sys`, `pwsh.exe` только псевдонимом в `C:\WinApps`, `io.open` на нём падает → `default_prog = { "C:\WinApps\pwsh.exe", "-NoLogo" }`. Если pwsh и в `C:\A`, и в `C:\WinApps` → берётся `C:\A`. Если pwsh нет → `{ "powershell.exe", "-NoLogo" }`. Для macOS и Linux `default_prog` не задан.
- (б) Имена в `config.font` — ровно «CaskaydiaCove NF» и «CaskaydiaCove Nerd Font» для троек windows, macos и linux.
- (в) `format-tab-title`, `cols = 118`, воркспейс `default`:
  - 4 длинных названия → ширина 19;
  - 5 → 15;
  - 2 → 24;
  - `cols = 28` → 1;
  - для всех случаев `n·w + 3 + R ≤ cols`, заголовок начинается с « N: »;
  - короткое название одной вкладки не меняется;
  - длинное имя воркспейса уменьшает `w`.
- (г) `format-tab-title` не трогает окно и асинхронные API: подделка в этих местах бросает ошибку.
- (д) Для каждого из четырёх режимов ширина правой части, которую ставит `update-right-status`, не больше `R`. Это инвариант «резерв покрывает любой бейдж».

Что тест не доказывает — что WezTerm видит и запускает псевдоним, что окно ошибки шрифтов не появляется и что панель рисуется как рассчитано. Это пробы и ручные шаги на Windows и Mac (tasks).

## Risks / Trade-offs

- [Ни `glob`, ни `read_dir` псевдоним не видят, или WezTerm не запускает его по полному пути] → Это выясняет проба 1.1 до кода. Если так, запуск по имени `pwsh.exe` тоже проверяется пробой. Если и это не работает, change останавливается и возвращается к владельцу через `/opsx:update`: WT-UI-1 для Store тогда невыполнимо штатными средствами.
- [`read_dir` по всем каталогам PATH при каждом вычислении конфига медленный: в System32 тысячи файлов] → `read_dir` нужен, только если glob не видит псевдоним. Проба 1.1 замеряет время `wezterm ls-fonts` с проверкой и без. При заметной разнице листинг ограничивается каталогами, где `io.open` не нашёл файл, и обрывается на первом совпадении.
- [Профиль 5.1 содержит команды, которые pwsh 7 не понимает] → Ручная проверка 2.1 смотрит, нет ли ошибок при старте pwsh. Несовместимые строки обводятся проверкой версии (D4).
- [Поведение, которое держится на профиле, например OSC 7 для каталога новой панели (WT-PANE-12)] → Переходит в pwsh 7 вместе с dot-source. Сценарии WT-PANE-12 проверяются в ручном шаге 2.3.
- [Заголовки вкладок меняются: консоль показывает путь к `pwsh.exe`] → Заголовок — это заголовок панели (WT-PANE-11), его содержание здесь не задаётся. Длинные заголовки теперь сужаются, не срезая правую часть.
- [Без CaskaydiaCove текст рисуется JetBrains Mono, а не Consolas] → Принято (D5). Символы, которых нет в CaskaydiaCove, раньше брались из Cascadia Mono и Consolas, теперь из встроенных и системных шрифтов. CaskaydiaCove — это Cascadia Code с иконками, поэтому разница видна только на редких символах. Внешний вид сверяется вручную на Windows.
- [Резерв под самый длинный бейдж сужает вкладки и без режима] → Только когда вкладки и так не помещаются. Взамен вкладки не прыгают при входе в режим (D6).
- [`format-tab-title` вызывается на каждое обновление панели по разу на вкладку] → Расчёт O(n) без выделений на каждый символ и без асинхронных вызовов. Ошибку в колбэке WezTerm логирует и рисует заголовок по умолчанию, падения нет.
- [Имя сценария WT-UI-15 «Бейдж обрезан» описывает старое поведение] → OpenSpec 1.13.2 требует в MODIFIED все прежние имена сценариев. Текст сценария описывает новое поведение. Переименовать можно редакторской правкой `openspec/specs/` после архивации, по решению владельца. Так же сделано в `fix-copy-clobbers-clipboard`.
- [Mac проверить отсюда нельзя] → WT-UI-4 (нет окна ошибки после установщика) и WT-UI-15 на macOS владелец проверяет на месте. Результат — в записи FIXLOG, до этого там «на Mac не проверено».
- [Параллельные changes: `sync-docs-with-baseline` правит те же комментарии и docs, `fix-windows-mode-modality` — режимы] → Правки делаются поверх результата `sync-docs-with-baseline`. Таблица режимов для бейджа не меняется. Если `fix-windows-mode-modality` добавит режим, он попадёт и в расчёт `R`: таблица одна.

## Migration Plan

1. Подключить профиль PowerShell 7 (задача 2.1) и проверить его в `pwsh -NoLogo`, запущенном вручную. До этого код шелла не меняется.
2. Применить код. Новые вкладки начнут открываться в pwsh 7 после перечитывания конфига: каталог псевдонима уже в PATH. Открытые панели остаются в `powershell.exe`, пока их не закроют. Чтобы все панели были одинаковые, WezTerm перезапускается целиком.
3. Откат — `git revert` коммита. Строку в профиле pwsh 7 можно оставить: на Windows PowerShell 5.1 она не влияет.

Перед коммитом: `nvim -l tests/wezterm/ui.test.lua` зелёный, `wezterm --config-file wezterm.lua ls-fonts` — stderr без `ERROR`.
