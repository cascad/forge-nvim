## Purpose

Сохраняет доступ к выводу отлаживаемой программы при запуске, паузе,
исключении и завершении, чтобы причину сбоя можно было прочитать в редакторе.

## ADDED Requirements

### Requirement: IDE-DAP-1 Вывод первого и повторного запуска

Редактор SHALL показывать нижнюю область вывода активной конфигурации DAP
при запуске и остановке исполнения и сохранять полученный stdout/stderr
после завершения. Новый запуск MUST очищать предыдущий вывод до получения
вывода новой сессии; поздний ответ launch не должен стирать уже полученный текст.
Это включает ранние DAP output events самого адаптера, например сообщения о сборке.
Пользователь может явно скрыть панель; следующая остановка снова показывает её.

Платформы: все
Проверка: tests/e2e/dap-output.test.lua (IDE-DAP-1)

#### Scenario: обычный запуск и повтор
- **GIVEN** небольшой Go-проект с stdout/stderr, реальный Delve и breakpoint
- **WHEN** пользователь запускает его через F5, продолжает и запускает повторно
- **THEN** вывод обоих потоков виден в соответствующей нижней панели
- **AND** завершение сохраняет вывод; повтор не содержит старых строк

#### Scenario: Go remote output с полем console от прежней конфигурации
- **GIVEN** конфигурация Go содержит outputMode=remote и console=integratedTerminal
- **WHEN** Delve отправляет вывод через DAP output events
- **THEN** видна область с этим выводом, даже если терминал не был создан

#### Scenario: скрытая панель при следующей остановке
- **GIVEN** активная DAP-сессия, пользователь скрыл панели
- **WHEN** исполнение останавливается на следующем breakpoint или исключении
- **THEN** sidebar и соответствующая нижняя область снова доступны
- **AND** уже полученный вывод не очищается, фокус остаётся в коде

### Requirement: IDE-DAP-2 Текст исключения во время паузы

При остановке из-за panic/exception редактор SHALL показывать доступные
адаптеру описание и подробности ошибки в выводе отладки без продолжения
программы. Поздний ответ предыдущей остановки или сессии MUST NOT попадать
в вывод новой сессии. Отсутствие exceptionInfo поддерживается без ошибки.

Платформы: все
Проверка: tests/e2e/dap-output.test.lua (IDE-DAP-2)

#### Scenario: panic до печати runtime stderr
- **GIVEN** реальный Go-процесс вызывает panic с узнаваемым текстом
- **WHEN** Delve останавливает его до печати runtime stderr
- **THEN** текст panic уже доступен в Output/REPL
- **AND** процесс остаётся на паузе; предыдущий stdout не потерян

#### Scenario: завершение после panic
- **GIVEN** текст исключения показан на паузе
- **WHEN** пользователь продолжает процесс до выхода
- **THEN** фактический stderr добавляется и остаётся доступен после выхода
