## Context

См. proposal.md. Текущий стек — nvim-dap + dap-ui + Edgy + ide slots.
Go internalConsole/outputMode=remote идёт в dap-repl, Rust runInTerminal
использует dap-terminal. На Windows системный Go 1.23.3 несовместим с
Delve 1.26.3 (минимум Go 1.24). Для теста подготовлены частные Go 1.26.0 и
Delve 1.26.3 в .tests/dap-tools; системная установка не менялась.
В Docker те же версии подготовлены при build.
Bare headless не покрывает UIEnter/VeryLazy; используем существующий RPC UI.

## Goals / Non-Goals

Goals: устранить доказанные потери вывода/панели и добавить текст исключения
в момент паузы, сохранив пользовательские F5/F9 и текущие плагины.
Non-Goals: новые хоткеи/парадигма панелей, смена адаптеров, автопродолжение panic,
полное языковое покрытие, решение zsh Mac или тестовой панели IDE-006.

## Decisions

- E2E использует настоящий Go/Delve и mappings редактора. Fixture stdlib-only,
  GOTOOLCHAIN=local/GOPROXY=off исключают сетевую установку в ходе сценария.
  Подготовка SDK/адаптера Ubuntu выполняется при build, Mac отдельно.
- Проверяем полученные DAP events, видимые буферы и реальные строки Output;
  наблюдатели теста делегируют настоящее поведение, не изображают адаптер.
- Очистка принадлежит новому запуску до событий новой сессии. Очистка в
  callbacks initialized/launch доказанно стирала output event Building до паузы.
  Убираем пользовательские повторы: сам nvim-dap уже чистит REPL перед initialize.
- section_for_config учитывает Go outputMode=remote раньше console: Delve
  реально шлёт DAP output, но старый выбор integratedTerminal скрывал REPL.
- При exception запрашиваем exceptionInfo, если поддерживается; дополнение
  в REPL помечаем как сведения адаптера, не выдаём за уже напечатанный stderr.
  Ответ привязываем к сессии/остановке; не продолжаем и не вычисляем выражения.
- На stopped восстанавливаем отсутствующую область вывода идемпотентно;
  существующую не закрываем и не очищаем. Операции окон планируются вне RPC callback.
  Сам сценарий скрытия панелей прошёл и до исправления (Edgy восстанавливал
  окна); его не объявляем найденной первопричиной. Оставляем постоянным регрессом.

## Risks / Trade-offs

- Точный исходный сценарий владельца неизвестен → сохраняем фактический red
  E2E и различаем найденный дефект от полного воспроизведения его окружения.
- Протоколы адаптеров различаются → общий механизм использует capabilities;
  Go проверяется реально, Rust/Python и macOS остаются явными пунктами матрицы.
- ExceptionInfo может прийти после continue/новой сессии → проверка владельца
  ответа и состояния паузы перед добавлением текста.
- Docker ptrace может требовать SYS_PTRACE/seccomp-настройки → ограничить
  изменение тестовым контейнером, не привилегировать повседневный редактор.

## Migration Plan

Установленные адаптеры сохраняются. Новые E2E входят в общий suite и требуют
явной подготовки инструментов. Откат — удаление нового listener и возврат
прежней политики открытия/очистки; снимки red/green сохраняются в .tests.
