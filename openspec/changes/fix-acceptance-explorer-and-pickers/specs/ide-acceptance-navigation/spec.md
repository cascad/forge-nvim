## ADDED Requirements

### Requirement: IDE-FILE-8 Files отражает диск отдельно от Git
Files SHALL обновляться после успешных create/copy/move/delete без ручного Refresh;
на нём нет Git decorations. Git view сохраняет сведения об удалённых и новых файлах.
Платформы: все.
Проверка: tests/e2e/acceptance-navigation.test.lua.

#### Scenario: Unicode и Git
- **GIVEN** Git-проект, tracked source и открытая целевая папка
- **WHEN** пользователь создаёт, копирует и перемещает файл с кириллицей/пробелом
- **THEN** Files показывает существующие source/destination по факту диска
- **AND** после удаления/перемещения отсутствующий source не остаётся строкой Files
- **AND** Git view отдельно показывает изменение.

### Requirement: IDE-FILE-9 Root и reveal сохраняют контекст
Редактор SHALL давать явный возврат Files к рабочей папке и reveal активного файла
с сохранением состояния несвязанных ветвей; навигация Files не меняет проект.
Платформы: все.
Проверка: tests/e2e/acceptance-navigation.test.lua и project/worktree E2E.

#### Scenario: Выше корня и обратно
- **GIVEN** дерево поднято выше выбранной рабочей папки
- **WHEN** пользователь вызывает возврат к корню
- **THEN** Files ограничен рабочей папкой, cwd проекта прежний.

#### Scenario: Русская раскладка
- **GIVEN** Files поднят выше рабочей папки и включена ЙЦУКЕН
- **WHEN** пользователь нажимает физические g, Shift+R (символы пК)
- **THEN** выполняется тот же возврат к рабочему корню, что для gR на QWERTY.
- **AND** вариант с явным Shift-модификатором у кириллицы также поддержан.

#### Scenario: Reveal
- **GIVEN** раскрытая соседняя ветвь и файл в другой вложенной папке
- **WHEN** пользователь вызывает Space E из файла
- **THEN** раскрыты нужные предки и выбран файл
- **AND** соседняя ветвь сохраняет раскрытие.

#### Scenario: Отложенный reveal и новый input
- **GIVEN** native scan для reveal ещё выполняется, пользователь уже открыл создание файла
- **WHEN** завершается scan
- **THEN** reveal не отбирает фокус у input и введённый путь создаёт файл.

### Requirement: IDE-PANEL-31 Поиск хоткеев и стабильные pickers
Редактор SHALL предоставлять поиск по действующим сочетаниям и быстрый buffer picker;
повторная навигация палитры не меняет текст и отступ строк.
Платформы: все.
Проверка: tests/e2e/acceptance-navigation.test.lua, buffers.test.lua.

#### Scenario: Повторные переходы
- **GIVEN** открыта палитра Ctrl+Shift+P
- **WHEN** пользователь многократно проходит одни строки через Ctrl+J/K
- **THEN** строки сохраняют исходные отступы и команды доступны для выполнения/отмены.

#### Scenario: Поиск управления
- **GIVEN** активен файл или Files
- **WHEN** пользователь открывает поиск хоткеев и вводит описание действия
- **THEN** видны действующие keys и описание, отмена возвращает обычный ввод.
