# Design

## Context

См. proposal.md. Нативный CLI repro показывает: Git из удаляемого cwd или другой процесс, удерживающий этот cwd, оставляет пустой каталог на Windows с exit 255. Git из main удаляет его. Trace Neogit показывает spawn до scheduled chdir. Приватный кандидат с одним `async.util.scheduler()` после chdir прошёл исходный UI E2E на Windows и Ubuntu; основной конфиг на момент сравнения не менялся.

## Goals / Non-Goals

**Goals:** сохранить штатный Neogit UI, дождаться уже запланированной смены cwd, сделать локальный патч явным и воспроизводимым.

**Non-Goals:** свой менеджер worktree, monkeypatch приватных Lua функций во время работы, отмена Gitsigns initial attach (IDE-035), изменение Windows SDK, исправление shell startup, публикация форка/сообщений upstream.

## Decisions

1. Минимальный временный патч закреплённого Neogit `d7bb91b42f984416adc6116d6ba8fba287857af3`. Дополнительный scheduler даёт ранее поставленной смене cwd закончиться до создания Git process. Собственный worktree слой увеличил бы объём поддерживаемого UI; обновление плагина само по себе не подтверждено исправлением — тот же участок upstream оставался прежним при проверке.
2. Один Lua applier и декларация с базовой ревизией, точной заменой и SHA256 до/после. Hash считается после нормализации CRLF→LF, EOL установленного файла сохраняется. При наличии `.git` дополнительно проверяется точный HEAD; экспортированные тестовые архивы сверяются с lock через harness. Неизвестное содержимое не переписывается.
3. Явный CLI подготовки и публичный Lazy `build(plugin)` используют тот же applier. Конфиг Neogit закрепляет commit и при загрузке только проверяет результат, с подсказкой подготовки при отсутствии патча. Подготовленный запуск ничего не меняет. `--revert` отменяет только точно известный патч.
4. Python prepare_editor запускает этот Lua CLI выбранным Neovim и записывает provenance в manifest. Editor и ConPTY harness проверяют payload, не исправляют его во время теста. Docker готовит ту же версию при build. Сеть при e2e не нужна.
5. Отдельный реальный editor E2E: удаление текущего worktree, dirty cancel, реальный внешний commit и повторное удаление/visit. UI stage/commit editor остаётся в существующем git-workflow E2E, не дублируется. Постоянный CLI repro фиксирует различие cwd на Windows/POSIX. Git fixture ограничена собственным потолком каталогов.

## Risks / Trade-offs

- Локальный патч делает checkout Neogit изменённым → закреплённый commit, явные SHA/проверка/отмена; для обновления сначала отменить патч, затем заменить pin/декларацию после E2E.
- CRLF в Windows checkout → нормализованный hash, сохранение исходных переводов строк, отдельный CLI E2E.
- Другой процесс продолжает удерживать удаляемый cwd → штатный Git может отказать; этот патч устраняет гонку самого редактора, но не принудительно закрывает чужие процессы.
- macOS не доступен → общая реализация, команда native E2E в документации, статус непроверено.

## Migration Plan

На существующей установке: `:Lazy build neogit`, затем перезапуск редактора. Вне редактора: `nvim -l nvim_forge/scripts/prepare-plugins.lua`; можно явно задать каталог Lazy. После подтверждённого upstream исправления: отменить только известный патч CLI `--revert`, обновить pin и удалить декларацию/build guard в отдельном шаге с тем же регрессом. До этого обычный `Lazy update` не двигает закреплённую версию Neogit.
