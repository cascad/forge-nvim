## Purpose

Подсветка вхождений слова сохраняет отзывчивость редактора при необычных
размерах текста и обычные навигационные действия на всех целевых ОС.

## ADDED Requirements

### Requirement: IDE-HL-1 Подсветка с ограничением размера слова
В текстовых буферах с включённой подсветкой редактор SHALL пропускать
подсветку вхождений слова длиннее 4096 UTF-8 bytes,
сохраняя открытие, движение, редактирование и сохранение файла. Для слов до
4096 bytes SHALL сохраняться подсветка и Alt+n/Alt+p; размер строки сам по
себе не отключает эту возможность. Правило SHALL действовать и после
переключения в режим больших файлов (более 5000 строк).
Существующие исключения типов файлов и внешних Rust буферов сохраняются.
Платформы: все
Проверка: tests/e2e/reference-highlighting.test.lua (реальный UI, запись и переходы)

#### Scenario: Очень длинное слово
- **WHEN** пользователь открывает слово 512 КиБ и перемещает курсор внутри
- **THEN** редактор не показывает E339/обязательный prompt и принимает редактирование/сохранение
- **AND** переход на обычное слово возобновляет подсветку и навигацию

#### Scenario: Граница UTF-8 bytes
- **WHEN** размер текущего Unicode слова равен 4096 либо 4097 bytes
- **THEN** первое слово получает подсветку/переходы, второе пропускается без ошибки

#### Scenario: Большой файл
- **WHEN** файл содержит более 5000 строк, в том числе слово 512 КиБ
- **THEN** длинное слово не блокирует редактор, на обычных словах переходы работают

#### Scenario: Длинная строка с короткими словами
- **WHEN** строка длиннее 512 КиБ содержит два коротких Unicode вхождения
- **THEN** оба вхождения подсвечиваются, Alt+n/Alt+p переходят между ними
