# Proposal

## Why

Логику `wezterm.lua` переписывать не нужно: §41, §42, `phys:` и защита копирования выстраданы. Хрупкость в устройстве файла.

- Сейчас файл — 786 строк, из них 318 строк комментариев.
- Привязки попадают в `config.keys` тремя способами: литерал, `table.insert` и помощник `map()`, примерно из десяти мест. Таблицы режимов собираются вперемешку с ними.
- ОС проверяется в девяти местах (`is_windows`). Привязки только для macOS лежат в трёх местах файла.
- Колбэки написаны прямо в выражениях, и внешний мир (`os.getenv`, `home_dir`, `io.open`) читается в разных частях файла.
- Знания записаны прозой, и часть прозы уже неверна: 14 расхождений комментариев с кодом разбирает `sync-docs-with-baseline`.

Чтобы ответить на вопросы «что перехватывает терминал», «чем Mac отличается от Windows», «где код требования WT-CLIP-2», сегодня нужно прочитать весь файл.

Переделывать файл безопасно станет, когда `add-wezterm-spec-checks` даст проверки по ID и снимки `show-keys` и конфигурации. Тогда «поведение не изменилось» проверяется механически: эталоны побайтно те же.

## What Changes

Поведение не меняется: ни привязки, ни настройки, ни события. Файл остаётся один и лежит там же, в корне репо (WT-LOAD-1), подключение на всех ОС прежнее.

Перестройка идёт внутри `wezterm.lua` мелкими шагами, каждый отдельным коммитом. После каждого шага `nvim -l tests/run.lua` зелёный, эталоны `tests/wezterm/golden/*` не изменились, `--update-golden` не применяется. Шаги:

- **Факты о платформе в одном месте.** Только в этой секции читаются `target_triple`, `home_dir`, `os.getenv` и PATH. Остальной код получает готовую таблицу.
- **Колбэки — именованные функции с явными входами:**
  - копирование;
  - размер шрифта;
  - сохранение и восстановление размера окна;
  - готовый лэйаут;
  - запросы;
  - выгрузка истории в nvim;
  - бейдж.
- **Одна декларативная таблица привязок.** Это записи для `config.keys` и таблиц `windows` и `resize_pane`, платформенные различия пометкой в записи. Семейства (вкладки 1…9, шрифтовые сочетания) строятся генераторами в ту же таблицу. `config.keys` присваивается в одном месте, одним сборщиком. `copy_mode` и `search_mode` остаются встроенными таблицами WezTerm с переводом на `phys:` и явными записями-заменами.
- **Теги `-- spec: WT-XXX-n`** у каждой записи привязки и у каждой группы настроек. Trace из `add-wezterm-spec-checks` проверяет, что ID существуют, и что у записей таблицы привязок тег есть.
- **Комментарии.** Обоснование или история, которые уже есть в спеке или FIXLOG, заменяются ссылкой на ID или §. Знание, которого больше нигде нет, остаётся в комментарии.

Не входит:
- разбиение на модули — оно меняет WT-LOAD-1/3/4/13, значит, это отдельный change с delta (см. design);
- исправления поведения;
- самопроверка конфига во время работы.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет. Требования не меняются, delta-спек нет, в `.openspec.yaml` стоит `skip_specs: true`.

## Impact

- **Правится только** `wezterm.lua`. Тесты и эталоны не меняются. Исключение — trace в `tests/trace.test.lua`: он получает проверку «у каждой записи таблицы привязок есть тег `-- spec:`».
- **Зависит от** `add-wezterm-spec-checks`: применить его первым, снимки и проверки по ID должны быть зелёными.
- **Порядок относительно других changes, правящих `wezterm.lua`:** `fix-windows-mode-modality`, `change-search-enter-accept`, `fix-copy-clobbers-clipboard`, `resolve-key-ownership-conflicts`, `fix-window-state-new-windows`, `fix-ui-robustness`, `sync-docs-with-baseline` (комментарии). Их задачи ссылаются на нынешнее устройство файла (`copy_selection_or`, `to_phys_binding`, `map()`). Поэтому перестройка идёт после них, когда они применены. Как быть, если какой-то из них отложен надолго, — в design.
- **Установщики, docs, README, спеки и FIXLOG не меняются**, поведение то же.
- **После:**
  - ответ на вопрос «что перехватывает терминал» — одна таблица;
  - «чем Mac отличается» — `grep 'os = "macos"'`;
  - «где код требования» — `grep 'spec: WT-CLIP-2'`.
