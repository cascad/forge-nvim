# Design

## Context

Есть общий ide.state с одним компонентом на слот; Aerial/Edgy уже установлены.
Debug-пилот добавил ide.controls с overlay zoom того же буфера. Aerial имеет
собственные keymaps/события, и простой FileType hook может быть ими перезаписан.

## Goals / Non-Goals

**Goals:** один Outline-модуль, совместимые клавиши, настоящий пользовательский
путь без мыши, общий код Windows/macOS/Ubuntu, постоянный E2E.

**Non-Goals:** все остальные панели, собственный парсер/LSP, перестройка слотов
для одновременного Explorer+Outline, GUI/физическая раскладка клавиатуры,
закрытие исходной Mac startup проблемы, изменение версий зависимостей.

## Decisions

- Aerial настраивается только в plugins/outline.lua. Сохраняются ограничения
  размера файлов, глобальное отслеживание активного файла и переходы { / }.
  LSP предпочтителен; Treesitter — fallback. autojump выключен: j/k только
  выбирают строку, Enter подтверждает. Нативные h/l/Enter не переизобретаются.
- Старые toggle используют ide.toggle; новое Space w a использует ide.show.
  Обработчик восстанавливает overlay перед переходом. Space w o/ws/wv заняты
  прежними командами, их смысл не меняется.
- Общие controls получают descriptor Outline; буферные клавиши задаются после
  установки Aerial keymaps. Помощь учитывает тип панели. Overlay обязан
  возвращать исходный контекст перед нативным переходом, если backend этого
  требует; проверяется через Enter из zoom, а не только API открытия окна.
- E2E использует настоящий Aerial и доступный Treesitter parser с fixture,
  а не подменяет documentSymbol. Все действия — nvim_input; чтение API
  используется для ожиданий/проверки. На исходном конфиге сохраняется red.

## Risks / Trade-offs

- Асинхронное извлечение символов: ожидание backend и содержимого вместо sleep.
- Аerial меняет собственные окна; проверять overlay Enter и внешнее закрытие.
- Без LSP/парсера символов не будет; открытие не должно загружать инструменты.
- Windows/Ubuntu доступны здесь; macOS и физические клавиши остаются долгом.

## Уточнение по найденному регрессу

Полный Windows прогон сохранил ERROR Neo-tree follow: окно уже новое,
state.tree ещё использует удалённый буфер. Штатный window_exists проверяет
state.bufnr, а NuiTree:get_node ищет окно tree.bufnr. Интеграция использует
события neo_tree_window_after_open / after_render, удаляя устаревшую ссылку
на tree с переносом раскрытий через одноразовые default_expanded_nodes.
Функции и таймеры зависимостей не патчатся, follow остаётся включённым.
Дополнительно hide закрывает видимый компонент через registry, если его
открыла штатная команда backend вне состояния менеджера. Это сохраняет q
после AerialOpen; отдельный E2E сначала воспроизвёл оставшееся окно.
Нагрузочный Windows прогон дополнительно сохранил позднее повторное открытие
Explorer после смены слота на Outline: pending navigate завершает render после
close. after_render сверяет актуальный слот и закрывает позднее окно, если
менеджер уже выбрал компонент другого backend. Закрытие происходит после
render, чтобы не инвалидировать состояние в середине создания окна.
E2E наблюдает ссылку на закрытый tree-буфер на реальном after_open, не меняя
backend; так редкая гонка выявляется и на машине, где таймер не успел упасть.
