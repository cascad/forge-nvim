# Proposal

## Why

`nvim_forge/scripts/install-macos.sh` расходится с собственными обещаниями: в шапке («повторный запуск ничего не переустанавливает… чинит то, что разъехалось»), в FIXLOG §43 и в README. Так показала сверка базовой линии. Ниже баги по требованиям: где в коде и как воспроизвести (пробы — в scratchpad верификации, WSL-песочница).

- **MAC-INST-6 (divergence 1).** `install-macos.sh:176-180` передаёт одному `ls` оба шаблона: `~/Library/Fonts/CaskaydiaCoveNerdFont*` и `/Library/Fonts/CaskaydiaCoveNerdFont*`. Поэтому шрифт считается установленным, только если он лежит в обоих каталогах. Шрифт, поставленный руками в один каталог, не распознаётся. Скрипт каждый раз зовёт cask, и, по комментарию в коде, cask падает на конфликте файлов, давая предупреждение. Повтор: HOME с `~/Library/Fonts/CaskaydiaCoveNerdFont-Regular.ttf` и пустым вторым каталогом — `ls` возвращает ненулевой код.
- **MAC-INST-5 (divergence 5).** `:185-187`: с `FORGE_NVIM_WITH_LANGUAGES=1` условие «нет `cargo` в PATH» после `rustup-init --no-modify-path` остаётся истинным, и каждый повторный прогон ставит Rust заново.
- **MAC-INST-3 (divergence 6).** `:610-615`: на маке без Xcode Command Line Tools `command -v git` находит системную заглушку `/usr/bin/git`. `git clone` вызывает системный диалог и падает, а подсказка скрипта про `xcode-select --install` не выводится. Это вывод по устройству macOS, на Mac не проверено.
- **WT-LOAD-7 (divergence 7).** `:374-377`: профиль, где уже есть блок forge-nvim, пропускается целиком. Присваивание `WEZTERM_CONFIG_FILE`, дописанное после блока, не нейтрализуется (проба P3).
- **WT-LOAD-8 (divergence 8).** `:324-340`, `:444-448`: проверка plist текстовая. Шаг объявляется сломанным (код 1), даже если plist переменную только снимает, задаёт её лишь своему процессу (`EnvironmentVariables`) или ведёт в репо через `~` или симлинк (проба V8). Из нескольких таких plist называется только последний. FIXLOG §43, комментарий и сообщение обещают другое: называть LaunchAgent, который выставляет переменную при входе.
- **WT-LOAD-12 (divergence 9).** `:471-482`: подсказка «закрой WezTerm (Cmd+Q)» ложно выводится в панели WezTerm, загрузившего `~/.wezterm.lua` → репо: загруженным файлом считается `$WEZTERM_CONFIG_DIR/wezterm.lua` (проба P12).
- **MAC-INST-10 (divergence 2).** Установка в `~/.config/nvim` без `FORGE_NVIM_USE_LOCAL_SOURCE=1` всегда проваливается. Прежний конфиг уходит в бэкап, в каталог клонируется весь монорепо (в его корне нет `init.lua`), и скрипт выходит с кодом 1 (`:548-578`, проба P2). Отказы «не из чекаута» и «нет git» тоже происходят уже после бэкапа.
- **MAC-INST-13 (divergence 3).** `:45`: каталог установки берётся из `XDG_CONFIG_HOME` шелла. Из терминала nvim_forge конфиг ставится внутрь репо, в `<репо>/nvim` (проба V4).
- **MAC-INST-11 (divergence 4).** `:531-548`: повторная установка в `~/.config/nvim` из локального источника каждый раз создаёт новый бэкап (проба P1).
- **Шапка скрипта (divergences 13, 14).** Шапка говорит, что `brew shellenv` пишется в `~/.zprofile`; код пишет в `~/.bash_profile` для bash и в `${ZDOTDIR:-~}/.zprofile` для остальных шеллов. В списке флагов нет `FORGE_NVIM_REPO`, `FORGE_NVIM_BRANCH` и `FORGE_NVIM_USE_LOCAL_SOURCE`.

Режим установки в `~/.config/nvim` владелец решил 2026-09-27 (Q12 = B): путь установки становится симлинком на `nvim_forge/` чекаута, как `wezterm.lua` (WT-LOAD-4). Одна конструкция закрывает divergences 2, 3 и 4: копии, которая может разъехаться, больше нет, а «уже ведёт туда» — это и есть проверка повторного запуска. Отвергнутые варианты и следствия решения — design.md, Decisions 9–14.

## What Changes

- Шрифт считается установленным, если файлы `CaskaydiaCoveNerdFont*` есть хотя бы в одном из каталогов `~/Library/Fonts` и `/Library/Fonts`. Повторный запуск не зовёт cask и не выводит предупреждение.
- Rust считается установленным, если есть `cargo` в PATH или исполняемый `~/.cargo/bin/cargo`. Во втором случае `rustup-init` не запускается, а установщик подсказывает добавить `~/.cargo/bin` в PATH.
- При `curl | bash` git считается доступным, только если это не заглушка macOS без CLT. Иначе — прежняя подсказка `xcode-select --install` и код 1 до любых действий.
- В профилях шелла упоминание `WEZTERM_CONFIG_FILE` ищется после последнего блока forge-nvim. Если оно есть, в конец дописывается ещё один блок; свои строки пользователя по-прежнему не трогаются.
- По имени называются только plist, которые при входе выполняют `launchctl setenv WEZTERM_CONFIG_FILE <путь>` с путём, не ведущим в репо после раскрытия `~` и симлинков. За один прогон называются все такие plist.
- Подсказка о перезапуске определяет загруженный файл по `WEZTERM_CONFIG_FILE` панели или по кандидатам в `WEZTERM_CONFIG_DIR` (`wezterm.lua`, `.wezterm.lua`). WezTerm, загрузивший файл репо, подсказку не получает.
- **Режим установки в `~/.config/nvim` — симлинк (решение владельца, Q12 = B).** Путь установки (`FORGE_NVIM_INSTALL_DIR`, по умолчанию `~/.config/nvim`) становится симлинком на `<чекаут>/nvim_forge`. Чекаут — тот, из которого запущен скрипт, или клон в `FORGE_NVIM_SRC`. В путь установки больше ничего не клонируется и не копируется.
  - Путь, уже ведущий туда, не трогается, поэтому повторный запуск не создаёт бэкапов (MAC-INST-11).
  - Занятый чем-то другим (каталог, файл, битый симлинк, симлинк на другой чекаут) уходит в бэкап целиком.
  - Все отказы режима — до первого бэкапа: отказы бутстрапа до шага зависимостей, остальные сразу после него, до шага WezTerm. При отказе ни путь установки, ни пути конфига WezTerm не тронуты. Отказывают: `FORGE_NVIM_USE_LOCAL_SOURCE=1` вне чекаута, нет git вне чекаута, нет `nvim_forge/init.lua`, путь установки и чекаут вложены друг в друга, нет `nvim`.
  - Запуск из файла вне чекаута получает чекаут тем же бутстрапом, что `curl | bash` (MAC-INST-3), и продолжает в режиме установки.
  - `XDG_CONFIG_HOME`, ведущий в чекаут (терминал nvim_forge), не учитывается — путь `~/.config/nvim`.
  - Плагины приводятся к `lazy-lock.json` чекаута: `Lazy! restore` вместо `Lazy! sync`. Установщик не переписывает отслеживаемые файлы чекаута. `nvim` при этом читает именно путь установки, а не конфиг, унаследованный из терминала nvim_forge.
  - `FORGE_NVIM_USE_LOCAL_SOURCE=1` из чекаута ничего не меняет; вне чекаута — отказ до любых действий вместо бутстрапа.
  - **BREAKING** для прежних установок копией: следующий прогон режима уносит копию в бэкап и ставит симлинк. Конфиг теперь живёт в чекауте, и удалённый чекаут оставляет `nvim` без конфига.
- Повторный запуск (MAC-INST-11) больше не имеет исключений: ни для шрифта и Rust, ни для установки в `~/.config/nvim`.
- Шапка `install-macos.sh`: профиль для `brew shellenv` (divergence 13), полный список флагов с умолчаниями (divergence 14) и описание режима `~/.config/nvim` как симлинка.
- В `tests/install-macos.scenarios.sh` добавляются сценарии на каждое исправление: заглушки `brew`, `xcode-select`, `plutil`, `nvim`, прогон под bash 5.2 и bash 3.2.57. Что нельзя проверить в песочнице, проверяется вручную на Mac, результат записывается.
- Обновляются документы, описывающие установщик: nvim_forge/README.md, README.md, docs/WEZTERM.md §9, комментарий-шапка `nvim_forge.sh`, шапка `install-macos.sh`. Дописывается запись FIXLOG со строками `Спека: <ID> (MODIFIED)`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `macos-install`:
  - MAC-INST-3 — заглушка git без CLT; бутстрап и для запуска из файла вне чекаута в режиме установки;
  - MAC-INST-5 — Rust вне PATH;
  - MAC-INST-6 — шрифт в одном каталоге;
  - MAC-INST-10 — режим `~/.config/nvim` становится симлинком, все отказы до бэкапа;
  - MAC-INST-11 — повтор без исключений и без бэкапов в режиме установки;
  - MAC-INST-13 — `XDG_CONFIG_HOME` в чекауте, смысл флагов режима установки.

  MAC-INST-2, MAC-INST-8 и MAC-INST-9 не меняются: их текст верен и для симлинка.
- `wezterm-config-loading`: WT-LOAD-7 (переменная после блока), WT-LOAD-8 (какой LaunchAgent считается перекрытием), WT-LOAD-12 (когда выводится подсказка о перезапуске).

## Impact

- Код: `nvim_forge/scripts/install-macos.sh` — шаги зависимостей и WezTerm, бутстрап (и для файла вне чекаута), установка конфига (симлинк вместо копии и клона), синхронизация плагинов, шапка.
- Тесты: `tests/install-macos.scenarios.sh` — новые сценарии и заглушки. Внешних зависимостей не прибавляется: нужны те же bash, git и python3.
- Документы: nvim_forge/README.md, README.md, docs/WEZTERM.md §9, шапка `nvim_forge.sh`; nvim_forge/FIXLOG.md.
- Проверка на Mac вручную: заглушка git без CLT, поведение cask шрифта, разбор plist через `plutil` (двоичный формат), `nvim` через симлинк `~/.config/nvim` и чистый `git status` чекаута после установки. Mac удалённый, песочница этого не покрывает.
- Соседние changes:
  - `add-linux-installer-parity` — общий файл функций подключения. Режим `~/.config/nvim` в `install-linux.sh` остаётся прежним (клон всего монорепо или копия); симлинк там — отдельный follow-up change.
  - `sync-docs-with-baseline` — тексты документов вне этих исправлений.
