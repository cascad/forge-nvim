## MODIFIED Requirements

### Requirement: WT-LOAD-7 macOS: профили шелла получают дописанный блок unset
Для каждого существующего профиля шелла из фиксированного списка, где `WEZTERM_CONFIG_FILE` упоминается вне комментария после последнего блока forge-nvim (или блока ещё нет), `install-macos.sh` SHALL дописать в конец помеченный блок, снимающий переменную, и MUST NOT изменять ни одной существующей строки файла.
Платформы: macos
История: FIXLOG §43
Проверка: tests/install-macos.scenarios.sh (S3, S12, S16, S20)

#### Scenario: какие файлы проверяются и что дописывается
- **WHEN** установщик проверяет профили
- **THEN** список: `~/.zshenv`; `$ZDOTDIR/.zshenv`, `.zprofile`, `.zshrc`, `.zlogin` (ZDOTDIR спрашивается у самого `/bin/zsh`); `~/.zprofile`, `~/.zshrc`, `~/.zlogin`, `~/.bash_profile`, `~/.bashrc`, `~/.profile`, `~/.config/fish/config.fish`
- **AND** блок — пустая строка, `# >>> forge-nvim: WezTerm config is the symlink ~/.config/wezterm/wezterm.lua (install-macos.sh) >>>`, `unset WEZTERM_CONFIG_FILE`, `# <<< forge-nvim <<<`

#### Scenario: export в ~/.zshrc
- **GIVEN** `~/.zshrc` содержит `export WEZTERM_CONFIG_FILE=…` среди своих строк
- **WHEN** запускается установщик
- **THEN** прежнее содержимое остаётся нетронутым префиксом файла, в конец дописан блок
- **AND** в выводе `<файл> задаёт WEZTERM_CONFIG_FILE — в конец дописан 'unset WEZTERM_CONFIG_FILE' (свои строки не тронуты)`
- **AND** после `source` профиля переменной нет

#### Scenario: любое упоминание вне комментария
- **GIVEN** профиль не присваивает переменную, а только упоминает её (например, `echo "$WEZTERM_CONFIG_FILE"`) или присваивает ей путь к файлу репо
- **WHEN** запускается установщик
- **THEN** блок всё равно дописывается

#### Scenario: сложные строки остаются синтаксически целыми
- **GIVEN** профиль с `…; fi` в строке присваивания, продолжением строки `\`, несколькими присваиваниями в одной строке и без перевода строки в конце файла
- **WHEN** установщик дописывает блок
- **THEN** файл по-прежнему разбирается `bash -n` и `zsh -n`
- **AND** остальные переменные из тех же строк (например, `EDITOR`) после `source` на месте, `WEZTERM_CONFIG_FILE` снята

#### Scenario: профиль — симлинк
- **GIVEN** `~/.bashrc` — симлинк на файл в каталоге dotfiles
- **WHEN** установщик дописывает блок
- **THEN** блок попадает в целевой файл, `~/.bashrc` остаётся симлинком
- **AND** один и тот же файл, достижимый под двумя именами, обрабатывается один раз

#### Scenario: упоминание только в комментарии
- **GIVEN** в профиле `WEZTERM_CONFIG_FILE` встречается только после `#` в той же строке
- **WHEN** запускается установщик
- **THEN** профиль не трогается

#### Scenario: fish
- **GIVEN** `~/.config/fish/config.fish` задаёт переменную
- **WHEN** запускается установщик
- **THEN** в блоке `set -e WEZTERM_CONFIG_FILE`, помечающие строки те же

#### Scenario: профиль недоступен для записи
- **GIVEN** профиль задаёт переменную и доступен только для чтения
- **WHEN** запускается установщик
- **THEN** в выводе `!! <файл> задаёт WEZTERM_CONFIG_FILE, но недоступен для записи — допиши в конец: unset WEZTERM_CONFIG_FILE` (для fish — `set -e WEZTERM_CONFIG_FILE`), файл не изменён
- **AND** шаг WezTerm от этого не считается сломанным (WezTerm из Dock профили не читает)

#### Scenario: повторный запуск не дублирует блок
- **GIVEN** в профиле есть блок forge-nvim, после последнего такого блока переменная не упоминается
- **WHEN** установщик запускается снова
- **THEN** профиль не меняется

#### Scenario: присваивание, добавленное после блока, не нейтрализуется
- **GIVEN** в профиле уже есть блок forge-nvim, а после него позже дописан новый `export WEZTERM_CONFIG_FILE=…` (прежде такой профиль пропускался целиком)
- **WHEN** установщик запускается снова
- **THEN** присваивание нейтрализуется: в конец дописан ещё один такой же блок, прежние строки не тронуты, после `source` профиля переменной нет
- **AND** следующий запуск профиль уже не меняет

#### Scenario: что блок не отменяет
- **GIVEN** переменная задаётся в файле вне списка (например, подключаемом через `source` или в `~/.config/fish/conf.d/`) или строкой `launchctl setenv WEZTERM_CONFIG_FILE …` в профиле
- **WHEN** запускается установщик
- **THEN** файл вне списка не проверяется; профиль со строкой `launchctl setenv` получает блок, но launchd-переменную, которую эта строка выставит при следующем старте шелла, блок не снимает

### Requirement: WT-LOAD-8 macOS: LaunchAgent, выставляющий переменную, называется по имени
`install-macos.sh` SHALL называть в stderr каждый plist из `~/Library/LaunchAgents` и `/Library/LaunchAgents` (XML или двоичный), который при входе в систему выставляет `WEZTERM_CONFIG_FILE` в окружение launchd — его команда выполняет `launchctl setenv WEZTERM_CONFIG_FILE <путь>` отдельными аргументами или строкой для шелла, — со значением, не ведущим в `wezterm.lua` репо. Путь сравнивается после раскрытия симлинков; `~` и `$HOME` раскрываются, только если команда выполняется шеллом. Сообщение — `!! <plist> выставляет WEZTERM_CONFIG_FILE при каждом входе в систему — убери из него эту переменную`, сам plist не изменяется, и при хотя бы одном таком plist скрипт MUST считать шаг WezTerm сломанным (код возврата 1, MAC-INST-9).
Платформы: macos
История: FIXLOG §43
Проверка: tests/install-macos.scenarios.sh (S13, S21); двоичный plist — вручную на macOS

#### Scenario: plist с чужим путём
- **GIVEN** `~/Library/LaunchAgents/env.plist` при входе выполняет `launchctl setenv WEZTERM_CONFIG_FILE /elsewhere.lua`
- **WHEN** запускается установщик
- **THEN** plist назван в stderr и не изменён, код возврата 1

#### Scenario: plist с путём репо
- **GIVEN** plist выставляет переменную с путём к `wezterm.lua` репо — абсолютным, через симлинк или, в команде для шелла, через `~`
- **WHEN** запускается установщик
- **THEN** перекрытием он не считается, код возврата 0

#### Scenario: проверка текстовая
- **GIVEN** plist упоминает переменную, но не выставляет её в launchd: только снимает (`launchctl unsetenv WEZTERM_CONFIG_FILE`), задаёт её лишь собственному процессу (`EnvironmentVariables`) или упоминает иначе
- **WHEN** запускается установщик
- **THEN** проверка больше не текстовая: plist не назван, шаг от него не ломается

#### Scenario: setenv в команде для шелла
- **GIVEN** команда plist — `sh -c "… launchctl setenv WEZTERM_CONFIG_FILE /elsewhere.lua …"`
- **WHEN** запускается установщик
- **THEN** plist назван, код возврата 1

#### Scenario: двоичный plist
- **GIVEN** plist с той же командой сохранён в двоичном формате
- **WHEN** запускается установщик
- **THEN** решение то же, что для XML-plist с таким содержимым

#### Scenario: несколько таких plist
- **GIVEN** переменную с чужими путями выставляют два plist
- **WHEN** запускается установщик
- **THEN** за один прогон названы оба, код возврата 1

### Requirement: WT-LOAD-12 macOS: подсказка о перезапуске WezTerm
При успешном шаге WezTerm и запущенном `wezterm-gui` `install-macos.sh` SHALL вывести `WezTerm запущен со старым конфигом — закрой его (Cmd+Q) и открой заново, один раз` только тогда, когда запущенный WezTerm грузит не файл репо: до правок WezTerm из Dock загрузил бы не файл репо, либо установщик запущен из панели WezTerm, загрузившей другой файл или встроенные дефолты. WezTerm, загрузивший файл репо через симлинк в каталоге конфига, через `~/.wezterm.lua` или через переменную `WEZTERM_CONFIG_FILE` (видимую в панели или заданную в launchd), MUST NOT получать подсказку.
Платформы: macos
История: FIXLOG §43
Проверка: tests/install-macos.scenarios.sh (S3: restart hint; rerun: no restart hint; S22)

#### Scenario: первая установка при запущенном WezTerm
- **GIVEN** WezTerm запущен, до установки из Dock грузился не конфиг репо (или дефолты)
- **WHEN** установщик отработал успешно
- **THEN** выводится подсказка про Cmd+Q

#### Scenario: повторный запуск
- **GIVEN** предыдущий запуск уже подключил конфиг
- **WHEN** установщик запускается снова при запущенном WezTerm — из Dock-окружения или из панели, где `WEZTERM_CONFIG_DIR` = каталог симлинка
- **THEN** подсказки нет

#### Scenario: WezTerm не запущен или шаг не успешен
- **WHEN** `wezterm-gui` не запущен, шаг WezTerm сломан или пропущен
- **THEN** подсказки нет

#### Scenario: панель WezTerm на встроенных дефолтах
- **GIVEN** установщик запущен из панели WezTerm, у которой нет `WEZTERM_CONFIG_DIR` (этот WezTerm не нашёл конфиг)
- **WHEN** установщик отработал успешно
- **THEN** подсказка выводится, даже если для Dock всё уже было подключено

#### Scenario: панель WezTerm, загрузившего ~/.wezterm.lua
- **GIVEN** `~/.wezterm.lua` — симлинк на файл репо, запущенный WezTerm загрузил именно его, установщик запущен из его панели (`WEZTERM_CONFIG_DIR` = домашний каталог)
- **WHEN** установщик отработал успешно
- **THEN** подсказки нет

#### Scenario: панель, где видна WEZTERM_CONFIG_FILE
- **GIVEN** установщик запущен из панели WezTerm, и в её окружении `WEZTERM_CONFIG_FILE` указывает на файл, ведущий в репо (под любым именем)
- **WHEN** установщик отработал успешно
- **THEN** подсказки нет
- **AND** если та же переменная ведёт не в репо, подсказка выводится

#### Scenario: загруженный файл из панели не виден
- **GIVEN** в панели `WEZTERM_CONFIG_FILE` снята профилем (WT-LOAD-7), а WezTerm загрузил файл репо под другим именем через `--config-file` или через переменную шелла; в `WEZTERM_CONFIG_DIR` нет ни `wezterm.lua`, ни `.wezterm.lua`, ведущих в репо, и launchd такой путь не задаёт
- **WHEN** установщик отработал успешно
- **THEN** подсказка выводится: из панели не видно, какой файл загружен
