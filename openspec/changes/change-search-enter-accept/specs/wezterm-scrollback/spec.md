## MODIFIED Requirements

### Requirement: WT-SCROLL-10 Search mode: Enter
В search mode Enter SHALL принимать введённый шаблон и переводить панель из search mode в copy mode с курсором на текущем совпадении, как Enter после `/` в vim; после этого `n` и `N` MUST переходить по совпадениям этого шаблона, а не дописываться в него.
Платформы: все
История: FIXLOG «WezTerm: Enter в search mode принимает шаблон»
Проверка: tests/wezterm/scrollback.test.lua (Enter принимает шаблон, ↑ остаётся переходом вверх, n/N в copy mode) | tests/wezterm/snapshot.test.lua (show-keys: Enter → AcceptPattern) | вручную (windows, macos; результат — в той же записи FIXLOG)

Совпадение, на котором стоит курсор, остаётся выделением: `y` копирует его (WT-SCROLL-7), движения расширяют выделение от его начала. Строка с шаблоном остаётся видна внизу панели, индикатор меняется с SEARCH на COPY. Так же Enter работает в поиске, открытом клавишей `f` из режима WINDOWS: панель переходит в copy mode, хотя до поиска его не было. Без совпадений Enter тоже переводит панель в copy mode; курсор остаётся там, где был, выделения нет. К совпадению выше в search mode ведут ↑ и Ctrl+P (WT-SCROLL-9). Ctrl+Shift+X переводит из поиска в copy mode так же, как Enter (WT-SCROLL-11).

#### Scenario: Enter после набора шаблона
- **GIVEN** панель в copy mode, нажата `/`, набрано `error`, найдено несколько вхождений, выделено самое нижнее
- **WHEN** нажат Enter
- **THEN** индикатор COPY, курсор copy mode на самом нижнем вхождении, оно выделено
- **AND** строка с шаблоном `error` видна внизу панели

#### Scenario: Enter у самого верхнего совпадения
- **GIVEN** search mode, клавишей ↑ выделено самое верхнее совпадение
- **WHEN** нажат Enter
- **THEN** включён copy mode, курсор на самом верхнем совпадении
- **AND** перехода по кругу к самому нижнему нет: Enter больше не двигает выделение

#### Scenario: После Enter n и N ходят по совпадениям
- **GIVEN** search mode с шаблоном `err`, в истории три вхождения, нажат Enter
- **WHEN** нажата `N`, затем `n`
- **THEN** курсор переходит к вхождению выше, затем обратно
- **AND** шаблон остаётся `err`: буквы в него больше не дописываются

#### Scenario: После Enter n — это буква
- **GIVEN** search mode с шаблоном `err`, нажат Enter, панель в copy mode
- **WHEN** снова нажата `/`, затем `n`
- **THEN** `/` возвращает к вводу того же шаблона (WT-SCROLL-8), и `n` дописывается в него: шаблон `errn`
- **AND** буквой `n` становится только в строке ввода; сразу после Enter она переходит по совпадениям (сценарий выше)

#### Scenario: Поиск из режима WINDOWS
- **GIVEN** включён режим WINDOWS, нажата `f`, набран шаблон, выделено совпадение, в буфере текст «A»
- **WHEN** нажат Enter, затем `y`
- **THEN** после Enter индикатор COPY, после `y` в буфере текст совпадения вместо «A»
- **AND** copy mode выключен

#### Scenario: Enter без совпадений
- **GIVEN** search mode, совпадений нет, в буфере текст «A»
- **WHEN** нажат Enter
- **THEN** включён copy mode, курсор на прежнем месте, выделения нет
- **AND** в буфере по-прежнему «A»

#### Scenario: ↑ и Ctrl+P остаются переходом вверх
- **GIVEN** search mode, выделено самое нижнее из нескольких совпадений
- **WHEN** нажата ↑ или Ctrl+P
- **THEN** выделено совпадение выше, search mode остаётся, строка ввода активна
