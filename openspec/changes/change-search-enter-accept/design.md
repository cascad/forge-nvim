# Design

## Context

Мотивация — в proposal.md (Why). Таблицы copy_mode и search_mode конфиг не пишет руками. Он берёт их из `wezterm.gui.default_key_tables()` и механически переводит символьные клавиши на `phys:` (`wezterm.lua`, `to_phys_binding`, WT-KEYS-2). Получение таблиц обёрнуто в `pcall`: вне GUI (mux-сервер) их может не быть, и тогда конфиг остаётся на встроенных. После перевода в copy_mode дописываются `/`, `n`, `N` (WT-SCROLL-8). Search_mode сейчас не правится вовсе.

Как устроено в WezTerm 20240203 (`wezterm-gui/src/overlay/copy.rs`). Copy mode и search mode — один и тот же оверлей. Режим определяется флагом `editing_search`, от него зависит, какая таблица активна на оверлее: `search_mode` или `copy_mode`. Действие `CopyMode("AcceptPattern")` сбрасывает флаг и переключает таблицу на `copy_mode`, больше ничего не трогает. Курсор и выделение уже стоят на текущем совпадении: их выставляет переход к совпадению при поиске. Поэтому одной привязки хватает, чтобы получить поведение WT-SCROLL-10 целиком.

Если в таблице повторяется пара (клавиша, модификаторы), WezTerm молча оставляет последнюю запись (research: мутант m3).

## Goals / Non-Goals

**Goals:**
- В таблице search_mode ровно одна запись Enter без модификаторов, и это `CopyMode("AcceptPattern")`.
- Проверка этого инварианта — командой, без GUI (`tests/`).

**Non-Goals:**
- Esc в search mode (WT-SCROLL-11: закрывает поиск вместе с copy mode). Не меняется, вопрос владельцу — в Open Questions.
- PageUp и PageDown в search mode (WT-SCROLL-15: направление обратно подписям). Не меняются, вопрос — в Open Questions.
- `/`, `n`, `N` в copy mode (WT-SCROLL-8) и `y` (WT-SCROLL-7, change `fix-copy-clobbers-clipboard`).
- Режим WINDOWS поверх search mode (WT-WIN-21, change `fix-windows-mode-modality`).
- Переписывание docs/WEZTERM.md целиком (change `sync-docs-with-baseline`). Здесь сверяется только строка про Enter в разделе поиска.

## Decisions

**1. Заменить запись Enter в уже переведённой таблице, а не дописать новую.** После цикла перевода найти в `config.key_tables.search_mode` запись с `key = "Enter"` и `mods` `NONE` (или без `mods`) и заменить её действие на `act.CopyMode("AcceptPattern")`. Если такой записи нет, добавить её. Если нет самой таблицы (`pcall` не дал встроенных), ничего не делать: тогда WezTerm живёт на своих встроенных таблицах, как и сейчас.
- Альтернатива: дописать вторую запись Enter и положиться на «побеждает последняя». Отклонено. Это неявное поведение WezTerm: после любой перестановки кода побеждать может не та запись, а проверка «ровно одна запись Enter» перестаёт что-либо значить.
- Альтернатива: собрать search_mode целиком руками. Отклонено: это лишний код и расхождение со встроенной таблицей при обновлении WezTerm, ради одной клавиши.
- Если будущая версия WezTerm сама привяжет Enter к `AcceptPattern`, замена ничего не изменит.

**2. Enter с модификаторами не трогать.** Решение владельца касается Enter. Shift+Enter, Ctrl+Enter и прочие в search_mode не привязаны и остаются как есть.

**3. Проверка — по той таблице, которую видит WezTerm.** *Уточнено при реализации:* к этому моменту `add-wezterm-spec-checks` принёс общий тестовый слой (поддельный `wezterm`, эталоны show-keys через настоящий бинарник в `tests/wezterm/snapshot.test.lua`). Проверка живёт там: `scrollback.test.lua` проверяет привязку на подделке, эталон — итог в настоящем WezTerm; отдельный `tests/wezterm-keys.scenarios.sh` был бы второй обвязкой ради того же. Исходный план ниже сохранён для истории.

 Сценарий в `tests/wezterm-keys.scenarios.sh` сначала убеждается, что конфиг загрузился: `wezterm --config-file wezterm.lua ls-fonts`, в stderr нет `ERROR` (`show-keys` ошибок загрузки не показывает, см. CLAUDE.md). Потом он берёт `wezterm --config-file wezterm.lua show-keys --lua --key-table search_mode` и требует ровно одну строку с `key = 'Enter'`, и в ней `act.CopyMode 'AcceptPattern'`. Это проверяет итог (привязку после всех преобразований конфига), а не исходник. Поведение в GUI (индикатор, курсор, выделение) без GUI не проверить, поэтому оно проверяется вручную на Windows и macOS, результат пишется в FIXLOG.
- Альтернатива: юнит-тест на поддельном модуле `wezterm` (research, «fake wezterm module»). Отклонено для этого change: инфраструктуры такого теста в репо ещё нет, а снимок `show-keys` проверяет ровно то, что нужно, и уже работает на установленной 20240203.

## Risks / Trade-offs

- [Проверка `show-keys` смотрит только на текущую ОС] → Таблица search_mode собирается без ветвления по платформе, так что прогона на Windows достаточно. На macOS достаточно ручной проверки сценариев при следующем доступе к Mac.
- [Выделение совпадения после Enter выведено из исходника 20240203, в GUI не проверялось] → Ручная проверка сценариев WT-SCROLL-10 на Windows до записи FIXLOG. Если поведение разойдётся со спекой, change возвращается на уточнение, а не правится молча.
- [Название сценария «После Enter n — это буква» осталось от прежнего поведения: OpenSpec 1.13.2 не даёт убрать сценарий из MODIFIED-требования] → Сценарий описывает случай, где название верно (после Enter снова `/`), и ссылается на основной сценарий «После Enter n и N ходят по совпадениям».
- [На Mac может стоять не 20240203] → В 20240203 `AcceptPattern` есть (проверено по исходнику); для другой версии это покажет ручная проверка на Mac.

## Migration Plan

Миграции состояния нет. Правка вступает в силу при перечитывании конфига (WT-LOAD-14). Откат — вернуть одну привязку; сценарий в `tests/` при этом упадёт, и это ожидаемо.

## Open Questions

- Esc в search mode, открытом через `/` из copy mode, закрывает и copy mode (WT-SCROLL-11), не как в vim. Решение №3 касается только Enter. Если владелец захочет, чтобы Esc возвращал в copy mode, это отдельный change с delta к WT-SCROLL-11. Этот change от ответа не зависит: другая клавиша и другое требование, привязка Enter от этого не меняется.
- PageUp и PageDown в search mode работают обратно подписям (WT-SCROLL-15, upstream 20240203, в GUI не проверено). Поменять их местами в конфиге или оставить как в WezTerm — тоже отдельный change с delta к WT-SCROLL-15. От ответа этот change не зависит.
