## Context

Ветка копирования из `c` и `p` общая, в filesystem/lib/fs_actions.lua.
Тот же companion уже использует `plenary.async.uv` для удаления. Хуки до
создания, callbacks показа результата и обновления дерева предоставляет Neo-tree.

## Goals / Non-Goals

Цель — сохранить привычный сценарий копирования при ожидании медленного
диска и сообщать об ошибке с причиной ОС. В этой итерации проверяется путь
копирования. Создание, переименование, перемещение и проверка dirty buffers
при удалении остаются самостоятельными участками аудита.

## Decisions

Существующий companion делегирует копирование модулю fride. Проверка нового
имени асинхронна, диалог имени остаётся штатным. Обычные файлы копируются
с COPYFILE_EXCL, каталоги создаются с проверкой результата mkdir, ссылки
копируются как ссылки. Проверка реального родителя предотвращает копирование
дерева внутрь себя через ссылку. UI callbacks и события идут через scheduler.
Рекурсивная ошибка оставляет созданные элементы на диске, сообщает причину
и не выдаёт событие успешного копирования.

## Risks / Trade-offs

Проверяем новый файл в момент между выбором имени и копированием, переход
фокуса в код, сохранение другого файла и существующие сценарии Unicode.
Реальный запрос libuv в тесте временно отложен. Сам результат даёт файловая
система. Проверка на macOS входит в ручную приёмку.
