# Proposal

## Why

Спеки `openspec/specs/` (10 capability, 128 требований) сняты с кода 2026-09-27. Сейчас это базовая линия фазы 1: при расхождении прав код. Чтобы спека стала намерением владельца (фаза 2), её должен проверить владелец. Сверка базовой линии (`baseline_divergences.json` в этой папке) оставила то, что без него не закрыть:

- Девять утверждений выведены из исходника WezTerm 20240203 и в GUI ни разу не проверялись (divergences 28–34, 46, 47):
  - почти всё поведение клавиатуры и буфера обмена на macOS: kitty, путь через IME, F13 от Ctrl+[, Super без привязки, Cmd+C/Cmd+V;
  - запуск `nvim` из WezTerm.app, открытого из Dock;
  - значения WT-KBD-6 на английской раскладке;
  - Alt+Space и Alt+F4 на Windows.
- В открытых вопросах сверки есть пункты, которые тоже выведены из исходника и вживую не проверены:
  - метки `q` против клавиш режима WINDOWS;
  - подтверждение Cmd+Q;
  - OSC 52 и bracketed paste через ConPTY;
  - работает ли Claude Code на альтернативном экране;
  - перечитывание конфига при правке любого файла в корне репо;
  - и ещё около десятка.
- Семь особенностей поведения владелец ещё не подтвердил, и ни один другой change их не разбирает. Код так работает либо намеренно, либо по умолчанию WezTerm.
- Внутри базовой линии есть известное противоречие. По WT-WIN-16 `f` открывает поиск с пустым шаблоном. По WT-SCROLL-9 и по коду — с шаблоном, сохранённым для вкладки.

Если перейти в фазу 2 сейчас, непроверенные выводы станут намерением: агент начнёт «чинить» работающий код под ошибку спеки.

## What Changes

Поведение WezTerm и установщиков не меняется.

- **Ручные проверки по платформам.** Чек-листы `tests/manual/wezterm-windows.md` и `tests/manual/wezterm-macos.md`. В каждом пункте: ID требований, шаги, ожидаемое по спеке и отметка «проверено: дата, ОС, версия WezTerm, раскладка». Прогон — на обеих машинах.
- **Уточнение базовой линии по правилу фазы 1.** Правка прямо в `openspec/specs/`, до перехода. Правятся WT-WIN-16 и всё, в чём ручная проверка разошлась со спекой. У проверенных требований появляется строка `Проверка: вручную (…)`. Это исправление спеки под код, поведение не меняется.
- **Решения владельца по семи вопросам.** «Оставить» — спека становится намерением как есть. «Менять» — отдельный `/opsx:propose`. Вопросы:
  - готовый лэйаут `a` при повторном вызове снова делит панель (WT-PANE-9);
  - повторный запуск WezTerm из не-default воркспейса создаёт невидимое окно (WT-PANE-10);
  - Cmd+Q всегда спрашивает подтверждение (WT-PANE-8);
  - выгрузка `b` теряет пустые строки и оставляет на диске файл, где могут быть секреты (WT-SCROLL-13);
  - QuickSelect ищет в 1000 строках истории над экраном (WT-SCROLL-12);
  - на Windows конфиг перечитывается при правке любого файла в корне репо (WT-LOAD-14);
  - смена шрифта и перечитывание конфига выключают WINDOWS и RESIZE (WT-WIN-2).
- **Подтверждение владельцем** каждой из 10 capability.
- **Переход в фазу 2.** В `openspec/config.yaml` строка «ТЕКУЩАЯ ФАЗА: 2 «источник правды» (с <дата>)». Текст о фазе в `CLAUDE.md`. Запись в `nvim_forge/FIXLOG.md`.
- **BREAKING (для процесса, не для кода).** После перехода код, расходящийся со спекой, — баг, а README и docs выводятся из спек.
- **Отчёт сверки сохранён.** На номера divergences в `baseline_divergences.json` ссылаются все changes. Копия этого файла лежит в папке этого change, чтобы номера не повисли, когда очистится временный каталог.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет. Delta-спек нет, в `.openspec.yaml` стоит `skip_specs: true`. Уточнения базовой линии (WT-WIN-16 и расхождения, найденные ручной проверкой) делаются до перехода, по правилу фазы 1, прямо в `openspec/specs/`. Поведение они не меняют. Изменения поведения, которые выберет владелец, идут отдельными changes.

## Impact

- Новые файлы: `tests/manual/wezterm-windows.md`, `tests/manual/wezterm-macos.md`.
- `openspec/specs/*/spec.md` — только уточнения базовой линии.
- `openspec/config.yaml` (строка фазы), `CLAUDE.md` (фаза и раздел «Проверки»), `nvim_forge/FIXLOG.md` (новая запись).
- Не меняются: `wezterm.lua`, установщики, docs, README.
- **Соседние changes не блокируются.** Ручные пункты по требованиям, которые правят открытые changes, фиксируют текущее поведение и служат им воспроизведением. Это WT-KBD-6, WT-WIN-6/7/10, Cmd+C на Mac и WT-UI-4. Проверки установщика на Mac остаются в `fix-macos-installer`.
- **Риск.** Уточнение базовой линии может разойтись с MODIFIED-delta открытого change по тому же ID. Такие места сверяются до перехода.
- **Нужен Mac.** Проверки macOS требуют доступа владельца к Mac. Переход в фазу 2 ждёт их.
