# Design

## Context

В отличие от артефактов .tests/editor-e2e, большие private runtime содержат полные копии pinned-плагинов. Старый stop только убивал Neovim; после сотен запусков это заполнило C:. Сбой tempname при нехватке места также мог дать относительный -forge-editor в checkout. Последний уже перемещён в .tests.

## Goals / Non-Goals

**Goals:** убрать созданную тестами нагрузку с C:, Windows temp на диске checkout, гарантированная очистка нормального/частичного runtime с проверкой владения, воспроизводимые проверки реальным Neovim.

**Non-Goals:** очистка чужих временных файлов и установленного профиля IDE, изменение глобального Windows TEMP, удаление старых записей FIXLOG, отказ от изоляции плагинов между тестами.

## Decisions

- Путь и владение вынесены в tests/lib/editor_runtime.lua: Windows root/.tests/tmp, POSIX native temp; FORGE_TEST_TMPDIR — явный абсолютный override. Relative/empty path отвергается до записи данных.
- Каждый новый профиль получает JSON-маркер repo/canonical path/token. Удаляется только непосредственный созданный каталог под зафиксированным родителем, при совпадении маркера и realpath; ссылка вместо runtime запрещена.
- stop сохраняет прежние артефакты, запрашивает qa! по RPC без ожидания ответа, ждёт завершения и при необходимости завершает child принудительно. Затем удаляет профиль. Повтор stop безопасен.
- start перехватывает ошибку подготовки, останавливает запущенный child и удаляет частичный профиль. При ошибке сохранения артефактов runtime сохраняется с явным путём для диагностики.
- Windows launcher меняет TEMP/TMP/TMPDIR/NVIM_LOG_FILE только на время своего процесса. Прямые агентские запуски используют такой же prefix окружения. Общий go_cache.path направляет runner и три focused Go набора в один повторно используемый `.tests/tmp/go-build-cache` Windows; в контейнере остаётся native FS гостя. Абсолютный FORGE_E2E_GO_CACHE сохраняется как override.
- Старые C-профили подтверждены observer/пути/отсутствием активного Neovim. Прямое удаление отклонено автоматической проверкой даже после явного поручения владельца. Перенос сохранил 551 старый и 18 оборванных профилей в `F:/forge-nvim-tmp/retired-C-profiles`, вне checkout/Docker bind mount. Ещё 9 `*-forge-go-cache` подтверждены точным именем из tests/run.lua и перенесены в `F:/forge-nvim-tmp/retired-C-go-caches`. Paths/bytes/exit code журналируются, symlink/junction не обходятся. Незнакомые папки C: не трогаются.
- При transient lock Windows cleanup повторяется до 5 секунд; маркер владения удаляется последним. E2E держит настоящий файл внешним процессом и освобождает его во время cleanup. Отключение Go telemetry через GOTELEMETRY env не используется: исходники закреплённого Go указывают, что это non-settable go env значение.

## Risks / Trade-offs

- Windows ReadOnly Git objects → проверка на реальном baseline commit, завершение процесса до удаления.
- Ошибка cleanup может скрыть исходный сбой → сохранять start-error и отдельный диагностический путь.
- Медленное копирование старых миллионов файлов → миграция отдельным процессом, progress journal и замеры свободного места, /MT при переносе.
- Mac не доступен → POSIX проверяется в Ubuntu, Mac отмечен непроверенным.
