# Proposal

## Why

IDE-030: полный Windows-прогон остановился на No space left on device. `editor.start` копировал 66 плагинов в native TEMP на C:, а `stop` сохранял артефакты и убивал процесс без удаления runtime. На C: найдены 551 старый профиль с уникальным observer тестового каркаса. Владелец явно потребовал убрать созданные агентом данные и перенести tmp на F:.

## What Changes

- Windows runtime по умолчанию размещается в .tests/tmp на диске checkout; абсолютный FORGE_TEST_TMPDIR позволяет явное переопределение на любой ОС.
- Завершение Neovim, сохранение артефактов и удаление собственного runtime согласованы; ошибки подготовки также очищают частичный профиль.
- Удаление разрешено только по совпавшему маркеру владения и проверенному абсолютному пути; чужая папка сохраняется.
- scripts/test.ps1 направляет TEMP/TMP/TMPDIR и лог runner на диск checkout и восстанавливает окружение после запуска.
- Windows runner и focused Go e2e используют один повторно используемый compiler cache в .tests/tmp/go-build-cache; старые девять Go cache на C: также перенесены на F:.
- Старые подтверждённые профили освобождают C: переносом на F: с журналом путей и объёмов. Автопроверка отклонила прямое удаление; перенос сохраняет данные. Файлы пользователя не затрагиваются.
- Постоянные проверки реального завершения/очистки, ошибки prepare, чужого маркера и временного file lock; настоящий Go проверяет выбранный GOCACHE. История и команды.

## Capabilities

### New Capabilities

Нет. Это тестовая инфраструктура, skip_specs: true, как establish-platform-e2e-workflow.

### Modified Capabilities

Нет изменений поведения пользовательской IDE/main specs.

## Impact

tests/lib/editor.lua, новый менеджер runtime, E2E, Windows launcher, CLAUDE и документация. Исправление Diffview IDE-026 продолжается отдельно. Глобальные TEMP Windows и профили установленной IDE не меняются.
