# Общая консоль IDE Logs

Открыть: **Space w i** в normal mode или **:ForgeLogs**. Команда также видна
в палитре команд. Консоль занимает обычную нижнюю панель; Space w 0 возвращает
код, Space w h/j/k/l меняют окно, q скрывает, Space w z увеличивает/возвращает,
? показывает общую помощь. Выбранный источник и фильтры сохраняются при скрытии.

## Найти причину

По умолчанию открыта общая история: время, уровень, источник и текст.
Предупреждение об отсутствующем инструменте остаётся здесь после исчезновения
всплывающего сообщения. Его исходная подсказка подготовки также сохранена.

| Клавиши в консоли | Действие |
|---|---|
| s | Выбрать подсистему, native журнал или существующий Output buffer |
| f | Фильтр по тексту; Enter применяет, Esc отменяет ввод |
| v | ALL → WARN и ERROR → только ERROR → ALL |
| c | Сбросить текстовый и уровневый фильтры |
| /, n, N | Обычный поиск Neovim в показанном тексте |
| Enter на сообщении | Подробности с датой, источником и сессией; q/Esc закрывают |
| r | Обновить native историю и прочитать источники заново |
| y | Скопировать показанный отчёт в безымянный регистр; в clipboard при наличии provider |
| H | Явно открыть :checkhealth forge с состоянием tools и подсказками |

Нет совпадений по фильтру и отсутствующий источник — разные состояния.
Если чего-то не хватает, начни с общей истории и H; для подробностей выбери
нужный канал через s. Подготовку выполняешь явно, затем повторяешь действие
в том же редакторе. Консоль сама не устанавливает инструменты и не запускает jobs.

## Подробные источники

Neovim, LSP, DAP и его adapter logs, Conform, Neotest, Neogit, Overseer,
Mason, Fidget и загруженные terminal/test/debug Output buffers доступны через s.
Можно сразу вызвать :ForgeLogs lsp, :ForgeLogs dap, :ForgeLogs format,
:ForgeLogs tests, :ForgeLogs git, :ForgeLogs tasks, :ForgeLogs setup,
:ForgeLogs fidget, :ForgeLogs messages или :ForgeLogs events.
Дополнение после пробела показывает доступные источники и группы сообщений.

Панель показывает известный путь, состояние, время изменения и хвост файла.
«Файл не найден» означает отсутствие журнала, а не отсутствие ошибок.
Neogit file logging по умолчанию отключён; его старый файл помечается как
исторический. Консоль не меняет logging level и не включает такой logger.
Текущая Git command history доступна в Neogit через $ (Space w g).
Полная [карта источников и причины решений](IDE_LOG_SOURCES.md).

Native файл читается хвостом до64KiB; неполная начальная строка отбрасывается,
когда за ней есть полные строки. У единственной длинной строки сохраняется
доступный хвост с явной отметкой. Начало Unicode не режется внутри символа.
Output — до500 последних строк и до64KiB. Граница помечается [truncated].
Строки с неопределённым уровнем UNKNOWN видны в ALL. Просмотр/фильтрация не
переписывают исходные журналы; raw source остаётся у соответствующего backend.

## История между запусками

Собственные сообщения пишутся в stdpath('state')/forge-logs/.
Точный текущий путь и идентификатор сессии видны в панели. У каждой сессии
свой writer: current и предыдущий файл по128KiB, в памяти/общем view до200
последних записей. При следующем запуске сохраняются8 последних подтверждённо
завершённых сессий; файлы живых/неподтверждённых PID защищены от удаления.
Лимиты и факт вытеснения старых записей обозначаются в консоли.

vim.notify и direct Fidget notifications записываются сразу. Native :messages
читается при открытии/r/VimEnter/VimLeavePre: его timestamp обозначает время
получения снимка. Штатные командная строка и вывод сообщений сохраняются;
экспериментальная подписка ext_messages не используется. Разные native
форматы времени подробных журналов не подменяются общей выдуманной шкалой.

Ошибка записи не мешает UI и обычным уведомлениям: последние сообщения
остаются в памяти, причина показана в консоли. Такие записи могут быть
недоступны после выхода; последняя ошибка хранения остаётся видимой.
Повреждённые строки истории пропускаются с явным счётчиком.

Отчёт содержит выбранный view. Recorder не читает notification data,
environment или debug variables. Распознаваемые password/token/Bearer/URL
credentials скрываются в собственных записях и отчёте; native оригинал остаётся
неизменным. Обычный program/test Output читается только как выбранный канал.

## Проверки

Windows использует выбранный SDK; Ubuntu/macOS — официальный Neovim:

```sh
nvim -l tests/e2e/ide-logs.test.lua
nvim -l tests/e2e/ide-log-sources.test.lua
nvim -l tests/e2e/ide-log-history.test.lua
nvim -l tests/e2e/ide-log-tail.test.lua
nvim -l tests/e2e/debug-focus-order.test.lua
```

Deps готовятся явно по tests/e2e/README.md: editor plugins, Node/js-debug и
gofmt для реального formatter failure. Tests не скачивают инструменты.
Native restart использует настоящий TUI в своём терминале с общим state,
а не имитацию повторного старта UI. Mac/physical WezTerm/clipboard пока
требуют отдельного запуска: tests/manual/ide-logs.md.
