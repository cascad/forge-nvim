# Тормоза ввода и окон Windows — 2026-11-01

Статус: диагностика IDE-036. Зависание GPU-процесса VS Code подтверждено;
причина общесистемной задержки и устойчивое исправление ещё не установлены.

Во время Windows full IDE-034 владелец сообщил о сильных задержках ввода
и других программ, предполагая WezTerm. Свой прогон агент остановил целым
деревом процессов, проверив PID/родителя/команду. Тяжёлые проверки пока не
возобновляются. VS Code, WezTerm, Docker/WSL и рабочие приложения не закрывались.

## Что измерено

Windows 11 build 22631, 6 доступных логических CPU, около 61,6 GiB RAM;
VS Code 1.144.0. Замеры примерно 21:30–21:38 по Москве.

| Наблюдение | Результат |
|---|---|
| CPU | Система около 25%; GPU-процесс Code в трёх последовательных замерах 15,5–16,4% всей CPU, то есть почти одно ядро |
| Память | Свободно около 24–25 GiB; дефицит RAM не наблюдался |
| Диски | Очереди 0, активность мала; упора в диск в момент замера не было |
| WezTerm | CPU примерно 0,2–0,9% в первых замерах; окно Responding=True, cli list ответил за 128 ms |
| NVIDIA RTX 5080 | GPU около 2%, VRAM 1881/16303 MiB; переполнения видеопамяти не было |
| AMD Radeon Graphics | ConfigManagerErrorCode=43, Status=Error; это отдельный обнаруженный сбой устройства, связь с задержкой пока не доказана |
| VS Code GPU | Несколько смен PID: 28532 → 28988 → 20744 → 1384; процесс 1384 создан в 21:36:01, в замере 21:38 CPU уже 0% |

Ключевое доказательство — настоящий `code --status`, а не вывод о причине
только по высокой CPU. GPU Log Messages содержит три сообщения:

```text
GpuProcessHost: The GPU process crashed! Exit code: RESULT_CODE_HUNG.
```

Также есть ошибки `SharedImageManager::ProduceSkia` и
`Failed to create shared context for virtualization`. GPU Status сообщает
software fallback для compositing/rasterization; GPU vendor/device 0x0000.
Это подтверждает сбой графического процесса VS Code, но не доказывает,
что именно он первоначально вызвал все задержки остальных приложений.

В Application/System за последние два часа не найдены соответствующие
AppHang/AppCrash Code/WezTerm и Display 4101. Отсутствие этих событий не
отменяет RESULT_CODE_HUNG: он зафиксирован собственным GPU diagnostics Code.
WezTerm log содержит один mux disconnect 10054; ошибки missing.lua и
намеренно сломанного конфига относятся к sandbox-тесту, не к рабочему окну.

## Что дальше проверять

1. Сопоставить отзывчивость ввода с завершением серии GPU hangs и остановкой
   тестов. От владельца запрошено наблюдение; ответа на момент записи нет.
2. Если проблема повторяется, сохранить `code --status` прямо во время неё.
   Для контролируемого сравнения полностью перезапустить **после сохранения
   работы** VS Code с `code --disable-gpu`. Это диагностический вариант,
   а не уже доказанное исправление. [Официальная FAQ VS Code](https://code.visualstudio.com/docs/supporting/faq#_vs-code-is-blank).
3. Ошибку AMD Code 43 исследовать отдельно: Windows получил сообщение о
   неисправной работе устройства/драйвера; по одному этому коду нельзя выбрать
   конкретную причину или требуемый драйвер. [Microsoft](https://support.microsoft.com/en-us/windows/hardware/display-graphics/fix-graphics-device-problems-with-error-code-43).
4. Если при исправном GPU-процессе задержки сохранятся, отдельно сравнить
   отрисовку WezTerm и задержку доставки клавиатуры. Пустая очередь диска и
   низкая CPU WezTerm сами по себе не исключают ожидание драйвера/событий.

Ни драйверы, ни глобальные графические настройки в ходе измерения не менялись.
Рестарт рабочих приложений для A/B ещё не выполнен; E2E/«исправлено» не заявлены.

В 21:47 по повторной просьбе вернуть отзывчивость отдельно перезапущен только
GPU child VS Code: перед завершением проверены имя, `--type=gpu-process` и
родитель 19960; PID 1384 сменился на 20668. Главный процесс Code 19960 и
WezTerm 13924 сохранились, оба Responding=True. Перед этим GPU CPU уже был 0%,
поэтому это попытка восстановления графического контекста, не доказанный fix.
Владельцу предложен Win+Ctrl+Shift+B (штатное восстановление графики Windows),
затем, при сохранении проблемы, полный запуск сохранённой работы VS Code с
`code --disable-gpu`.

После этого владелец сообщил: отзывчивость восстановилась только после
перезагрузки компьютера; предложенные меры эпизод не устранили. Завершение
GPU child VS Code не является исправлением. Факт его hangs сохраняется,
но причиной всех задержек он не объявляется. IDE-036 остаётся открытым;
переустановка драйверов или изменение общего конфига по этому эпизоду не делались.
После рестарта владелец поручил продолжить roadmap и возобновить проверки.
