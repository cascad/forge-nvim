# Helix — что заболело и почему уходим на Neovim

Этот файл — постмортем сессии настройки Helix. Сама конфигурация рабочая
и зелёная по `hx --health`. Но в процессе настройки и первого
использования всплыло несколько вещей, которые **не лечатся**
конфигурацией — это архитектурные ограничения Helix. Список ниже
объясняет, почему дальше едем на Neovim.

## 1. File picker — плоский fuzzy, без иерархии

`Ctrl+P` показывает плоский список путей. Tree-view explorer'а в ядре
Helix **нет**. Это решается только внешним TUI-файлменеджером (yazi,
broot, lf), запускаемым через `:sh` — что работает, но это уже
не «нативный» интерфейс.

**Эффект на практике:** для проектов с хорошо знакомой структурой
fuzzy быстрее tree-view. Для незнакомых проектов или когда не помнишь
имени файла — мучительно.

## 2. Picker засоряют `venv/`, `node_modules/`, `target/`...

Helix file_picker уважает `.gitignore` и `.ignore`, но если в проекте
их нет — picker завален мусором. Лечится созданием `.ignore` в корне
проекта или глобального `~/.ignore`. Дополнительная ручная работа на
каждый новый проект.

## 3. Подсветка fuzzy-матчей зависит от темы и тусклая на дефолте

На стандартной `onedark` совпавшие символы в picker'е едва видны.
Лечится сменой темы (catppuccin_mocha, tokyonight) — но это уже
костыль вокруг фундаментально слабого picker'а.

## 4. DAP без UI — все панели реализованы пикерами

Дебаг работает (codelldb, dlv, debugpy подцепляются), но интерфейс —
это **picker'ы по запросу**, а не постоянные панели как в VS Code:

* нет постоянной side-panel с переменными и стеком;
* нет hover-tooltip над переменной с её значением;
* условные breakpoint'ы — через typable-команду, не через UI;
* watch-выражения — только через `:debug-eval` руками.

**Эффект:** для редкой отладки терпимо. Для регулярной работы с
дебаггером — VS Code или JetBrains всё равно лучше, и на этом фоне
смысл Helix-DAP размывается.

## 5. TOML-грабли в конфиге

Helix читает только TOML, и TOML-формат вместе со специфичной
семантикой Helix даёт целый набор ловушек, на которые поймались в этой
сессии:

| Ловушка | Сообщение | Как лечится |
|---|---|---|
| Многострочный inline-table | `invalid inline table, expected '}'` | Переписать на dotted-keys или отдельную секцию `[a.b]` |
| Кавычки вокруг dotted-keys (gopls config) | парсится, но ключ становится плоским с точкой в имени; LSP игнорирует | Убрать кавычки: `formatting.gofumpt = true` |
| Двухклавишная последовательность через пробел | `Invalid key code 'g i'` | Использовать секцию `[keys.normal.g]` или inline-table |
| Многострочный inline-table в keybinds | то же `invalid inline table` | Секции `[keys.normal.space.X]` |
| DAP-команды как typable | `No TypableCommand named ':debug-breakpoint'` | Заменять на actions `dap_*` (без двоеточия) — typable есть только три: `:debug-start`, `:debug-remote`, `:debug-eval` |
| Вложенный inline-table в `args` DAP-шаблона | `data did not match any variant of untagged enum DebugArgumentValue` | Развернуть через dotted-keys или удалить шаблон |

**Эффект:** Helix падает на **первой** ошибке, нет режима «провалидируй
всё разом». Ловить грабли пришлось 6+ перезапусков подряд. В Neovim
эта проблема снимается просто потому что конфиг — это Lua-код, который
парсится целиком, плюс есть `:checkhealth`, `:Lazy log`, `:messages`.

## 6. Нет плагинов — то, что не в ядре, добавить нельзя

Принципиальная позиция Helix-команды. Что попало в ядро — есть. Чего
нет — не добавишь. File-tree, нормальный DAP UI, lint-интеграция за
пределами LSP, AI-помощники, git-merge UI — всё это в Helix будет
«когда-то», без возможности ускорить процесс под себя.

## 7. Selection-first модель ломает мышцы из Vim

`miw d` вместо `diw`, `mi{ c` вместо `ci{` — концептуально красиво, но
после многих лет Vim переучиваться сложно. Особенно когда параллельно
правишь старые `init.vim` в других редакторах. Когнитивный налог
постоянный.

## 8. Bin-distribution и runtime на Windows

Под Windows runtime нельзя засимлинкать без админ-прав → копируем.
Каждый апдейт Helix через winget — ещё одна копия `runtime/`. Не
смертельно, но раздражает.

## 9. Каждая правка `config.toml` в `F:\claude_code\vim\helix\` требует `copy ... -Force` в `%AppData%\helix\`

Helix не читает конфиги по симлинку без админ-прав на Windows.
Workflow «правка → копирование → перезапуск» вместо «правка →
перезагрузка». Лечится ручным симлинком от админа, но из коробки —
лишняя ступенька.

## Что зашло хорошо в Helix (для честности)

* **`hx --health <язык>`** — мгновенный отчёт по LSP/DAP/grammar/queries.
  Это очень удобно. Хотим такое же или лучше в Neovim — будет через
  `:checkhealth`.
* **Без плагинов** = без зоопарка зависимостей, без plugin-conflict'ов,
  быстрый старт. Цена — потолок гибкости (см. выше).
* **Multi-cursor** и **structural editing** через tree-sitter
  (matchin' inside, surround) — действительно быстрее Vim'овских
  text-objects, **когда** к ним привыкаешь.
* **Подсветка**, **hover**, **inlay hints**, **rename**, **code
  actions** — работают из коробки за 5 минут настройки.

## Итог

Helix отлично подходит для **«легковесный модальный редактор для
быстрых правок и навигации по уже знакомой кодовой базе»**. Для
**«основной IDE, в которой проводишь день»** — упирается в потолок
по UX (file tree, DAP UI, file picker mass-action) и кастомизации
(нет плагинов).

Дальше — Neovim. План в `F:\claude_code\vim\nvim\README.md`.
