# Как fride запускает код

## Открыть проект

Из корня репозитория на macOS или Linux запусти `./fride /путь/к/проекту`,
на Windows — `.\fride.cmd D:\путь\к\проекту`. В установленном комплекте
запускай его `bin/fride` или `bin\fride.cmd`. Запуск без аргументов
открывает стартовый экран. `p` показывает недавние проекты. В редакторе
тот же список открывает `Space o p`. Если у выбранной папки сохранена
сессия, fride восстанавливает её файлы и панели.

Checkout использует конфиг из репозитория и отдельный профиль
`nvim_forge`. На Windows он запускает Neovim из подготовленного
`.tools`, на macOS и Linux — `nvim` из `PATH`. Установленный комплект
использует свой Neovim, конфиг и профиль `fride`. После обновления checkout
проверяет известные локальные поправки к плагинам до открытия редактора.
Если в кэше осталась другая чистая Git-ревизия такого плагина,
запуск переключает её на закреплённый коммит при наличии объектов на диске.
Для кэша, которому нужна загрузка, на macOS из корня репозитория выполни
`./fride --headless -i NONE -u "$PWD/nvim_forge/init.lua" -l nvim_forge/scripts/setup-stage.lua plugins`.
При локальных правках сначала посмотри `git status` в каталоге плагина.
Подготовка отсутствующих плагинов и языковых инструментов запускается
явно. [Подготовка checkout](../README.md#how-the-launchers-work) ·
[Как устроен установленный комплект](ACCEPTANCE_INSTALLER.md)

## Запуск из терминала и отладка

`Space w T` открывает обычную системную оболочку внутри редактора.
В ней можно выполнить привычную команду проекта, например
`python app.py`, `go run .` внутри Go-модуля или `cargo run`.
`Space t S` выбирает оболочку, а `Space t N` открывает новую консоль.
Команда `python` в терминале использует окружение этой оболочки.
Если нужна конкретная venv, активируй её или вызови её Python по пути.

Для отладки открой нужный файл, сохрани правки, поставь точку останова
через `F9` и нажми `F5`. Выбери готовую конфигурацию для файла или
запись из ближайшего `.vscode/launch.json`. `Space d P` показывает все
записи из найденного `launch.json`, включая конфигурации другого языка.
На `Cargo.toml` нажми `F5`, выбери исполняемый пакет или пример из Cargo workspace и подтверди через `Enter`. fride соберёт выбранную цель и запустит её под CodeLLDB. В списке также доступны явные цели из `launch.json`. Если подходящих целей нет, редактор покажет сообщение. `Esc` возвращает к документу.

Строка состояния показывает поиск целей (`Debug: finding targets`), сборку Cargo (`building`), подключение к адаптеру (`starting`). Затем `running` — выполнение, `paused` — остановку на точке или шаге, `idle` — отсутствие активной сессии. После завершения вывод можно перечитать.

Поля запуска передаются соответствующему адаптеру. Некоторые поля,
например специальное поле CodeLLDB `cargo`, обрабатываются расширением
VS Code и требуют эквивалентной конфигурации с `program` во fride.

| Действие во время отладки | Клавиши |
| --- | --- |
| Продолжить выполнение | `F5` |
| Шаг по строке, вход в вызов, выход из вызова | `F10`, `F11`, `Shift+F11` |
| Остановить или перезапустить | `Shift+F5` или `Ctrl+Shift+F5` |
| Фокус в переменные, вывод или обратно в код | `Space w d`, `Space w c`, `F7` |

При запуске открываются панели Debug. На остановке в них доступны
переменные и стек. Вывод остаётся доступным после завершения программы.
При сбое смотри Debug Output и `:ForgeLogs`, для ошибки загрузки
самого редактора — `:messages`. [Общая консоль логов](IDE_LOGS.md)

## Что выбирают стандартные конфигурации

| Файл | Что собирает и запускает fride |
| --- | --- |
| **Go** | **Current Go package** запускает Delve для всего пакета из каталога файла. Delve собирает в этом каталоге, а программа получает рабочий каталог открытого проекта. Если есть `go.mod` или активный `go.work`, применяются штатные правила Go. Для пакета без них стандартный запуск использует режим GOPATH только в процессе Delve и собирает `.`. Это работает и для нескольких файлов одного пакета. |
| **Python** | **Current Python file** запускает открытый файл из корня проекта выбранным ниже интерпретатором. У debugpy может быть отдельный интерпретатор для самого адаптера. |
| **Rust** | Стандартная конфигурация выбирает Cargo bin для открытого файла, собирает debug-бинарь через Cargo и запускает его в CodeLLDB. [Работа с Rust](RUST_WORKFLOW.md) |

Своя настройка `.vscode/launch.json` задаёт цель, аргументы и каталог
через её поля. Правила стандартного Go-запуска применяются к пункту
**Current Go package**.

## Как выбирается Python

1. Если указал интерпретатор явно через `:ForgeSdk python` или в настройках
   путей fride, используется явный выбор. Через меню можно выбрать
   найденную среду или указать свой путь. [Выбор SDK](SDK_SELECTION.md)
2. В автоматическом режиме fride ищет `.venv`, `venv`, `.env` и `env`
   для ближайшего Python-проекта и корня репозитория. Проверяется
   исполняемый Python внутри окружения. Активация в оболочке не требуется.
3. Если локального окружения нет, fride берёт валидный `VIRTUAL_ENV`
   или `CONDA_PREFIX`. Затем ищет Python в `PATH`.

Pyright при запуске и стандартный Python Debug используют этот порядок.
Явные настройки конкретного подключения Pyright или DAP сохраняют приоритет.
Чтобы увидеть путь для отладки, открой Python-файл и выполни
`:DapPythonInfo`. В `:ForgeLogs` источник **Tool paths** показывает
найденный путь и откуда он взялся.

Порядок повторяет полезную часть модели VS Code: явный выбор, затем
окружение внутри проекта, затем системные варианты.
[Как VS Code обнаруживает и выбирает Python-окружение](https://code.visualstudio.com/docs/python/environments#interpreter-selection-priority)
