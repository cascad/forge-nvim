# Чистый Docker на Windows — 2026-11-01

По явному выбору владельца используется новое пустое хранилище, без импорта
прежних контейнеров/образов. Docker Desktop не переустанавливался.

| Настройка | Значение |
|---|---|
| Engine | Docker 28.5.1, Linux/WSL 2, context `desktop-linux` |
| Хранилище | `F:/wsl/DockerDesktopWSL-clean` |
| Предел виртуального диска | 128 GiB (`DiskSizeMiB=131072`) |
| Desktop AutoStart | `false` |
| Image store | containerd/overlayfs |
| Проверка | private container + named volume write/read PASS |

Активный `disk/docker_data.vhdx` в новом каталоге после настройки занимает
около 1,36 GiB. После проверки остался только образ `busybox:1.37.0`
(6,77 MB по Docker); пробные контейнеры/том удалены. Репозиторий не содержит
автозапуска Docker Desktop: тесты могут использовать только уже запущенный
разрешённый engine. При недоступности engine агент сообщает ограничение,
не перезапускает Desktop/WSL и не ремонтирует runtime без отдельного поручения.

## Старые данные и отменённое копирование

Прежний диск находится в
`F:/wsl/DockerDesktopWSL/disk/docker_data.vhdx`:
503452794880 байт (468,88 GiB), исходная метка создания 2025-03-16,
LastWrite 2026-11-01 21:50:06 по Москве. Он сохранён без изменения размера/
LastWrite и не подключён к чистому Docker. Само наличие файла ещё не является
проверкой целостности каждой файловой системы/данных внутри него.

До выбора чистого окружения агент начал копирование старого диска в
`F:/wsl/DockerDesktopWSL-recovered-20261101/disk/docker_data.vhdx`. По просьбе
владельца процесс копирования и его управляющий shell остановлены. Этот файл
**незавершённый** и не используется Docker. Он может занимать весь заранее
выделенный размер, хотя копирование не закончилось. Удаление именно этой
созданной агентом копии отклонено автоматической проверкой (`blocked by policy`);
копия осталась. Исходный диск без суффикса `recovered` — другой файл.

## Почему до настройки Docker выглядел пустым

Предыдущий запуск после рестарта ПК упал на недоступных AF_UNIX runtime
endpoints. Агент сохранил `Docker/run` переименованием в
`run.retired-20261101-ide035` и создал новый runtime. Затем в журнале Docker
зафиксирован UI action `Reset to factory defaults` (22:52:00), после которого
CustomWslDistroDir сменился с прежнего F: на C: и были созданы новые диски.
Инициатор UI действия этим разбором не устанавливается. Команды агента
factory reset не вызывали; прежний диск на F: найден отдельно.

Восстановление прежнего диска было отменено владельцем в пользу чистого
окружения. Ни старые 468,88 GiB, ни незавершённая копия не являются новыми
тестовыми образами этого чистого Docker.
