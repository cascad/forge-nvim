# WezTerm — руководство по конфигу forge-nvim

Руководство «как сделать X». Что обязано происходить, со всеми
корнер-кейсами, — в спеках `openspec/specs/wezterm-*` (ID вроде `WT-WIN-2`
в заголовках и колонке «Спека» ведут туда); решённые, но ещё не
применённые изменения — в `openspec/changes/`.

WezTerm здесь не только терминал, но и **мультиплексор** вместо tmux:
панели, вкладки, воркспейсы. tmux и zellij нативно живут только под Unix, на
Windows их пришлось бы тащить в WSL, и хоткеи разъехались бы между
машинами. У WezTerm мультиплексор встроенный, а `wezterm.lua` — единственный
источник хоткеев на всех ОС.

---

## 0. Где конфиг и как понять, что он загружен (WT-LOAD-1, WT-LOAD-3, WT-LOAD-4, WT-LOAD-13, WT-LOAD-15)

Конфиг — один файл `wezterm.lua` в корне репо.

| ОС | Как подключается | Спека |
|---|---|---|
| Windows | переменная `WEZTERM_CONFIG_FILE` уровня пользователя (её видят и запуски из Пуска): `[Environment]::SetEnvironmentVariable("WEZTERM_CONFIG_FILE", "F:\repo\forge-nvim\wezterm.lua", "User")` | WT-LOAD-3 |
| macOS | ничего руками: `./nvim_forge/scripts/install-macos.sh` ставит симлинк `~/.config/wezterm/wezterm.lua` и убирает всё, что его молча перекрывает (раздел 11) | WT-LOAD-4…WT-LOAD-12 |
| Linux | из корня репо: `mkdir -p ~/.config/wezterm && ln -sf "$PWD/wezterm.lua" ~/.config/wezterm/wezterm.lua` или `./nvim_forge/scripts/install-linux.sh` (путь, уже ведущий в репо, не трогает, внутри чекаута ничего не кладёт). `~/.wezterm.lua` и `WEZTERM_CONFIG_FILE` на Linux перекрывают симлинк молча — убери их руками | WT-LOAD-13 |

**Признак, что загружен этот конфиг:** панель вкладок **внизу окна**, справа
в ней серым имя воркспейса (`default`). Встроенный конфиг WezTerm держит
панель вверху. Проверить, что файл грузится без ошибок, можно и без окна:
`wezterm --config-file wezterm.lua ls-fonts` — при ошибке stdout пуст, в
stderr строка `ERROR` (`show-keys` ошибок не показывает). Перечитать конфиг —
`Ctrl+Shift+R` (WT-LOAD-14).

## 1. Принципы (WT-KEYS-1, WT-KEYS-2, WT-SCROLL-12, WT-WIN-7, WT-PANE-4)

**Встроенные хоткеи WezTerm выключены целиком** (`disable_default_key_bindings`).
Они заданы по символу, работали бы только на английской раскладке и
отнимали клавиши у Neovim. Всё нужное задано в конфиге заново (WT-KEYS-1).
Мышь — встроенная (WT-PANE-13).

**Клавиши — по ФИЗИЧЕСКОЙ позиции** (`phys:`, раскладка US-ANSI), поэтому
на русской и английской раскладке всё одинаково. Это касается и copy mode /
search mode: их встроенные таблицы конфиг при загрузке переписывает на
позиции (WT-KEYS-2). Раскладка всё же важна там, где WezTerm сравнивает
набранный **символ**:

- метки QuickSelect — латинские: на русской раскладке переключись на
  английскую (WT-SCROLL-12);
- метки выбора панели по `q` в режиме WINDOWS — то же (WT-WIN-7);
- ответ `y`/`n` в запросе «закрыть панель?» — на русской раскладке ответить
  можно только мышью по кнопке (WT-PANE-4).

**Режим WINDOWS вместо tmux-префикса** — `Ctrl+Shift+Space`, раздел 2. У
Neovim отбирается одно сочетание — сам вход.

Буквы команд — по логике vim, а не tmux: `v` = `:vsplit`, `s` = `:split`.

## 2. Режим WINDOWS (WT-WIN-1…WT-WIN-21, WT-UI-12…WT-UI-15)

`Ctrl+Shift+Space` включает **липкий** режим управления окнами: жмёшь
команды сериями на голых буквах, пока не выйдешь. Справа в панели вкладок —
жёлтый бейдж `▶ WINDOWS · Esc выход`.

- **Выход** — `Esc`, `Enter` или ещё раз `Ctrl+Shift+Space`; каждый снимает
  один слой (WINDOWS, включённый поверх RESIZE, — обратно в RESIZE). Enter
  с модификаторами — не выход (WT-WIN-2).
- **Таймаут** — 5 секунд от последней команды режима или сочетания
  терминала; проглоченные клавиши таймаут не продлевают (WT-WIN-3).
- **Клавиша без команды проглатывается**: в программу не уходит, режим
  остаётся. Опечатка не напечатает букву в nvim (WT-WIN-4).
- **Сочетания терминала работают и в режиме** (`Ctrl+Shift+T`,
  `Ctrl+Shift+H`, `Ctrl+Tab`, `Ctrl+V`…) — так же, как без него, одинаково на
  Windows и macOS, и продлевают режим (WT-WIN-4). Открывающие экран
  (`Ctrl+Shift+W`, `Ctrl+Shift+U`, `Ctrl+Shift+X`, на macOS `Cmd+Q`) сначала
  выключают режим (WT-WIN-19).

| Клавиша | Действие | Режим после | Спека |
|---|---|---|---|
| `h` `j` `k` `l`, стрелки | фокус в панель в этом направлении | остаётся | WT-WIN-5 |
| `o` | следующая панель по кругу, панели не переставляются | остаётся | WT-WIN-6 |
| `v` / `s` | новая панель справа / снизу | остаётся | WT-WIN-8 |
| `z` | развернуть панель на всё окно и обратно | остаётся | WT-WIN-9 |
| `c` | новая вкладка | остаётся | WT-WIN-13 |
| `n` / `p` | следующая / предыдущая вкладка по кругу | остаётся | WT-WIN-13 |
| `1`…`9` | вкладка с этим номером (верхний ряд) | остаётся | WT-WIN-13 |
| `r` | подрежим RESIZE (ниже) | заменяется RESIZE | WT-WIN-11 |
| `q` | метки на панелях — прыгнуть в любую | выключается | WT-WIN-7 |
| `x` | закрыть панель (запрос — как у `Ctrl+Shift+W`) | выключается | WT-WIN-10 |
| `a` | раскладка: текущая панель слева, справа две консоли | выключается | WT-WIN-12 |
| `,` | переименовать вкладку | выключается | WT-WIN-14 |
| `w` | лаунчер: вкладки и воркспейсы с нечётким поиском | выключается | WT-WIN-15 |
| `Shift+S` | создать воркспейс или перейти в существующий | выключается | WT-WIN-15 |
| `[` | copy mode | выключается | WT-WIN-16 |
| `f` | поиск по истории | выключается | WT-WIN-16 |
| `Space` | QuickSelect | выключается | WT-WIN-16 |
| `b` | история панели в nvim новой вкладкой | выключается | WT-WIN-17 |
| `e` | выбор символа / эмодзи (копируется в буфер) | выключается | WT-WIN-18 |
| `;` | палитра команд WezTerm | выключается | WT-WIN-18 |
| `m` | полноэкранный режим | выключается | WT-WIN-18 |
| `d` | debug overlay: журнал WezTerm и Lua-консоль | выключается | WT-WIN-18 |

**RESIZE** (`r`) заменяет WINDOWS: `h`/`←` и `l`/`→` двигают вертикальную
границу на 3 ячейки, `k`/`↑` и `j`/`↓` — горизонтальную. `Esc` и `Enter` —
сразу в обычный ввод. Остальное — как в WINDOWS: чужие клавиши
проглатываются, сочетания терминала работают, таймаут 5 секунд (WT-WIN-11).

**Бейджи** (WT-UI-12): `WINDOWS` — жёлтый, `RESIZE` — оранжевый, `COPY` —
синий, `SEARCH` — зелёный. COPY и SEARCH принадлежат панели: в соседней
панели их нет. У оверлеев (QuickSelect, лаунчер, палитра, выбор символа,
запросы, debug overlay) бейджа нет, хотя клавиши они перехватывают. Бейдж и
имя воркспейса видны всегда: при нехватке места сужаются вкладки, а не
правая часть (WT-UI-15).

**Ограничение WezTerm:** если включить режим поверх уже открытого экрана
выбора панели, выбора символа или палитры, клавиши без команды режима
получает экран, а не режим (WT-WIN-21).

## 3. Панели без режима (WT-PANE-1…WT-PANE-4, WT-PANE-9, WT-PANE-12, WT-PANE-13)

| Сочетание | Действие | Спека |
|---|---|---|
| `Ctrl+Shift+Enter` | новая панель справа — основной способ «дай вторую консоль» | WT-PANE-1 |
| `Ctrl+Shift+Alt+Enter` | новая панель снизу | WT-PANE-1 |
| `Ctrl+Shift+H` `J` `K` `L`, `Ctrl+Shift+←↓↑→` | фокус в панель в этом направлении | WT-PANE-2 |
| `Ctrl+Shift+Z` | развернуть панель и обратно | WT-PANE-3 |
| `Ctrl+Shift+W` | закрыть панель | WT-PANE-4 |

Закрытие спрашивает подтверждение, только если в панели работает что-то
кроме шелла (pwsh, zsh, bash…): одна консоль закрывается сразу. На русской
раскладке `y` в запросе не набрать — ответь мышью по `[Y]es`, отмена — `Esc`
(WT-PANE-4).

Новая панель открывается в каталоге текущей, если шелл сообщает его через
OSC 7 (zsh/bash — shell-integration WezTerm, pwsh — строка в профиле); без
этого — в каталоге, где был запущен процесс панели (WT-PANE-12). Раскладка
«nvim слева, две консоли справа» — `a` в режиме WINDOWS (WT-PANE-9).

Мышь: границы панелей таскаются, клик по вкладке переключает её
(WT-PANE-13). Неактивные панели слегка притушены (WT-UI-11).

## 4. Вкладки и окна (WT-PANE-5…WT-PANE-8, WT-PANE-11, WT-KEYS-5)

| Сочетание | Действие | Спека |
|---|---|---|
| `Ctrl+Shift+T` (macOS и `Cmd+T`) | новая вкладка | WT-PANE-5 |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | следующая / предыдущая вкладка | WT-KEYS-5 |
| `Ctrl+Shift+PageDown` / `PageUp` | то же | WT-PANE-6 |
| `Ctrl+Shift+1`…`9` | вкладка с этим номером | WT-PANE-6 |
| `Ctrl+Shift+N` (macOS и `Cmd+N`) | новое окно | WT-PANE-7 |

Голые `Tab` и `Shift+Tab` не перехватываются — ими Neovim крутит буферы
(WT-KEYS-5). Переименовать вкладку — `,` в режиме WINDOWS (WT-PANE-11).

Новое окно открывается как первое: сохранённого размера (раздел 10), по
центру активного экрана (WT-STATE-2).

## 5. Воркспейсы (WT-PANE-10, WT-UI-13)

Воркспейс — набор вкладок и панелей под задачу, аналог сессии tmux.

| Клавиша в режиме WINDOWS | Действие | Спека |
|---|---|---|
| `Shift+S` | создать воркспейс или перейти в существующий по имени | WT-PANE-10 |
| `w` | список воркспейсов и вкладок с нечётким поиском | WT-PANE-10 |

Имя текущего воркспейса всегда видно справа в панели вкладок (WT-UI-13).

## 6. История: прокрутка, очистка, copy mode, поиск (WT-SCROLL-1…WT-SCROLL-11, WT-SCROLL-15)

| Сочетание | Действие | Спека |
|---|---|---|
| колесо, `Shift+PageUp` / `Shift+PageDown` | прокрутка истории на экран; любой ввод в программу возвращает вид вниз | WT-SCROLL-2 |
| `Ctrl+Shift+Delete` | стереть историю панели выше экрана (на Mac — Forward Delete, `fn+⌫`) | WT-SCROLL-4 |
| `Ctrl+Shift+X` / `[` в режиме WINDOWS | copy mode | WT-SCROLL-5 |
| `/` в copy mode / `f` в режиме WINDOWS | поиск | WT-SCROLL-8, WT-SCROLL-9 |

### Copy mode — движение (WT-SCROLL-6)

| Клавиши | Куда |
|---|---|
| `h` `j` `k` `l`, стрелки | символ / строка |
| `w` / `b` / `e` (и `Tab` / `Shift+Tab`, `Alt+→` / `Alt+←`) | следующее слово / предыдущее / конец слова |
| `0`, `Home` / `^` / `$`, `End` | начало строки / первый непробельный / конец содержимого |
| `Enter` | начало следующей строки |
| `Ctrl+U` / `Ctrl+D` | полэкрана вверх / вниз |
| `Ctrl+B` / `Ctrl+F`, `PageUp` / `PageDown` | экран вверх / вниз |
| `H` / `M` / `L` | верх / середина / низ экрана — с отступом 5 строк от края |
| `g` / `G` | первая строка истории (одиночная `g`, не `gg`) / последняя строка экрана; столбец сохраняется |
| `f` `F` `t` `T` + символ, `;` / `,` | прыжок к символу в строке и его повтор |

### Copy mode — выделение и копирование (WT-SCROLL-7)

| Клавиши | Действие |
|---|---|
| `v` (или `Space`) / `Shift+V` / `Ctrl+V` | выделение по символам / по строкам / блоком |
| `o` / `O` | на другой конец выделения |
| `y` | скопировать выделение и выйти; без выделения буфер не трогается |
| `Ctrl+Shift+C`, `Ctrl+Insert` (macOS и `Cmd+C`) | скопировать, не выходя |
| `Esc`, `q`, `Ctrl+C`, `Ctrl+G` | выйти без копирования |

### Поиск (WT-SCROLL-8…WT-SCROLL-11, WT-SCROLL-15)

| Клавиши | Действие |
|---|---|
| `/` в copy mode | ввести шаблон (кириллица — как есть) |
| `Enter` | принять шаблон и вернуться в copy mode на совпадении, как `/` в vim |
| `n` / `N` в copy mode | следующее / предыдущее совпадение |
| `↑` / `Ctrl+P`, `↓` / `Ctrl+N` | к совпадению выше / ниже — в строке ввода |
| `Ctrl+R` | тип поиска по кругу: без учёта регистра → regex → с учётом регистра |
| `Ctrl+U` | очистить шаблон |
| `Ctrl+Shift+X` | в copy mode на текущем совпадении |
| `Esc` | закрыть поиск **вместе с copy mode** |

Шаблон и тип запоминаются для вкладки: следующий `/` или `f` начинает с них.
`PageUp` / `PageDown` в строке поиска работают наоборот подписям — так
устроена встроенная таблица WezTerm (выведено из исходника, WT-SCROLL-15).

## 7. QuickSelect (WT-SCROLL-12)

`Ctrl+Shift+U` или `Space` в режиме WINDOWS подсвечивает на экране и до
1000 строк выше пути, URL, git-хеши, UUID, IP, числа от 4 цифр — с
буквенными метками. Набрал метку — фрагмент в буфере; **Shift+метка**
копирует и сразу вставляет. `Esc` — выход.

Метки латинские: на русской раскладке переключись на английскую, а уже
набранную кириллицу сотри `Backspace` (или `Ctrl+U`). Пути Windows с `\` не
подсвечиваются.

## 8. Выгрузка истории в nvim (WT-SCROLL-13)

`b` в режиме WINDOWS пишет историю и экран панели в `~/.wezterm_scrollback.txt`
и открывает его в новой вкладке (`nvim +`, курсор на последней строке).
Дальше это обычный Neovim: `/`, `n`, визуальное выделение, `:w` куска в файл;
`:q` — назад к консоли.

- Запускается `nvim` из PATH со стандартным конфигом (`~/.config/nvim`), не
  nvim_forge: важен мгновенный старт.
- Строки экранные: длинная перенесённая строка — несколько строк. **Пустые
  строки выпадают все**, в том числе посреди вывода; в конце файла нет
  перевода строки.
- Файл один и перезаписывается; в нём остаётся последний вывод — если там
  мелькали токены или пароли, удали его руками.
- На альтернативном экране выгружается только видимый экран (раздел 13).

## 9. Буфер обмена (WT-CLIP-1…WT-CLIP-11)

| Сочетание | Платформы | Действие | Спека |
|---|---|---|---|
| выделение мышью | все | копируется в буфер при отпускании кнопки | WT-CLIP-7 |
| `Ctrl+Shift+C`, `Ctrl+Insert` | все | копировать выделение WezTerm; без выделения — ничего | WT-CLIP-1, WT-CLIP-4 |
| `Ctrl+C` | Windows | есть выделение — копирует и снимает его; нет — прерывание в программу | WT-CLIP-2 |
| `Ctrl+C` | macOS, Linux | не перехвачен — всегда прерывание | WT-CLIP-3 |
| `Cmd+C` | macOS | копировать выделение; без выделения — ничего | WT-CLIP-5 |
| `Ctrl+V`, `Ctrl+Shift+V`, `Shift+Insert` (macOS и `Cmd+V`) | все | вставить (в nvim — как вставленный текст) | WT-CLIP-6 |

Без выделения никакая клавиша копирования буфер не трогает — в нём остаётся
то, что было (WT-CLIP-1). Программа может положить текст в буфер сама через
OSC 52 (WT-CLIP-11, раздел 13).

## 10. Окно и шрифт (WT-STATE-1…WT-STATE-8)

| Сочетание | Платформы | Действие | Спека |
|---|---|---|---|
| `Ctrl` + `=` / `-` (и с Shift) | все | шрифт крупнее / мельче (×1,1) в этом окне | WT-STATE-6 |
| `Cmd` + `=` / `-` | macOS (Super на Linux) | то же | WT-STATE-6 |
| `Ctrl` + `0` (macOS и `Cmd+0`) | все | сбросить шрифт к сохранённому (без сохранённого — 12), при каждом нажатии | WT-STATE-7 |
| `Ctrl+Shift+S` (macOS и `Cmd+Shift+S`) | все | запомнить размер окна и шрифт | WT-STATE-3 |

**Как задать размер:** растяни окно, подбери шрифт, нажми `Ctrl+Shift+S`.
Так открываются все новые окна — по центру активного экрана и с сохранённым
шрифтом; уже открытые окна не меняются (шрифт они возьмут после
`Ctrl+Shift+R`). Пока ничего не сохранено — окно в 0,62 × 0,72 экрана
(WT-STATE-1, WT-STATE-2, WT-STATE-5). Файл состояния —
`~/.wezterm_forge_window.json`, вне репо (WT-STATE-4). Смена шрифта
выключает режимы WINDOWS/RESIZE в этом окне. На Windows Super-вариантов
шрифта нет: `Win+=` там — системная экранная лупа.

## 11. Различия Windows и macOS (WT-KBD-1…WT-KBD-5, WT-CLIP-2, WT-CLIP-3, WT-CLIP-5, WT-PANE-8, WT-UI-1, WT-UI-2)

Набор хоткеев общий; устаревшая кодировка CSI-u выключена везде (WT-KBD-5).
Отличается ровно следующее.

**Только Windows:**

- `Ctrl+C` — «умное» копирование (раздел 9): на Windows нет `Cmd`.
- Шелл по умолчанию — PowerShell 7 (`pwsh`), установленный из Microsoft Store
  или MSI/winget, иначе `powershell.exe` (WT-UI-1).
- **Профиль PowerShell 7.** У pwsh 7 свой профиль
  (`Documents\PowerShell\Microsoft.PowerShell_profile.ps1`), и настройки
  PSReadLine (Tab — меню путей, история) и UTF-8 из профиля Windows
  PowerShell в нём сами не действуют. Одна строка в профиле pwsh 7
  подключает профиль 5.1 — источник настроек остаётся один:

  ```powershell
  $winPsProfile = Join-Path (Split-Path (Split-Path $PROFILE)) 'WindowsPowerShell\Microsoft.PowerShell_profile.ps1'
  if (Test-Path $winPsProfile) { . $winPsProfile }
  ```

  Проверка в новой вкладке: `$PSVersionTable.PSVersion.Major` — 7,
  `(Get-PSReadLineKeyHandler -Chord Tab).Function` — `MenuComplete`,
  `[Console]::OutputEncoding.WebName` — `utf-8`.
- Шрифт — только `Ctrl` + `=` / `-` / `0`.
- Meta (`<A-…>` в nvim) — **левый** Alt; правый Alt на русской раскладке —
  AltGr: правый `Alt+8` вводит «₽». `Alt+Space` (системное меню окна) и
  `Alt+F4` (закрыть окно) забирает окно, до nvim они не доходят (WT-KBD-4).
- Клавиатурный протокол — win32-input-mode (родной для ConPTY), kitty
  **выключен**: через ConPTY он терял Shift+кириллицу и русскую запятую
  (FIXLOG §41, WT-KBD-1). Что из-за ConPTY получает nvim — раздел 12.

**Только macOS:**

- `Ctrl+C` не перехватывается вообще; копирование — `Cmd+C` (WT-CLIP-3,
  WT-CLIP-5).
- `Cmd+C` / `Cmd+V`, `Cmd+N` / `Cmd+T` (новое окно / вкладка), `Cmd+H` /
  `Cmd+M` / `Cmd+Q` (скрыть / свернуть / выйти), `Cmd+=` / `Cmd+-` / `Cmd+0`
  (шрифт), `Cmd+Shift+S` (запомнить размер) (WT-PANE-8).
- Шелл — `$SHELL` пользователя, конфиг его не задаёт (WT-UI-2).
- kitty keyboard protocol включён: nvim получает «хитрые» сочетания
  (`Ctrl+.`, `Ctrl+Enter`, `Shift+Enter`, `Ctrl+;`) отдельными клавишами
  (WT-KBD-2). `macos_forward_to_ime_modifier_mask = "SHIFT"` — инвариант:
  Shift+буква идёт через системный IME готовым текстом, поэтому заглавные
  кириллицей работают и в kitty-программах. Не убирать (WT-KBD-3).
- Конфиг подключает `./nvim_forge/scripts/install-macos.sh`, руками — ничего.
  Скрипт ставит симлинк `~/.config/wezterm/wezterm.lua` и нейтрализует то,
  что WezTerm молча предпочёл бы ему: `~/.wezterm.lua` уходит в бэкап,
  `WEZTERM_CONFIG_FILE` снимается в launchd, а в профиль шелла, где она
  задана, в конец дописывается помеченный `unset` (свои строки не
  трогаются). Присваивание, появившееся после прежнего блока, получает ещё
  один блок в конце. LaunchAgent, который при входе выставляет
  `WEZTERM_CONFIG_FILE` с путём не в репо (`launchctl setenv …` в команде
  plist), скрипт называет по имени и не трогает — убрать руками; plist,
  который переменную только снимает или задаёт своему процессу, не
  считается. В конце скрипт пишет, какой файл WezTerm реально загрузит, и
  проверяет, что `wezterm.lua` грузится без ошибок; не так — код 1 и
  объяснение. Что-то сломалось — просто запусти скрипт ещё раз (WT-LOAD-4…
  WT-LOAD-12).

## 12. Что отдано nvim и что nvim получает (WT-KEYS-4, WT-KEYS-6, WT-KEYS-7, WT-KEYS-10, WT-KBD-6, WT-KBD-7, WT-KBD-9)

**Не перехвачено — уходит в nvim** (WT-KEYS-4): `Ctrl+PageUp` /
`Ctrl+PageDown`, `Alt+Enter`, `Tab` / `Shift+Tab`, `Ctrl+Shift+B`, `F1`–`F12`,
`Alt`+клавиша, `Ctrl`+буква (кроме `Ctrl+V` и `Ctrl+C` на Windows). Сочетания
nvim_forge `Ctrl+Shift+F`/`P`/`E`/`D`, `Ctrl+Shift+F5`, `Ctrl+.`,
`Ctrl+Enter`, `Ctrl+/`, `Ctrl+Space` на macOS и Linux уходят в nvim как есть, а
на Windows их перехватывает и доставляет подмена (ниже). `Ctrl+Shift+J`/`K` —
навигация WezTerm (раздел 3), панели nvim_forge — на `Ctrl+B` / `Ctrl+J`.

**Особые случаи:**

- `Ctrl+[` перехватывается и уходит в nvim как `F13`: физически это тот же
  байт, что `Esc`, и nvim их не различил бы. На `F13` в nvim_forge — сдвиг
  строки влево; сам `Esc` не страдает (WT-KEYS-6).
- `Ctrl+V` nvim не получает на всех платформах: вставку делает WezTerm, а
  блочное выделение и ввод символа буквально в nvim — на `Ctrl+Q`
  (WT-KEYS-7).
- `Ctrl+C` на Windows — единственное общее сочетание: при выделении WezTerm
  копирует, без выделения `<C-c>` уходит в nvim (WT-KEYS-7, WT-KBD-7).

**Windows: что nvim получает через ConPTY** (WT-KBD-6). kitty там нет, и
ConPTY кодирует клавиши сам:

| Сочетание | nvim без объявления получает | nvim_forge (подмена, WT-KEYS-10) |
|---|---|---|
| `Ctrl+Shift+F` / `P` / `E` / `D` | `<C-f>` / `<C-p>` / `<C-e>` / `<C-d>` | свои действия (поиск, палитра, проводник, отладка) |
| `Ctrl+Shift+F5` | `<F41>` | перезапуск DAP |
| `Ctrl+Enter` | `<NL>` (= `<C-j>`) | `<C-CR>` |
| `Ctrl+.` | `<C-n>` | code action |
| `Ctrl+/` | `<C-n>` | переключить комментарий |
| `Ctrl+Space` | ничего | автодополнение |
| `Shift+Enter` | `<CR>` | `<CR>` (привязки `<S-CR>` нет) |
| `Ctrl+;` (русская раскладка) | `<C-v>` | `<C-v>` — блочное выделение |
| `Shift+F5`, `Ctrl+F5` | `<F17>`, `<F29>` | так же: привязки `<S-F5>`/`<C-F5>` не срабатывают |

**Подмена (WT-KEYS-10, WT-KBD-9).** WezTerm на Windows перехватывает девять
сочетаний из таблицы и в панели, где nvim_forge объявил себя (user var
`FORGE_NVIM`), шлёт вместо них `<C-F13>`…`<C-F20>` / `<C-S-F13>`: они
проходят ConPTY, а nvim_forge переназначает их на исходные сочетания. Любая
другая программа (pwsh, Claude Code, `nvim --clean`) получает исходное
нажатие, как раньше; отличие одно — правый Ctrl приходит как левый.
Подмена работает и в режиме WINDOWS.

Смена объявления пишется в журнал (debug overlay: `d` в режиме WINDOWS,
строка `forge: FORGE_NVIM pane=… value=…`). Если nvim_forge упал, не сняв
объявление, шелл этой панели на подменные клавиши ничего не печатает, а
снять объявление можно одной командой в pwsh:

```powershell
[Console]::Write("`e]1337;SetUserVar=FORGE_NVIM=`a")
```

(или запустить nvim_forge и выйти из него как обычно). Выключить подмену —
`vim.g.forge_wezterm_chords = false` в nvim_forge: объявления нет, WezTerm
ничего не подменяет.

## 13. Альтернативный экран и OSC 52 (WT-SCROLL-14, WT-CLIP-11)

nvim, less, htop, Claude Code переключают терминал на **альтернативный
экран**: забирают всю площадь и перерисовывают её сами. Истории у этого
экрана нет по определению, и это свойство экрана, а не WezTerm — в tmux или
Windows Terminal то же самое. История основного экрана сохраняется и
вернётся, когда программа выйдет.

Copy mode, поиск, QuickSelect и выгрузка в nvim работают и там, но **только
с видимым экраном** программы; листать нечего. Колесо уходит программе,
`Shift+PageUp`/`PageDown` и `Ctrl+Shift+Delete` ничего не делают.

Проверить, на альтернативном ли экране программа:

```bash
wezterm cli get-text --pane-id "$WEZTERM_PANE" --start-line -5000 | wc -l
```

Примерно высота окна — да; для обычного шелла — весь скроллбэк.

**За историю отвечает сама программа:** у `less` — `/` и `Ctrl+B`, nvim сам
себе редактор, у Claude Code клавиши покажет `/help`. Транскрипты Claude
Code лежат в `~/.claude/projects/<проект>/<session-id>.jsonl`; открыть
читаемым текстом:

```bash
jq -r 'select(.type=="user" or .type=="assistant")
       | (.message.content | if type=="string" then .
          else (.[]? | select(.type=="text") | .text) end)' \
  ~/.claude/projects/<проект>/*.jsonl | nvim -
```

**Копирование без мыши и без графики — OSC 52**: программа сама просит
терминал положить текст в буфер обмена той машины, где ты сидишь; WezTerm
это поддерживает, Neovim 0.10+ умеет сам (WT-CLIP-11). Проверка:

```bash
printf '\033]52;c;%s\a' "$(printf 'test-osc52' | base64)"
# после этого системный буфер должен содержать test-osc52
```
