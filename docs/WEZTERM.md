# WezTerm — шпаргалка по хоткеям

Конфиг: `wezterm.lua` в корне репо. Подключается либо переменной
`WEZTERM_CONFIG_FILE`, либо симлинком в `~/.config/wezterm/wezterm.lua`
(Unix) / `%USERPROFILE%\.wezterm.lua` (Windows) — подробности в шапке
самого файла.

WezTerm здесь работает не только терминалом, но и **мультиплексором**
вместо tmux: панели, вкладки, воркспейсы. Причина — tmux и zellij нативно
живут только под Unix, на Windows их пришлось бы тащить в WSL, и хоткеи
разъехались бы между машинами. У WezTerm мультиплексор встроенный, а этот
файл — единственный источник хоткеев на обеих ОС.

---

## 1. Три принципа, на которых всё держится

**LEADER — это `Ctrl+Shift+Space`.** Аналог `Ctrl+B` в tmux: нажал,
отпустил, нажал команду. Даётся 2 секунды. Пока префикс взведён, в панели
вкладок горит жёлтое `LEADER`. Смысл в том, что у Neovim отбирается одна
комбинация, а не десяток.

**Все клавиши привязаны по ФИЗИЧЕСКОЙ ПОЗИЦИИ (`phys:`), а не по символу.**
Раскладка не имеет значения нигде: русская, английская — всё работает
одинаково. Это касается и режимов copy mode / search mode: их встроенные
таблицы конфиг переписывает на позиции автоматически при старте.

**Встроенные хоткеи WezTerm отключены целиком**
(`disable_default_key_bindings`). Они заданы по символу, то есть работали
бы только на английской раскладке, и вдобавок воровали клавиши у Neovim.
Всё нужное возвращено вручную через `phys:` — см. раздел 9.

Буквы команд выбраны по логике vim, а не tmux: `v` = `:vsplit`,
`s` = `:split`.

## 2. Панели (сплиты)

| Клавиши | Действие |
|---|---|
| `Ctrl+Shift+Enter` | новая панель справа — основной способ «дай вторую консоль» |
| `Ctrl+Shift+Alt+Enter` | новая панель снизу |
| `LEADER v` | панель справа (`:vsplit`) |
| `LEADER s` | панель снизу (`:split`) |
| `Ctrl+Shift+←↓↑→` | перейти в панель в этом направлении |
| `LEADER h` `j` `k` `l` | то же, по-вимовски |
| `LEADER ←↓↑→` | то же, стрелками |
| `Ctrl+Shift+Z` / `LEADER z` | развернуть панель на всё окно и обратно (zoom) |
| `Ctrl+Shift+W` / `LEADER x` | закрыть панель (спросит подтверждение) |
| `LEADER o` | перейти в следующую панель по кругу |
| `LEADER q` | показать буквы на панелях и прыгнуть в любую |
| `LEADER r` | **режим ресайза** — дальше стрелки или `hjkl` сколько нужно, `Esc` или `Enter` на выход |
| `LEADER a` | собрать раскладку: текущая панель слева, справа две консоли столбиком |

Границы панелей ещё и таскаются мышью. Неактивные панели слегка притушены,
чтобы фокус читался с одного взгляда.

## 3. Вкладки

| Клавиши | Действие |
|---|---|
| `Ctrl+Shift+T` / `LEADER c` | новая вкладка |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | следующая / предыдущая |
| `Ctrl+Shift+PageDown` / `PageUp` | то же |
| `LEADER n` / `LEADER p` | то же |
| `Ctrl+Shift+1`…`9` / `LEADER 1`…`9` | сразу на вкладку N |
| `LEADER ,` | переименовать вкладку |
| `LEADER w` | лаунчер: fuzzy-поиск по вкладкам и воркспейсам |

Голый `Tab` и `Shift+Tab` НЕ перехватываются — они уходят в Neovim, где
крутят буферы.

---

## 4. Воркспейсы (аналог сессий tmux)

Набор вкладок и панелей под задачу. У каждого своя раскладка, переключение
мгновенное, состояние сохраняется.

| Клавиши | Действие |
|---|---|
| `LEADER Shift+S` | создать воркспейс или перейти в существующий по имени |
| `LEADER w` | список воркспейсов и вкладок с fuzzy-поиском |

Имя текущего воркспейса всегда видно справа в панели вкладок.

## 5. Vim-навигация по выводу консоли (copy mode)

Это ответ на вопрос «как ходить по выводу и копировать без мыши».

**Вход:** `Ctrl+Shift+X` или `LEADER [`
**Выход:** `Esc`, `q`, `Ctrl+C` или `Ctrl+G`

> Работает по выводу шелла. **Внутри nvim, htop, less и Claude Code историю
> не покажет** — они забирают альтернативный экран, и скроллбэка у терминала
> просто нет. Почему так и что делать — раздел 11.

### Движение

| Клавиши | Куда |
|---|---|
| `h` `j` `k` `l`, стрелки | символ / строка |
| `w` / `b` / `e` | вперёд по слову / назад по слову / в конец слова |
| `Tab` / `Shift+Tab`, `Alt+←` `Alt+→` | то же, по словам |
| `0` / `Home` | в начало строки |
| `^` | в первый непробельный символ |
| `$` / `End` | в конец содержимого строки |
| `Enter` | в начало следующей строки |
| `Ctrl+U` / `Ctrl+D` | полэкрана вверх / вниз |
| `Ctrl+B` / `Ctrl+F`, `PageUp` / `PageDown` | страница вверх / вниз |
| `H` / `M` / `L` | верх / середина / низ видимого экрана |
| `g` | в самое начало скроллбэка |
| `G` | в самый конец |

Обрати внимание: в начало буфера — **одиночная** `g`, а не `gg` как в vim.

### Прыжки по символу

| Клавиши | Действие |
|---|---|
| `f<символ>` / `F<символ>` | к следующему / предыдущему вхождению символа |
| `t<символ>` / `T<символ>` | то же, но встать перед ним |
| `;` / `,` | повторить прыжок вперёд / назад |

### Поиск

| Клавиши | Действие |
|---|---|
| `/` | ввести шаблон, `Enter` — вернуться в copy mode на совпадении |
| `n` / `N` | следующее / предыдущее совпадение |
| `Ctrl+R` | переключить тип поиска (regex / текст) — внутри строки ввода |
| `Ctrl+U` | очистить шаблон — внутри строки ввода |

`/`, `n` и `N` добавлены этим конфигом: в штатной поставке WezTerm поиск
из copy mode не вызывается вообще.

### Выделение и копирование

| Клавиши | Действие |
|---|---|
| `v` (или `Space`) | выделение по символам |
| `V` | выделение по строкам |
| `Ctrl+V` | блочное выделение |
| `o` / `O` | перейти на другой конец выделения (по вертикали / горизонтали) |
| `y` | **скопировать в системный буфер и выйти** из copy mode |

## 6. Весь вывод — сразу в Neovim

`LEADER b` — скроллбэк текущей панели уходит в файл и открывается настоящим
nvim новой вкладкой, курсор на последней строке. Дальше это обычный Neovim
со всей его мощью: поиск, визуальные выделения, `:w` куска в файл.
Возврат к консоли — просто `:q`, вкладка закроется.

Запускается голый `nvim`, а не `nvim_forge` — для чтения вывода важен
мгновенный старт. Как переключить на форж, написано в комментарии рядом с
биндингом в `wezterm.lua`.

Файл всегда один и тот же: `~/.wezterm_scrollback.txt`, перезаписывается
при каждом вызове. В нём остаётся последний вывод консоли — если там
мелькали токены или пароли, удали руками.

> Та же оговорка, что и у copy mode: из приложения на альтернативном экране
> дампить нечего — см. раздел 11.

## 7. Без мыши: выделить и скопировать

| Клавиши | Действие |
|---|---|
| `Ctrl+Shift+U` / `LEADER Space` | QuickSelect: подсветить на экране пути, URL и хеши буквами, нажать букву — скопировано |
| `LEADER f` | поиск по скроллбэку (не заходя в copy mode) |
| `Shift+PageUp` / `Shift+PageDown` | прокрутка на страницу |

Выделение мышью, если всё же понадобится, кладётся в буфер обмена сразу —
дополнительно нажимать копирование не нужно.

| Клавиши | Действие |

| `Ctrl+Shift+N` | новое окно |
| `LEADER m` | полноэкранный режим |

## 9. Различия между Windows и macOS

Набор хоткеев одинаковый на обеих ОС. Отличается ровно следующее.

**Только Windows:**

- `Ctrl+C` — «умное» копирование: есть выделение → копирует и снимает его,
  нет выделения → уходит в программу как обычный `SIGINT`. Так сделано
  потому, что на Windows нет `Cmd` и одна клавиша вынуждена делать два дела.
- Шелл по умолчанию — `pwsh`, если он есть в `PATH`, иначе `powershell.exe`.

**Только macOS:**

- `Ctrl+C` **не перехватывается вообще** — всегда чистое прерывание.
  Копирование здесь системное, на `Cmd+C`.
- `Cmd+C` / `Cmd+V` — копировать / вставить.
- `Cmd+N` / `Cmd+T` — новое окно / новая вкладка.
- `Cmd+H` / `Cmd+M` / `Cmd+Q` — скрыть / свернуть / выйти.
- `Cmd+=` `Cmd+-` `Cmd+0` — размер шрифта.
- `macos_forward_to_ime_modifier_mask = "SHIFT"` — чтобы Ctrl-комбинации не
  уходили в системный IME и долетали до WezTerm при любой раскладке.

## 10. Что намеренно НЕ перехвачено (отдано Neovim)

Если какая-то из этих комбинаций вдруг перестанет доходить до nvim — искать
причину надо здесь.

| Клавиши | Кому и зачем |
|---|---|
| `Ctrl+Shift+F` | панель поиска nvim (`<C-S-f>`) |
| `Ctrl+Shift+P` | палитра Telescope (`<C-S-p>`) |
| `Ctrl+Shift+E` | эксплорер (`<C-S-e>`) |
| `Ctrl+Shift+D` | панель отладки (`<C-S-d>`) |
| `Ctrl+Shift+B`, `Ctrl+Shift+J` | панели nvim |
| `Ctrl+Shift+F5` | рестарт DAP |
| `Ctrl+PageUp` / `Ctrl+PageDown` | переключение буферов |
| `Alt+Enter` | `<A-CR>` |
| `Tab` / `Shift+Tab` | переключение буферов |
| `Ctrl+.`, `Ctrl+;`, `Shift+Enter` и прочие «хитрые» комбо | долетают в nvim благодаря kitty keyboard protocol — ради него терминал и выбран |

Отдельный случай — `Ctrl+[` перехватывается и превращается в `F13`.
Физически `Ctrl+[` — это тот же байт, что и `Esc`, и Neovim их различить не
может. Конфиг ловит комбинацию до этого и шлёт `F13`, на который в
`nvim_forge/lua/config/keymaps.lua` повешен сдвиг строки влево. Сам `Esc`
на своей клавише при этом не страдает.

## 11. Альтернативный экран: где терминал бессилен

Разделы 5 и 6 работают по выводу шелла. Внутри **nvim, htop, less, Claude
Code** они историю не покажут, и это не недоработка конфига.

Такие программы переключают терминал в **альтернативный экран**: забирают
себе всю площадь и перерисовывают её сами. У этого буфера **нет истории по
определению** — терминалу нечего запоминать, потому что прокрутки как
таковой не происходит, просто перерисовка. Скроллбэк родного буфера при
этом сохраняется нетронутым и вернётся, когда программа закроется.

Важно: это свойство самого альтернативного экрана, а не WezTerm. В tmux,
kitty или Windows Terminal будет ровно то же самое.

### Как проверить, что приложение на альтернативном экране

```bash
wezterm cli get-text --pane-id "$WEZTERM_PANE" --start-line -5000 | wc -l
```

Если в ответе примерно высота окна, а не тысячи строк — да, альтернативный
экран, истории нет. Для обычного шелла та же команда вернёт весь скроллбэк.

### Что тогда делать

**Копировать с видимого экрана — copy mode всё равно годится.**
`Ctrl+Shift+X`, дальше `hjkl`, `v`, `y`. Не работает только листание
истории; выделение и копирование того, что на экране — работают.

**За историю отвечает само приложение.** Это плата за альтернативный экран:
забрал экран — обеспечь навигацию. У `less` это `/` и `Ctrl+B`, у nvim —
он сам себе редактор, у Claude Code список клавиш покажет `/help`.

**Универсальный запасной путь — файл на диске.** Он не зависит ни от
терминала, ни от того, есть ли вообще графика: открывается чем угодно, хоть
`less` по SSH, хоть nvim.

### Транскрипты Claude Code

Claude Code пишет каждую сессию в JSONL:

```
~/.claude/projects/<путь-проекта-через-дефисы>/<session-id>.jsonl
```

Открыть всю переписку читаемым текстом в nvim:

```bash
jq -r 'select(.type=="user" or .type=="assistant")
       | (.message.content | if type=="string" then .
          else (.[]? | select(.type=="text") | .text) end)' \
  ~/.claude/projects/-Users-romryzhkov-claude/*.jsonl | nvim -
```

Дальше это обычный буфер: `/`, `n`, `G`, визуальные выделения, `:w` куска.

### Копирование без мыши и без графики

Когда графики нет вовсе (голый tty, SSH), системный буфер достаётся через
**OSC 52** — escape-последовательность, которой программа просит терминал
положить текст в буфер обмена **той машины, где ты сидишь**. WezTerm её
поддерживает, Neovim 0.10+ умеет ею пользоваться сам.

Проверить, что цепочка работает:

```bash
printf '\033]52;c;%s\a' "$(printf 'test-osc52' | base64)"
# после этого системный буфер должен содержать test-osc52
```

Это и есть ответ на вопрос «как копировать из TUI, если мыши нет»: не
терминал вытаскивает текст из приложения, а приложение отдаёт его терминалу.
