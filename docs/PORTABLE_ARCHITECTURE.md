# Универсальная сборка: границы модулей

Решение владельца, 2026-10-31: активные среды — Windows, macOS и Ubuntu;
Linux Mint временно отложен. Ниже целевая архитектура; перенос кода по этим
границам ещё предстоит выполнить отдельными изменениями.

Уточнение 2026-11-10: до рефакторинга обязателен [обзор фич/стоимости](FEATURE_REVIEW.md)
(IDE-080). Предлагаемые ниже модули не являются разрешением механически
разносить код или вводить новый framework. Сначала доказать сокращение
ответственности/дублирования и сохранить пользовательские сценарии.

## Общее ядро и платформенные детали

| Область | Что общее | Что зависит от среды |
|---|---|---|
| Панели и фокус | Состояние, открытие/скрытие, навигация, единые действия | Доставка клавиши терминалом на границе ввода |
| Языки | LSP/DAP/test-конфигурации, поиск проекта, приоритет launch.json | Путь к инструменту и layout venv |
| Процессы | Запуск argv, cwd, env, timeout, результат и stderr | Параметры запуска, PTY и особенности исполняемых файлов |
| Инструменты | Единый порядок поиска, явная установка/обновление | Имена бинарников и проверенные места установки |
| Shell | Запустить выбранный пользователем shell | Native Windows shell; пользовательский POSIX shell |
| Clipboard | Одно действие copy/paste и ожидаемый результат | Native provider, X11/Wayland/OSC52/SSH, возможности терминала |
| Файлы | Пути через vim.fs/stdpath, операции и проектный root | Суффикс executable, разделитель PATH, системные каталоги |
| Установка | Каталог инструментов и политика версий | winget/PowerShell, Homebrew, apt для Ubuntu/Mint |
| WezTerm | Семантика действий, большая часть клавиш и внешнего вида | GUI-модификаторы, shell, клавиатурный протокол |
| E2E | Одни сценарии, фикстуры, assertions и протокол отчёта | Backend PTY/GUI и доступные capabilities |

Ubuntu/Mint не требуют отдельных копий Lua-конфига. Различия дистрибутива
относятся к установке пакетов и проверке версий. X11/Wayland и SSH — свойства
сессии, а не просто название ОС. Arch, Fedora, WSL можно поддерживать
дополнительно; WSL не заменяет нативный Windows-прогон.

## Предлагаемые границы Lua

Уточнение review 2026-11-12: имена platform/tools ниже — варианты, не
обязательные новые модули. [Текущий разбор](WORKSPACE_TOOL_REVIEW.md#актуальный-проход-инструментов--2026-11-12)
подтвердил разные override/fallback политики; сохраняем существующие языковые
границы. Ближайший кандидат — native managed debugpy venv (IDE-119), а не
общий framework resolver или механическое объединение project roots.

- `forge/platform.lua`: небольшое описание среды, conventions путей,
  venv bin/Scripts, separator, shell. Определяется один раз; не устанавливает
  пакеты и не запускает внешние команды ради определения ОС.
- `forge/tools.lua`: общий resolver `override → project env → PATH → managed
  fallback` там, где этот порядок применим. Возвращает путь и источник;
  не скачивает инструмент при открытии UI. Политика поиска явно задаётся
  для инструмента, а не выбирает «самый новый» произвольный бинарник молча.
- Общая обёртка процессов появляется там, где повторяются timeout, stderr,
  cwd и argv. Используем API Neovim для процессов; shell-строки оставляем
  операциям, которым действительно нужна интерпретация shell.
- `plugins/*` и языковые конфигурации используют эти возможности, а не
  повторяют поиск системных путей. Если платформенный код вырастет,
  выделяем адаптеры windows/posix/macos; пустые модули на каждую ОС не нужны.
- WezTerm сохраняет свой runtime: его конфиг не должен зависеть от `vim`.
  Общий контракт хоткеев связывает два приложения через проверяемые данные.

Пользовательский override и возможности среды важнее догадки по ОС. Отсутствие
clipboard/GUI/нужного SDK должно быть видно в health и отчёте тестов. Команды
Neovim и базовые leader-привязки доступны также в обычном терминале без WezTerm.

| Место | Наблюдение по текущему коду | Целевое изменение |

| Диагностика IDE-001 | zsh и macOS как место воспроизведения | Сборщик общий; поиск GOENV включает Mac и Linux, запуск проверяем на всех ОС |

Это список для проектирования и e2e-воспроизведения; runtime этих компонентов
в текущем изменении не переписан. При переносе сохраняем поведение и уменьшаем
дублирование по одному компоненту, с регрессом для каждой найденной проблемы.

## Проверка архитектуры

Bash (§116–117): общий forge.bash использует Node resolver и общие Tasks;
forge.bats — публичный Neotest adapter, а forge.bash_host изолирует native
interpreter, Windows WSL rejection, cygpath и MSYS env только дочернего Bats.
Новых plugin pins и копий конфигурации по ОС нет. Windows workflow проверен
реальными UI; Ubuntu/Mac/Bash 3.2/DAP требуют отдельных запусков.

IDE-027 (§92 FIXLOG): подтверждена ошибка ConPTY в самом Windows Neovim,
воспроизводимая без Forge/плагинов. Временный SDK вынесен за границу Lua:
`scripts/prepare-windows-sdk.ps1`, source/patch lock, отдельный runtime в
`.tools`, общий resolver для Windows launcher/test entrypoint. Явная
подготовка, проверка hash и ошибка при missing/stale SDK; в общем управлении
панелями/окнами нет Windows-only обхода. Официальные Linux/macOS SDK,
хоткеи и сценарии едины. Правило удаления временного SDK — подтверждённый
upstream fix и прохождение того же core/buffer регресса. Команды и ограничения:
[tests/diagnostics/README.md](../tests/diagnostics/README.md).

Общий e2e-набор запускается нативно в Windows, headless в Ubuntu Docker
на Windows, отдельно на Mac. Mint временно не входит в обязательную матрицу. Тест фичи
описывает одинаковое действие и результат; адаптер ввода/PTY меняется по
среде. Для clipboard и клавиатуры добавляются ru/en и нужный GUI-backend.
Контракт прогонов и текущий пробел покрытия — [tests/e2e/README.md](../tests/e2e/README.md).
