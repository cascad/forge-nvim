# Ручные проверки WezTerm — Windows

Чек-лист владельца (change `review-baseline`, design, решения 3 и 4): то,
что на Windows не проверяется без GUI. Платформо-независимое (таблицы
клавиш, экран выбора панели, запросы, оверлеи) проверяется здесь, на Mac —
только платформенные пути (`tests/manual/wezterm-macos.md`).

**Порядок.** Сверху вниз, за одной машиной; W1–W2 — на английской и русской
раскладке, остальное — на английской, если в пункте не сказано иное. Перед
прогоном: `git pull`, Ctrl+Shift+R в WezTerm, `nvim -l tests/run.lua` зелёный.

**Результат** дописывается строкой в конец пункта, прежние строки не
правятся, последняя — текущий статус:

    Проверено: <дата>, <ОС и версия>, WezTerm <версия>, раскладка <…> — совпало | расходится: <что видно>

**Ожидаемое** — текст требования в `openspec/specs/` на момент прогона. Где
требование поменял уже применённый, но ещё не заархивированный change, код
работает по его delta, и сверка идёт с delta (change назван в пункте).
«Расходится» — правится спека (правило фазы 1, `review-baseline`, решение 5).

## wezterm-keyboard-protocol

### W1 — что nvim получает через ConPTY
Требования: WT-KBD-6. Источник: divergence 31.
Шаги: в WezTerm открыть `nvim --clean`, выполнить
`:lua print(vim.fn.keytrans(vim.fn.getcharstr()))` и нажать сочетание; по
одному сочетанию на вызов. Сочетания: Ctrl+;, Ctrl+/, Ctrl+., Ctrl+Enter,
Shift+Enter, Ctrl+Shift+F, Ctrl+Shift+P, Ctrl+Shift+E, Ctrl+Shift+D,
Ctrl+Shift+F5, Ctrl+Space. Обе раскладки.
Ожидаемое: таблица WT-KBD-6 (сценарии «Ctrl+Shift+буква неотличима от
Ctrl+буквы», «Enter и точка с модификаторами», «Ctrl+Space не доходит»,
«Ctrl+знак препинания на русской раскладке»). `nvim --clean` не объявляет
себя для подмены сочетаний (change `add-nvim-chords-on-windows`), поэтому
девять сочетаний подмены приходят исходным нажатием. Таблицу сняли пробой через conpty.dll
(`tests/wezterm/conpty/chords.fixture.json`, обе раскладки), не в GUI.
Воспроизведение для: `resolve-key-ownership-conflicts`, `add-nvim-chords-on-windows`.

## wezterm-key-ownership

### W2 — Alt+Space и Alt+F4
Требования: WT-KEYS-9. Источник: divergence 34.
Шаги: в окне WezTerm (в панели nvim) нажать левый Alt+Space, закрыть меню
Esc; затем Alt+F4 во втором, ненужном окне WezTerm.
Ожидаемое: сценарии «Alt+Space в nvim» — открывается системное меню окна,
nvim ничего не получает; «Alt+F4» — окно закрывается, как кнопкой закрытия.
Воспроизведение для: `resolve-key-ownership-conflicts` (задача 3.3).

## wezterm-clipboard

### W3 — OSC 52 через ConPTY
Требования: WT-CLIP-11. Источник: вопрос «OSC 52 через ConPTY».
Шаги: в pwsh `[Console]::Write("$([char]27)]52;c;dGVzdA==$([char]7)")`, затем
`Get-Clipboard`. Потом `Set-Clipboard A`,
`[Console]::Write("$([char]27)]52;c;$([char]7)")`, `Get-Clipboard`.
Ожидаемое: сценарии «Программа кладёт текст в буфер» — `test`; «Программа
очищает буфер» — пусто.

### W4 — bracketed paste через ConPTY
Требования: WT-CLIP-6. Источник: вопрос «DECSET 2004 через ConPTY».
Шаги: скопировать три строки с отступами; в `nvim --clean` `:set autoindent`,
режим вставки, Ctrl+V. Затем то же в pwsh (PSReadLine).
Ожидаемое: сценарии «Многострочная вставка в программу с bracketed paste»
(отступы как в источнике, без «лесенки») и «Многострочная вставка без
bracketed paste».

### W5 — выделение держится
Требования: WT-CLIP-9. Источник: вопрос «перерисовка ConPTY».
Шаги: в pwsh вывести `1..20`, выделить мышью строку, ничего не нажимать 10 с;
затем выполнить `1..60` (вывод ниже выделения).
Ожидаемое: сценарий «Вывод ниже выделения» — выделение остаётся; сам ConPTY
его не гасит.

## wezterm-scrollback

### W6 — Claude Code на альтернативном экране
Требования: WT-SCROLL-14. Источник: вопрос «Claude Code».
Шаги: в панели с Claude Code из другой панели выполнить
`wezterm cli get-text --pane-id <id> --start-line -5000 | wc -l` и сравнить с
высотой панели (`wezterm cli list`).
Ожидаемое: сценарий «Проверка, что программа на альтернативном экране»:
число строк равно высоте панели — альтернативный экран. Если так, Claude
Code добавляется в перечень WT-SCROLL-14 (уточнение базовой линии, задача 3.2).
Проверено: 2026-09-27, Windows 11 Pro 10.0.22631, WezTerm 20240203-110809-5046fc22, раскладка — не влияет — расходится: Claude Code на альтернативном экране (67 строк при высоте панели 67), а в перечне WT-SCROLL-14 его нет; прогнал агент из этой же панели

### W7 — PageUp и PageDown в search mode
Требования: WT-SCROLL-15. Источник: вопрос «PageUp/PageDown».
Шаги: вывести 200 строк с `foo` через одну, Ctrl+Shift+Space → `f`, набрать
`foo`; нажать PageDown, затем PageUp, затем PageUp до конца истории.
Ожидаемое: сценарии «PageDown ведёт вверх», «PageUp возвращает к самому
нижнему», «PageUp в конце истории».

### W8 — подсветка после copy mode и QuickSelect, следующий Ctrl+C
Требования: WT-SCROLL-5, WT-SCROLL-12, WT-CLIP-2. Источник: вопрос «сброс выделения».
Шаги: Ctrl+Shift+X, выделить `v` и стрелками, выйти Esc; повторить с `q` и с
`y`; Ctrl+Shift+U, скопировать метку. После каждого выхода — `ping -t
localhost` и Ctrl+C.
Ожидаемое: сценарии WT-SCROLL-5 «Выход без копирования», WT-SCROLL-12
«Копировать и вставить», WT-CLIP-2 «Фрагмент, оставшийся после QuickSelect»
и «Нет выделения — прерывание». Записать, остаётся ли подсветка и что сделал
Ctrl+C: скопировал или прервал.
Воспроизведение для: `fix-copy-clobbers-clipboard` (задача 2.4).

## wezterm-windows-mode

### W9 — `q`: выбор панели по метке
Требования: WT-WIN-7. Источник: divergence 50, вопрос «q».
Шаги: две панели; Ctrl+Shift+Space → `q` → `s`. Затем снова `q` → Esc. Затем
развернуть панель зумом (`z`), `q` → метка; и ещё раз `q` → Esc.
Ожидаемое (delta `fix-windows-mode-modality`): «Метки перехватывает сам
режим» — `s` выбирает панель, сплита нет; «Esc на экране выбора — Windows» —
экран закрыт, режим уже выключен; «Панель развёрнута зумом» — после выбора
развёрнута выбранная панель, после Esc зум не возвращается.
Воспроизведение для: `fix-windows-mode-modality` (задача 2.8).

### W10 — `x`: запрос закрытия панели
Требования: WT-WIN-10, WT-WIN-21. Источник: divergence 51.
Шаги: две вкладки, в панели nvim; Ctrl+Shift+Space → `x` → `n`; снова `x` →
Esc; снова `x` → `y`. На русской раскладке — `x` → клавиша Y.
Ожидаемое (delta `fix-windows-mode-modality`): «Запрос при включённом
режиме» — режим выключен до запроса, `n`/Esc отменяют с первого нажатия,
вкладки не переключаются, `y` закрывает; «Запрос на русской раскладке» —
клавиша Y ничего не делает, подтверждение только кликом.
Воспроизведение для: `fix-windows-mode-modality` (задача 2.8).

### W11 — режим WINDOWS поверх оверлеев
Требования: WT-WIN-21, WT-UI-12. Источник: вопрос «WINDOWS поверх оверлеев».
Шаги: Ctrl+Shift+X → Ctrl+Shift+Space → h, j, v, `s`, Esc, Esc. Затем
Ctrl+Shift+U → Ctrl+Shift+Space → `u`, `n`, Esc, Esc.
Ожидаемое (delta `fix-windows-mode-modality`): «Вход в режим из copy mode» —
h/j/v работают как в copy mode, `s` делит панель; «Режим поверх запроса или
QuickSelect» — метка без команды проглатывается, `n` переключает вкладку,
первый Esc выключает режим, второй закрывает экран. Бейдж — по WT-UI-12
(delta `fix-ui-robustness`), сценарий «Режим WINDOWS, включённый из copy mode».

### W12 — когда режим гаснет сам
Требования: WT-WIN-2. Источник: вопрос «режим гаснет».
Шаги: Ctrl+Shift+Space, затем по очереди (каждый раз снова входя в режим):
Ctrl+Shift+R; Ctrl+=; сохранить `wezterm.lua` без изменений; сменить
светлую/тёмную тему Windows.
Ожидаемое (delta `fix-windows-mode-modality`): «Перечитывание конфига и смена
шрифта» — режим выключается, бейдж гаснет, следующая клавиша уходит
программе. Про смену темы требование молчит — записать, что видно.

### W13 — `o` под зумом
Требования: WT-WIN-6. Источник: вопрос «o под зумом».
Шаги: три панели, `z` на одной, Ctrl+Shift+Space → `o` несколько раз.
Ожидаемое: сценарий «Панель развёрнута зумом» WT-WIN-6. Записать, снимается
ли зум и не ломается ли размер развёрнутой панели.
Воспроизведение для: `fix-windows-mode-modality` (задача 2.8).

## wezterm-panes-tabs

### W14 — воркспейс при повторном запуске
Требования: WT-PANE-10. Источник: вопрос «воркспейс при повторном запуске».
Шаги: Ctrl+Shift+Space → Shift+S → `work`; запустить WezTerm ещё раз из меню
«Пуск»; затем Ctrl+Shift+Space → `w` → default.
Ожидаемое: сценарий «Повторный запуск WezTerm из другого воркспейса» — новое
окно в default и на экране не появляется, видно после переключения.

### W15 — готовый лэйаут в маленькой панели
Требования: WT-PANE-9. Источник: вопрос «частичный сбой лэйаута».
Шаги: разделить окно так, чтобы панель стала узкой (несколько `v`), в ней
Ctrl+Shift+Space → `a`.
Ожидаемое: сценарий «Зум и нехватка места» — нет места на первое деление:
ничего не меняется; только на второе: справа одна новая панель, фокус в ней.

### W16 — мышь на панели вкладок
Требования: WT-PANE-13. Источник: вопрос «мышь».
Шаги: три вкладки, активна третья; колесо вниз над панелью вкладок; правый
клик по вкладке.
Ожидаемое: сценарии «Колесо над панелью вкладок» (вниз — следующая, по
кругу) и «Правый клик по вкладке» (Tab Navigator).

## wezterm-config-loading

### W17 — перечитывание конфига
Требования: WT-LOAD-14. Источник: вопрос WT-LOAD-14.
Шаги: (а) при включённом режиме WINDOWS изменить `README.md` в корне репо;
(б) временно переименовать `wezterm.lua`, нажать Ctrl+Shift+R, вернуть имя;
(в) сменить `WEZTERM_CONFIG_FILE` (User) на другой путь, нажать
Ctrl+Shift+R, вернуть переменную.
Ожидаемое: сценарии «Windows — наблюдается весь каталог файла» (бейдж
гаснет, в debug overlay запись о перечитывании), «ошибка при перечитывании»
(окно ошибки, WezTerm на прежнем конфиге), «перечитывается тот же путь».

## wezterm-window-state

### W18 — окна и уведомления
Требования: WT-STATE-1, WT-STATE-2, WT-STATE-3, WT-KEYS-3. Источник: вопрос «окна и уведомления».
Шаги: `wezterm start --position 10,10`; при работающем WezTerm запустить его
ещё раз из меню «Пуск»; сохранить размер больше экрана (растянуть на два
монитора или сменить масштаб) и открыть новое окно; Ctrl+Shift+S —
засечь, сколько держится уведомление; нажать Win+=, Win+-, Win+0.
Ожидаемое: WT-STATE-1 «Положение из командной строки» и «Сохранённый размер
больше экрана»; WT-STATE-2 — по delta `fix-window-state-new-windows`
(«Повторный запуск, пока WezTerm работает» — окно того же размера по центру;
«Окно из командной строки»); WT-STATE-3 «Сохранение» — текст уведомления;
WT-KEYS-3 — Win-сочетания до WezTerm не доходят (лупа Windows).
Воспроизведение для: `fix-window-state-new-windows` (задачи 2.2, 3.2), `fix-ui-robustness` (задача 4.2).
